# Pi的工作原理

Pi负责协调模型请求、工具执行、上下文组装和会话存储。会话是Pi对一次对话的记录，包括消息、工具调用及其结果、模型变更、压缩操作以及其他事件。

会话中的消息和事件构成一棵树。树中的每一条路径称为一个分支。当前条目所在的分支称为活动分支，为下一个模型请求提供历史记录。

## 代理循环

提交的消息会被添加到活动分支中。Pi根据系统提示词、活动分支、可用工具和模型设置构建模型请求，然后通过选定的提供者发送请求。

提供者会流式返回助手的响应，响应中可能包含文本和工具调用。Pi会记录该响应，并执行每个工具调用，记录结果。这完成了一轮交互。如果工具结果或排队的消息需要进一步的模型请求，Pi会开始下一轮。否则，运行结束。

转向消息会在当前助手轮次之后插入。后续消息会在代理完成待办工作后插入。中止操作会停止当前运行，并将排队的消息返回给编辑器。

## 上下文

活动分支提供对话历史。Pi会将会话条目转换为模型兼容的用户消息、助手消息和工具结果消息。

Pi会根据其基础指令和发现的上下文文件构建系统提示词。请求还会携带工具定义和技能描述。

完整的技能指令按需加载。扩展可以添加指令或转换上下文。

提示模板会在编辑器输入变成用户消息之前对其进行扩展。选定的文件、图片、粘贴的文本和shell输出都可以成为消息内容。

## 会话

持久化会话是JSONL文件。每个树条目都有一个ID，并引用其父条目。当前条目标识活动分支。

从较早的条目继续会创建同一文件中的另一个分支。分叉和克隆会将选定的历史记录复制到新的会话文件中。

模型上下文会根据活动分支重建。压缩操作会在后续模型请求中插入一个摘要条目，用以替代较旧的消息。原始条目仍保留在会话树中。

## 接口

交互模式会在终端中渲染会话和代理事件。打印模式会运行提示并写入最终响应。JSON模式会将代理事件以JSONL格式写入。

RPC模式会接受stdin中的JSONL命令，并将响应和事件写入stdout。TypeScript SDK会在进程中创建和控制代理会话。

所有接口都使用相同的代理和会话机制。

## 扩展和资源

扩展是加载到Pi进程中的TypeScript模块。它们的工厂函数会注册工具、命令、快捷方式、提供者、事件处理器、渲染器和终端UI。

技能提供按需加载的指令和支持文件。提示模板提供可复用的消息文本。主题提供终端颜色。Pi通过npm或git分发这些资源。

## 信任和权限

Pi在加载项目设置和资源之前会解析项目信任。信任决策和项目资源加载完成后，Pi会加载上下文文件。启用的工具会使用Pi进程的操作系统权限。扩展在该进程中执行。
