# 安全运行 Pi

将模型生成的命令和代码视为不可信。Pi 会以启动它的账户权限读取、更改和执行文件，且不会在每次调用工具前请求确认。扩展、包管理器、语言服务器等子进程也会以相同的权限运行，除非操作系统或虚拟化边界对其进行了限制。

文件、注释、说明、命令输出和模型响应都可能通过提示注入引导模型。项目信任控制项目启动时加载的资源，但并不能保证内容或其结果是安全的。

安全来源于限制 Pi 可以访问和影响的文件、凭证、进程和网络服务，以防生成的操作错误或恶意。监控会话记录、使用项目信任和审查更改并不能创建安全边界。

## 选择 Pi 的运行方式

不同的运行方式对生成命令的访问权限施加了不同的限制：

| Pi 的运行方式 | 保持受保护的内容 |
|---|---|
| 直接运行，使用其操作系统用户的权限 | 该用户无法访问的内容。使用专用用户账户可以缩小这些权限，但 Pi 仍与其他用户共享操作系统和网络。 |
| 完全在容器、虚拟机或沙箱内运行 | 你未暴露给环境的主机文件和进程。如果将凭证和网络服务放在其中，它们仍然可被访问。这通常是实际最强的隔离选项。 |
| 在隔离环境外运行，仅使用其内置工具 | 通过这些工具执行的操作无法影响主机资源。Pi 本身和其他扩展仍位于边界之外，因此这是一种较窄的隔离形式。 |

工作文件夹控制资源发现和工具的默认位置，但并不能阻止 Pi 进程可访问的其他路径。

无论选择哪种方式，只提供任务所需的文件和服务。尽可能将凭证保留在隔离环境之外，或使用范围狭窄、生命周期短的凭证。在命令不需要时限制网络访问。

有关设置说明和各隔离方式的限制，请见 [在隔离环境运行 Pi](containerization.md)。

## 理解项目信任

项目信任控制 Pi 是否加载工作文件夹提供的大多数设置和资源。它防止文件夹在你未批准前静默加载可执行扩展。

项目信任不是完整的启动边界。Pi 在选择或创建会话时会读取项目 `sessionDir` 设置，之后才解析项目信任。拒绝信任会阻止剩余的项目设置和受保护资源加载，但无法撤销初始会话目录查找。

项目信任不会限制工具调用的访问权限。Pi 启动后，启用的工具仍使用 Pi 进程的操作系统权限。文件夹中的说明和其他内容也可能影响模型。

### 项目信任保护的资源

当 Pi 在当前工作目录中发现以下任一资源时，需要进行项目信任决策：

- `.pi/settings.json`
- `.pi/mcp.json`
- `.pi/extensions`, `.pi/skills`, `.pi/prompts`, 或 `.pi/themes`
- `.pi/SYSTEM.md` 或 `.pi/APPEND_SYSTEM.md`
- 当前目录或祖先目录中的项目 `.agents/skills`

仅包含 `.pi` 的目录不需要项目信任。

授予项目信任允许 Pi 加载：

- 项目设置
- 项目 MCP 服务器（来自 `.pi/mcp.json`）
- 扩展、技能、提示模板、主题和系统提示文件（位于 `.pi`）
- 通过项目设置配置的缺失包
- 项目本地和项目包扩展

拒绝项目信任会跳过这些受保护资源，除了上述描述的初始 `sessionDir` 查找。

上下文文件如 `AGENTS.override.md`、`AGENTS.md` 和 `CLAUDE.md` 无论项目信任如何都会加载，除非你禁用上下文加载。即使你拒绝项目信任，也要将文件夹中的说明视为不可信输入。
### 如何Pi选择信任决策

命令行`--approve`或`--no-approve`覆盖优先生效。当受保护资源存在且无命令行覆盖时：

1. 用户级和命令行扩展可处理`project_trust`事件。第一个返回yes或no的扩展拥有决策权。
2. 若无扩展决策，Pi将在当前目录或其父目录中查找已保存的决策。最近的决策生效。
3. 若无已保存决策，Pi将遵循全局`defaultProjectTrust`设置，默认为`"ask"`。

已保存决策使用规范目录路径，存储于：

```text
~/.pi/agent/trust.json
```

使用`/trust`为未来Pi进程保存决策。

### 无需交互提示的信任项目

打印、JSON和RPC模式无法显示内置信任提示。若无命令行覆盖、扩展或已保存决策：

- `defaultProjectTrust: "always"`加载受保护项目资源。
- `defaultProjectTrust: "ask"`或`"never"`跳过它们。

使用`--approve`或`--no-approve`时，自动化运行需要一次性的明确决策。

## 降低影响并改善恢复

这些实践不替代隔离，但可减少暴露或使恢复更易：

- 仅授予Pi执行任务所需文件和服务的访问权限。
- 在重大变更前使用快照、备份或版本控制。
- 加载扩展和包前进行审查。扩展在Pi进程内执行。
- 优先使用范围狭窄、生命周期短的凭证。
- 应用结果至另一系统前，审查差异和生成输出。
- 导出或共享会话前进行审查。会话可能包含提示、工具参数、命令输出、文件内容及会话中暴露的凭证。

## 报告安全问题

遵循仓库[安全政策](https://github.com/earendil-works/pi/blob/main/SECURITY.md)。请勿为安全敏感报告公开创建问题。

预期本地代理行为、来自不可信内容的提示注入、缺乏内置沙箱以及用户安装的扩展或技能行为通常超出安全边界，除非报告能证明特权边界绕过或访问权限超出本地用户已有的权限。
