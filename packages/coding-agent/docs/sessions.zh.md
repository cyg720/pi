# 会话与上下文

Pi 会将对话保存为会话。当前会话的活动分支为下一个模型请求提供对话历史记录。使用会话命令可以继续工作、探索其他分支，或减少发送给模型的历史记录量。

## 继续或切换会话

Pi 会自动保存会话，除非您使用 `--no-session` 启动它。

```bash
pi --continue
pi --resume
```

`--continue` 会打开当前工作目录的最新会话。`--resume` 会打开会话选择器。在交互模式下，`/resume` 会打开相同的选项器，而 `/new` 会开始一个新会话。

使用 `/name` 或 `--name` 为会话分配一个可识别的名称。运行 `/session` 可以验证当前会话文件、ID、消息计数、令牌使用情况和成本。

会话选择器允许您搜索、重命名和删除会话。它还可以显示路径、更改排序，并将结果限制为命名会话。有关其快捷键，请参见 [快捷键](keybindings.md#sessions)。

## 选择分支方式

Pi 以树状结构存储条目，因此返回到更早的时间点不会擦除您离开的分支。

| 操作 | 结果 | 适用场景 |
|---|---|---|
| `/tree` | 在当前会话文件内移动 | 相关替代方案应保持在一起 |
| `/fork` | 从较早的用户消息创建新会话 | 替代方案应成为独立工作 |
| `/clone` | 将活动分支复制到新会话 | 您希望获得当前状态的独立副本 |

在 `/tree` 中，选择用户消息会将其文本放回编辑器。编辑并提交以创建另一个分支。选择助手回复或其他条目会继续该条目之后的操作，编辑器为空。

离开分支后，Pi 可以对分支进行总结，并将该总结附加到您进入的分支。这保留了废弃路径的相关工作，而不包括该路径中的每条消息。

有关持久化树和条目类型，请参见 [会话格式](session-format.md)。

## 管理对话上下文

模型接收的是活动分支，而不是会话文件中的所有分支。Pi 会将该历史记录与系统提示、发现的上下文文件、可用工具和加载的技能描述结合。[Pi 的工作原理](how-pi-works.md#context) 详细说明了这些输入是如何组装的。

页脚显示当前上下文使用情况。当活动上下文接近模型限制时，Pi 通常会自动对较旧的历史记录进行压缩。压缩会添加总结并保留最近的消息。它不会删除原始会话条目。

运行 `/compact` 可以手动压缩。您可以添加指令，指示总结时应保留特定主题或决策。通过 [设置](settings.md#compaction) 配置自动压缩和保留的历史记录。

如果提供方不可用或无法接受摘要请求，压缩可能会失败。解决提供方问题后，再次运行 `/compact`。禁用自动压缩不会禁用手动命令。

有关阈值、保留边界、分支总结行为和扩展钩子，请参见 [压缩参考](compaction.md)。

## 控制会话存储

默认情况下，Pi 会将会话存储在 `~/.pi/agent/sessions/` 下，按工作目录分组。使用 `--session-dir`、`PI_CODING_AGENT_SESSION_DIR` 或 `sessionDir` 设置选择其他位置。CLI 选项具有最高优先级。

使用 `--no-session` 进行短暂运行。短暂会话在 Pi 退出后无法恢复。

使用 `--session` 时，您已经知道会话路径或 ID。使用 `--fork` 可以在交互模式开始前从现有会话创建新会话。

## 导出会话或分享会话

使用 `/export` 将当前会话写入 HTML 或 JSONL 格式。使用 `/share` 上传并获取查看链接。Pi 配置了 Radius 认证时使用 Radius 附件；否则使用私有 GitHub gist。

请先审阅导出或分享的会话。它们可能包含提示、模型响应、工具参数、命令输出、文件内容和扩展消息。

## 报告错误

运行 `/bug [description]` 会为 Pi 开发人员准备一份私有报告。您可以包含会话转录、省略转录，或请当前模型总结问题。请审阅任何转录或生成的总结，因为它们可能包含敏感的对话数据。
该报告包含环境和提供程序配置（不含凭证值），以及记录的错误诊断信息。您可以通过 `radius.pi.dev` 上传该报告，或导出相同报告的 zip 文件以便自行查看和分享。上传操作无需登录，Radius 会根据您的账户信息对报告进行身份认证，以便开发人员后续跟进。如果上传失败，Pi 会提供导出 zip 文件的选项。
