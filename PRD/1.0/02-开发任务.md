项目与智能体定义分开。项目不保存唯一 agentId，智能体包不归属某个项目；会话/执行记录建立 projectId 与 agentId 的使用关系。同一 Harness 可以承载多个独立会话并发，不能把“一个 Harness”解释为“只运行一个智能体”。

- 取消：传播到目标执行的进程树，按会话/admissionId/检查 executionId 保存独立环境实例，不能共享实例后修改 cwd。NodeExecutionEnv 的 cleanup 清理该实例全部子进程，且不证明进程树已经退出；宿主须核实退出，未知则待核对并保留占用，不能清理其他智能体环境。重启不能仅凭旧 PID 杀进程，须核对进程身份。Shell 保持 unsafe，停止不回滚文件。
- 共享边界：命令执行、输出归档回调与进程跟踪放公共 R；A 只做编码工具适配。T32 通过宿主注入复用同一机制，E 不导入 A。
- 验收：成功、非零退出、超时、取消、程序缺失、大输出均有实际本地命令用例。Windows PowerShell 必测，Bash 配置存在时补测。A10。

### T12 提交去重、并发与资源冲突

- 前置：T10、T11。覆盖 H12、U04、U21。
- 文件：`R/src/submissions.ts`、`resource-records.ts`、`models.ts`、`model-routing.ts`；`S/src/project-runs.ts`、`resource-leases.ts`、`config.ts`；`C/src/settings.ts`；`S/test/submissions.test.ts`、`concurrency.test.ts`；`R/test/model-routing.test.ts`。

- T12.1 并发：不同会话可同时执行，同一会话仍用 Durable 队列。配置有限的全局执行上限，默认至少容纳两个会话；后台压缩未收尾不释放所属执行名额。先查重复请求再检查容量，满额明确提示重试，不新增跨会话自动队列。降低上限不取消已准入执行；重启保留这些名额，满额期间不接新执行。

- T12.3 落盘：服务级短锁中一次检查本次全部资源、全局名额及连接是否可用，再在所属项目自有文档保存 admissionId、请求指纹、连接版本、占用和待提交内容；全部满足才准入，失败不保留半套占用。释放短锁后再 submit/扫描文件/调用模型，不在锁或 Session 事务内等待这些操作。文件工具复查真实目标和占用范围；可信 Shell 越界副作用不承诺覆盖。
- T12.4 中断：记录“已准入待提交、已关联提交、收尾中、已释放”。持久化结果不明先阻止冲突准入并重新读取，不能直接当失败释放；重启按同一 requestId 补齐提交。已取消不再补交；尚未准入的满额/冲突请求可原 ID 重试，但仍校验指纹。停止后的新执行使用新 ID，重放旧请求只返回旧结果。
- T12.5 释放：只由匹配 admissionId 的收尾操作释放，旧回调不得释放后来占用；不按时间到期或心跳丢失自动释放。关联任务、后台压缩、进程、队列处置和必要归档全部结束才释放。连续编码队列可沿用同一 admissionId 和兼容占用，每段 run 仍独立记录；队列清空/失败保留时收尾后释放，继续前重新准入。

- 入口：普通提交、继续队列、下一段 run、工具 execute/环境和恢复都复查准入；不能只保护 HTTP 或 beforeRequest。一个会话的停止/新准入按同一顺序处理，T13 接停止，T14 接恢复。修改连接时也检查已准入待提交、取材及收尾，不能只查已运行的 Durable 任务。

- 验收：重复请求只提交一次；同项目无冲突任务真实重叠执行；相同或嵌套可写目录冲突被拒绝；停止一项不影响另一项。A12、A37。

- T13.5 撤回/清空：复用公开 abortSubmission，保存操作意图、目标集合与结果。先校验归属和条目版本；已编辑的旧版本不删，与消费竞争返回 already_placed/settled 的真实结果。平台条目操作串行；调用期间不持有 Session 事务。清空捕获当前未消费集合，逐条保存结果；响应丢失或中途退出按原 ID 查询并补完，不能误删后来新增消息。清空不停止当前任务。
- T13.6 失败与恢复：原生 keep 也保留 steer，平台在失败收尾取消未消费 steer、保留普通 followUp，已 placed 不删。操作意图与失败清理状态持久化；T14 重启先核对并补完，再开放继续/新提交。停止、待核对、离线或恢复期间拒绝队列控制；服务器不使用客户端连接状态代替执行校验。单条编辑/撤回/插入及清空的重试先查回执，同 ID 换参数拒绝；模型和审批模式在队列或待插入存在时仍锁定。
- 停止：请求带 projectId/conversationId/admissionId/requestId，先串行校验并落盘 stopping，关闭该会话新输入和后续 run 的模型/工具入口，再调用对应 conversation 的 `abort(context, { background: true })`。撤回该会话队列，等待后台、宿主取材、进程及归档收尾；完成前不接新准入。迟到请求或回调只返回原执行结果，不能再调用 abort 误停新任务。原生 abort 不识别 admissionId，该保护由宿主实现。
- 取材取消：尚未 submit 时也有 admissionId 和宿主取消信号；停止取消复制/校验，不再提交模型，清理未发布临时文件后释放占用。已发布快照保留为草稿材料。停止处理中断则重启先补完停止，不恢复原业务。短锁不跨越 abort 等待，不取消其他会话。
- 验收：A13 全部通过：默认顺序、编辑不换位置/材料、插入不打断、final 同时消费、操作与边界竞争、重复请求、失败清理及事务前后退出重启；停止不误停后来任务。T26 再接材料与审批整链。
