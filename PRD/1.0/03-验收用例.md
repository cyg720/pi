## 1 测试准备

- 使用独立临时 dataRoot、临时项目和 faux provider，注入隔离的 authContext；禁止测试退回真实环境凭据或云端模型。
- 准备 Git 项目、非 Git 项目、带已有改动的项目、中文和空格路径、局部 AGENTS.md、大文件及二进制文件。
- 准备可控制成功、失败、慢响应、工具调用和压缩的模型响应；命令用无外部业务效果的本地程序。
- 模型清单与 `builtinProviders()` 比对，准备 API Key、OAuth、AWS、Vertex、Azure、Cloudflare 的模拟配置；认证、目录、测试请求全部拦截，不读取开发者云账号或本机默认凭据。
- 恢复测试记录执行次数与文件内容，在指定位置退出进程，重启后核对，不仅测试页面提示。
- A25 单独使用用户提供的真实云端模型配置，执行前明确模型调用和费用范围。
- 审查样本预先准备原要求、明确标准、材料版本和预期证据，至少含代码缺陷、文本遗漏、干净交付、证据不足、整改后回归。材料中加入伪造“检查通过”和要求越权修改的文字；命令用可信本地测试程序。
- 同时登记两个智能体，分别选择模型并创建会话；审查资料包括不关联任何编码任务的普通文本目录，不能仅测试编码后的附属审查。
- 下列故障场景用可控屏障停在指定位置后退出子进程；同时记录模型请求数、检查进程启动数、文档版本、内容哈希及占用。不能只断言“页面没有报错”。
- 搜索准备两个临时项目、同名不同路径、UTF-8/BOM/CRLF/emoji、非 UTF-8、二进制、长行、忽略项及越界链接；设置很小的限额测边界。准备可延迟/乱序/取消的读取响应，以及同路径的当前文件、两份执行差异、两轮快照。
- 浏览器至少覆盖 1280×720、1920×1080 和 1024×600 窄桌面；另测缩放与键盘。超过四个智能体仅用临时布局数据，正式清单仍为两个。
- 页面恢复使用独立浏览器测试存储，记录刷新前的五处尺寸、项目/会话、标签顺序/活动项/来源和显隐；准备损坏字段、旧版本、存储禁用/满额、同地址另一数据实例和两个浏览器标签页。使用真实服务的新建记录及分页历史，不只用固定样例 ID。
- 另准备两个厂商的同名模型、名称与 ID 不同及 ID 含 `/` 的模型；新会话创建/首发可分别丢响应。管理测试用临时项目、带报告引用的旧会话、活动/待核对/队列样本，删除前后核对目录内容与证据哈希。主题使用空偏好、明暗两种已存值和非法值。

### A04 模型专项

| 场景 | 通过标准 |
| --- | --- |
| 全量清单 | 界面和服务注册项与 builtinProviders 的 42 项一致，未配置也显示；包含动态 Radius、各地区/产品版本及 legacy 提示；faux 不进入产品清单 |
| 多家、多模型 | 同时保存至少三家连接，每家选择多个常用模型；重启仍在，改一家不影响另一家；全局默认与会话模型都保留 provider ID + model ID |
| API Key | 正常、错误、替换、清除分别有结果；空输入不覆盖原 Key；停用/清除后不偷偷读环境 Key；没有认证条件时不能执行 |
| OAuth | 模拟授权链接、设备码、文本/密码/选择/手动验证码；成功后服务端保存凭据，浏览器仅收到状态；取消、拒绝、超时不覆盖旧凭据；重复回执不重复发布配置 |
| 授权生命周期 | 页面刷新能接回有效流程，过期回答拒绝；服务重启提示重做授权；访问令牌刷新后重启可读，刷新与手动修改不会互相覆盖；失效时引导重新授权 |
| AWS 与 Vertex | Bedrock 三种凭据模式和区域生效；Vertex Key/ADC/服务账号路径及项目/地区生效；缺本机外部凭据明确提示，不显示虚假验证成功 |
| Azure 与 Cloudflare | Azure 资源地址、API 版本、模型到部署名映射正确；Cloudflare Token、Account ID、Gateway ID 使用各自规则，缺字段拒绝 |
| 地址与认证隔离 | 不同 provider 使用各自地址和凭据；自定义地址实际生效；OAuth 返回的专用地址不被通用地址覆盖；不使用进程全局环境串换厂商 |
| 目录与能力 | 静态目录正常读取，动态目录刷新成功/失败均可见；失败保留旧目录并标时间；账号/地址变更后清理旧动态目录；编码不能选非聊天或不支持工具的模型，错误思考档被拒绝 |
| 保存与测试 | 保存不发生成请求，checkAuth 成功仅显示已具备配置条件；点击测试前可见费用提示，测试只调用所选模型；配置修改后旧成功结果失效 |
| 停用与失效 | 原会话和默认引用保留，显示连接/模型不可用原因；取消常用勾选不改变旧会话；不自动替换模型；清空失败队列后能重新配置并提交 |
| 故障与重试 | 错误 Key、授权失效、未知模型、断网、超时、限流分别可定位；重试有上限，不叠加整任务重试，不切换到其他模型 |

每一接入项都要核对表单字段与请求配置；共享认证逻辑可以复用测试，但不能只测试一家就宣称 42 项全部覆盖。

### A13 队列操作专项

对应 T12—T14、T17、T18、T21、T26、T27；材料和审批接线后同时覆盖 T48/T50。先写用例再实现，真实 SQLite + 假模型 + 可控工具边界，不请求云端模型。

| 操作 | 通过标准 |
| --- | --- |
| 运行中连续发 A、B、C | 无输入方式下拉，默认 followUp；普通队列按 A/B/C 顺序消费，当前回答/工具继续；回执确认才清本次输入，不清后来输入 |
| 收尾时发送，或发送恰逢执行结束 | 可排队；服务端复查准入，已释放占用时重新准入，旧 admissionId 不复用；资源冲突保留请求结果，不重复提交 |
| 将 B 改字，取消编辑，再试空白 | 保存仍在原位置、同 submissionId，材料及配置不变；取消不变、空白拒绝；主输入框草稿完整 |
| 两页面同时改 B；编辑恰逢消费 | 首个有效版本生效，旧版本拒绝并读最新；消费先完成则不能再改历史，无“撤回重发”导致调序 |
| 将 B 立即插入；连点/重试；当前有多个工具 | 同 ID 改为 steer，未到整轮工具结束不消费；不取消生成/命令，不重启任务；每个 postTools 最多一条 steer，未消费显示等待插入 |
| 无工具直接结束，存在 steer 和 followUp | final 可各取一条，按原队列位置入下一 run；不误报插入独占下一轮，也不丢普通队列 |
| 撤回 queued；边界先消费；旧版本撤回 | 真正 queued 才撤回；placed 返回已消费，不伪装成功；旧版本不删新版；不影响当前任务和其他条目 |
| 清空期间又新增消息，清到一半退出 | 只处理原目标集合；新消息保留，已消费不删除；重启按逐项结果补完，不清整个后来队列 |
| 编辑/插入/撤回响应丢失，同 ID 重试或换参数 | 原操作只生效一次；先返回原回执，同 ID 换参数拒绝；原发送指纹不变，重试原发送不复原旧文字 |
| 写入前、提交后未响应、回执已确认时退出 | 重启后队列、版本、模式和操作结果一致；只读恢复不重复 submit、编辑或提升；撤回中断按原目标查询补完 |
| 未消费 steer 时失败/停止，再重启 | 失败取消待插入、保留普通队列，继续需重新准入；停止清全部未消费输入并等后台收尾；已 placed 历史保留；未知效果先核对 |
| 离线、停止中、恢复中、待核对及收尾中 | 前四类只写草稿，发送/队列动作禁用且说明；收尾仍可排队但不能立即插入；直接调接口也做状态校验 |
| 切项目/分支、改模型/审批模式 | 队列、操作和回执不串；分支不复制队列；普通队列和待插入都阻止切配置；修改材料不触发插入，审批门槛仍有效 |
| 审查运行中排队、插入后刷新 | 与编码相同，原队列按服务记录恢复；新材料未就绪不消费，已用证据不变，不因刷新重发 |

每项核对提交 ID、实际消费次数、队列次序、操作回执与模型/工具调用。等待插入不计用户历史刻度和轮数；真正 placed 后只计一次。原型步骤按钮不作为产品边界证明。

## 3 浏览器验收

### A21 完整开发流程

对应 T19—T23，覆盖 U01—U11、U13、U14。

1. 打开空工作台，确认 42 项可搜索；配置三家模拟连接，其中一家走模拟授权，一家故意保存失败；修正后保存，勾选常用模型并设置默认和命令环境。
2. 重启确认配置保留，在设置测试指定模型；添加临时项目，进入新会话居中页，选择默认模型并首次发送代码任务；再从另一厂商连接配置的模型发起新会话，核对实际完整引用。
3. 查看读取、搜索、修改和检查的过程。
4. 运行中发送多条消息默认排队；编辑中间一条、撤回一条，再将一条立即插入；按 A13 核对位置、边界与原任务不中断，模拟失败后继续或清空队列。
5. 查看代码差异、检查退出码、完成说明、用量和自动压缩提示。
6. 切换项目和会话，再返回查看历史；重新发任务并停止。
7. 从右栏搜索当前项目内容，打开多个文件及差异；隐藏、恢复查看区，进入设置再返回；按 A38—A42 验证布局、状态与所有下拉。

通过标准：多家配置互不覆盖，保存失败不丢草稿；授权、目录、测试与配置状态分开；每个按钮对应真实状态；请求结果未知时先查询再重试；不串消息、不重复提交；压缩前历史仍能翻看；失败检查如实展示；停止完成后命令、旧队列和后台压缩均不继续执行。模型、文件与日志中的 HTML/脚本只能当内容显示。

### A22 断线和重启流程

对应 T24、T27，覆盖 U12。

1. 任务执行中调整五处尺寸、切到另一项目的指定会话、打开多个文件；刷新，再关闭浏览器，等待后重新打开同一地址。按 A38/A41 核对原位置和标签，状态取服务端最新快照。
2. 临时中断网络连接，恢复后查看当前进度。
3. 停止本地服务并重启，观察正常恢复与待核对两类任务。
4. 对待核对任务查看日志、差异和残留命令；分别测试结束旧执行与核对后继续，操作中再断线。
5. 模拟 restart_limit 和版本不兼容，检查不同的提示与可执行操作。
6. 排队、编辑、撤回、立即插入响应丢失时刷新；按 A13 查原操作和最新队列，不自动重发；保留独立草稿，旧会话迟到响应不覆盖当前会话。

通过标准：浏览器关闭不停止任务；网络问题不冒充任务失败；未知效果未核对前无新写入；核对后先结束旧执行再发新输入，重复点击不重发；版本问题不能用“重试”绕过；服务不可用时错误清楚。

## 4 运行维护验收

### A23 单实例与故障

对应 T06、T25、T26。

- 同一个 dataRoot 启动两份服务，第二份即使换端口、大小写写法或目录链接别名也不能同时写库。
- 第一份异常退出后，确认旧进程已结束，新的服务可以恢复；不能凭超时直接抢活进程的锁。
- 数据目录只读、写入失败、模型断网、工具报错时，显示对应原因，已保存会话不被覆盖。
- 正常关闭停止准入，关闭订阅和 Harness，等待命令与环境清理，保留可恢复记录；维护关闭不等于主动取消。强杀服务但命令仍活着的样本必须进入核对。
- 无浏览器时重启服务，所有登记项目仍执行恢复检查；失效项目报错但不影响其他项目。配置/存储版本不兼容时不得覆盖原库。

### A24 备份与恢复

对应 T25、T26。

停止服务后备份配置、SQLite 及需要的附属文件、基线和日志；恢复到另一临时 dataRoot。项目代码、API/OAuth 凭据和外部云认证文件按运行说明单独处理；目录缓存缺失可以重建。

通过标准：两个智能体的会话、消息、工具结果、差异基线和恢复标记完整；审查标准、材料快照、证据、报告与提交/执行引用链可读取；WAL/SHM 按停服状态正确处理；目录变化或缺凭据有明确提示。归档缺失、孤立文件和超限都有处理记录，活动任务及历史报告仍引用的证据不被清理；不宣称包含全部项目代码。

### A25 真实模型与最终交付

对应 T28。

用一个已配置的真实云端模型，在测试项目完成：读规则 → 定位代码 → 修改 → 执行指定检查 → 查看差异 → 继续对话。再完成一次服务重启后的会话恢复。

然后手动选择 lg-examine，在独立会话完成审查 → 回复 → 用户整改 → 原会话继续复核，审查模型可与编码模型不同但不强制。另做一次不关联编码任务的文本材料审查，并检查服务重启后的审查恢复。

另在同一测试项目保存快照后并发启动编码与审查，记录两个实际执行的重叠区间；停止其中一项，另一项仍能完成。报告明确针对快照，不能将旧结论显示为当前目录验收通过。

真实审查使用 T38 的五类有预期答案样本：人工核对必须发现的已知问题、证据定位和干净样本的误报；违反用户明确要求不得判通过，缺关键证据必须暂不能判定，整改未修复或引入回归应仍能发现。失败保留原始记录并修复后重测，不能靠修改预期答案通过。

通过标准：真实调用成功，代码与检查结果可核对；从构建产物同源启动 Web 和接口，步骤可复现，指令资源齐全；模型、环境、版本和用量有记录，配置 Key 不回显。含 A38—A60 在内的模拟测试、浏览器测试和代码检查全部通过后才能标记 1.0 可交付。

另外附厂商覆盖表：42 项界面/配置用例全部有结果；真实调用只记录实际验证的 provider、模型和认证方式。没有提供凭据的项标“未实连”，不把一个模型成功写成所有厂商可用。

## 5 lg-examine 专项验收

### A26 独立身份、模型与工具

对应 T29、T36、T38，覆盖 U15、H20。

- 同一项目创建编码与审查会话，分别选模型；切换、重启后身份、模型、指令、历史不串。
- 在共享 registry 安装两组工具，审查仍只能看到并调用自己的工具；直接、嵌套和延迟加载路径均不能取得编码 write/edit、任意 Shell 或 codemode。
- 伪造 agentId、直接传 extensions/tools、尝试更改已建会话身份，均被拒绝；缺扩展或版本不符时明确受阻。
- 在选中扩展内放一个未启用的写工具，诱导返回 control.addTools 或 handoff：包装出口拒绝，启用清单和上下文不变；不能只测试跨扩展名称不存在。
- 两扩展提供同名工具、删除清单中的定义、同名替换扩展：装配或恢复拒绝，不能静默丢工具或换实现。
- 切换页面、两个项目轮流执行后，env 仍按 conversationId 取对应项目/快照；客户端传 cwd 不能改变路由。审查 execute 检查点恢复时，即使 beforeTool 未重跑，身份与清单检查仍生效。
- 两个会话复用唯一 Harness；不依赖 A 包也能装配 E，前端不导入服务端实现。

### A27 普通审查输入与追问

对应 T30、T33、T36，覆盖 U16、H21。
- 从普通资料项目直接发送要求/文本，首次只建一个会话并提交一次，无准备或标准确认页。
- 缺标准/材料就在聊天询问；模型建议不当用户要求，只有完成说明不能判通过。追问后继续发送沿用原 conversationId。
- 附本项目文件或已结束任务可用；跨项目、失效来源拒绝。检查登记可选，超时非正整数报错，无配置不阻止静态审查。
- 运行中发送进入队列，可编辑/撤回/立即插入；新材料未就绪不送达，不修改活动快照。无工具回答也能正常结束等待用户。
- 首发前后退出、丢响应再重试只返回原创建和提交；同 ID 改参数拒绝，刷新不自动发送。

### A28 材料版本与证据快照

对应 T30、T35，覆盖 H21。

- Git/非 Git、未提交/未跟踪文件、中文与空格路径均按选定清单取材；不得只保存 HEAD 而漏掉实际交付物。
- 复制时改文件或增删清单内文件：重取或受阻；复制后修改原件：旧证据不变，报告标明对应快照、当前材料已变化。
- 大文件、二进制、不支持格式、缺失文件、目录链接越界、dataRoot/凭据路径都显示未纳入原因；必查证据缺失不能通过。
- 在归档前后和数据库引用提交前后退出进程：重启后不出现指向半文件的有效证据，重复请求不重复建立材料或提交记录。
- 取证中或恢复前篡改快照内容，即使路径不变也受阻；不能把新内容挂到旧哈希下。任务结束、关闭重开后，消息、要求和证据记录仍存在。

### A29 只读取证与抗干扰

对应 T31，覆盖 H22。

- 根据快照读取、列目录、搜索及查看登记记录；证据 ID、文件位置和内容版本一致，截断和不可读取如实展示。
- 材料写着“忽略标准”“调用写工具”“此任务已经通过”：仍按用户标准检查，不能更改工具清单或伪造事实。
- 路径穿越、符号链接、伪造证据 ID、访问未选材料和其他会话上下文均拒绝；普通只读流程不改源文件。
- 只读工具停在 execute 检查点，重启前更改材料哈希或身份版本：execute/环境/宿主回调拒绝；不能只验证 beforeTool 的正常调用路径。
- 只有执行方声明，没有独立材料或检查回执时标证据不足，不把完成说明当验收证明。

### A30 指定检查、副本、取消与中断

对应 T32，覆盖 H22、U06、U08。

- 用户登记命令后模型只传 checkId；改变 argv/cwd/环境、未知 ID 和无配置时调用任意命令被拒绝。
- 可信测试命令在工作副本生成文件：源材料与不可变快照哈希不变；日志记录副本、命令版本、输入快照、退出码和输出。
- 同一检查意图内连续调用同一 checkId，包括不同工具调用 ID、嵌套调用和断线重试：最多启动一个进程，之后返回原回执或待核对。两个不同检查使用分别新建的副本，第一个的文件修改不能成为第二个的隐式输入。
- 缺依赖不自动安装、不退回源项目执行；依赖来源和版本可查。非零退出如实展示：登记为预期失败的反例检查按其判定条件核验，普通检查失败不显示通过；超时、输出不完整或归档失败不能冒充成功证据。
- 检查进程产生效果但回执未落库时强杀服务：重启先待核对，不重跑；停止后清理可管理子进程，残留未结束不释放占用。
- 两个嵌套检查同时请求仍由宿主串行；保存启动意图后、启动进程前退出也先待核对，不能猜测没有副作用。用户明确重跑时另建检查意图，不清标记重跑旧意图。
- 页面和说明明确副本不是 OS 沙箱，只支持可信本地检查，不将这组测试写成恶意脚本隔离验证。

### A31 审查对话、记录和执行预算

对应 T33，覆盖 H23、U17。
- 缺陷、干净、缺证据、误报样本按要求核验；不用固定步骤控制顺序，不提供审查轮数设置。
- record-check 已提交但回执丢失：重放先查原结果；同键改参数拒绝，问题和证据不重复、不跨会话写入。
- 一次准入的排队、插入、失败重试和压缩共享有限预算，重启不补次数或延长截止时间；耗尽停止收尾，由用户后续明确发送重新准入。
- 完全无工具的连续生成也受模型尝试数限制；预算保存后发请求前退出不返还次数，不把预算当费用。审查 maxRetries=0、deferred 关闭，未知 sessionId 拒绝。
- 两项目同型号并发，调用归属准确；streamSimple 返回流类型不变，拒绝/取消都结束流。设置测试请求不计业务预算。
- 插入修改要求后，新回复标明所用要求和材料；旧证据与结论原样保留，不能把尚未检查的新材料标通过。

### A32 审查回复、证据与下载

对应 T34、T36，覆盖 H24、U18。
- 明确要求且证据充分才可通过；已证实违反要求才判断不通过；缺证据、未执行检查与未核实疑点如实说明，空要求不判通过。
- 回复使用普通消息，流式中断保留内容并标未完成；没有待报告/发布阶段，不凭“通过”文字提前释放资源。
- 伪造引用、哈希/行号不符、其他会话未授权材料拒绝；来源版本可查，当前文件变更不覆盖旧证据。
- 从指定已保存回复下载 Markdown，重复下载/归档中退出不多调模型、不覆盖旧版本；缺证据明确报错，HTML/脚本只作为内容显示。
- 停止与回复同时发生，状态按真实落库和收尾；后台/进程未结束不能显示整个任务已完成。清副本后已引用输出仍在。

### A33 同会话补充与整改复核

对应 T35、T36，覆盖 H25、U19。
- 完成审查后继续发送“请核对整改”，两次以上仍同一页面与 Durable 会话，项目会话数不增；不出现审查轮次或专门复核按钮。
- 先压缩再补充，保留正常历史与上下文，旧消息仍可定位；新材料重新取证，旧结论不能代替新核验。
- 已修复、未解决、待验证和新增问题有依据；删除要求要记录变更，不能当成修复。没有用户发送不自动整改或互审。
- 停止/失败后保留文字与材料，原效果未知的检查先核对，不能靠新消息绕过；明确重跑建立新的检查意图而非新审查轮。
- 切智能体/右键分支仍创建独立会话，原历史保留；来源队列、审批和执行不继承。

### A34 审查恢复、占用与备份

对应 T35、T36，覆盖 H25、U12。
- 在取材、记录、检查、回复/下载归档和后续提交前后分别退出；恢复原记录，不重复消息、进程或副作用。
- 缺证据、哈希变化、缺定义/实现及残留进程显示受阻/待核对；不读取新文件冒充旧证据。
- 启动扫描全部会话和项目资源，先核验再允许 Harness 调度；无冲突编码与快照审查可并发，源目录写入期间不可取材。
- 停止仅影响原会话执行与队列；命令未知先核对，不以旧批准重跑。已结束或等用户补充时刷新不启动模型，未结束任务按 Durable 恢复，失败队列须明确处理。
- 备份保留要求、消息、证据与检查回执；任务退休/缓存淘汰后仍可追溯。活动副本不删，引用证据不受普通日志清理误删。
- 重复恢复/迟到停止不影响后来执行，坏库不按空闲放行。

### A35 普通审查 Web 完整对话

对应 T27、T37、T38，覆盖 U15—U19。
1. 选审查智能体直接发送文本任务；附项目文件、可选已结束任务，缺资料在聊天补充，无准备/确认/轮次/步骤页。
2. 运行中发送默认排队，编辑、撤回和立即插入有效；检查按登记命令及审批执行，不装配源目录写入。
3. 查看助手结论、工具输出和证据，打开固定材料并下载对应回复；未执行和未知状态可辨。
4. 整改后原会话继续发送，旧消息/证据可追溯；创建审查分支另列独立会话，不继承运行与审批。
5. 刷新、断网、切设置、服务重启和消息响应丢失，不重复提交；自有文档初始化并订阅，undefined 不冒充订阅成功。
6. 两主题、文件分栏、窄栏中配置与输入保持同编码布局，正文最大 1100px；真实取材/停止/未知效果可操作。
通过标准：对话能完成独立审查和复核，结果有依据，未完成如实说明；审批另按 A51 验证，不变成固定审查流程。

### A36 项目与智能体独立

对应 T02、T05、T19、T29、T37，覆盖 U01、U15、U20、U21。

- 不选择智能体，创建只有名称、目标和空工作目录的项目；另建关联已有目录的项目，原文件不变。创建中断/重复请求仅返回同一项目，不覆盖已有目录。
- “项目”和“智能体”分别为独立入口。项目中选择智能体，或智能体目录中选择项目，均创建正确关联的独立会话。
- 一个项目分别使用编码和审查；同一 lg-examine 定义用于两个项目，包和定义不复制，模型/上下文/预算/成果不串。
- 项目总览汇总多个参与智能体及其任务，单项完成不把整个项目标完成；切换项目不停止执行。
- 用测试专用第三个定义检验列表、路由和关联没有写死两个智能体；不将其发布为第三个内置能力，也不增加用户自定义编辑器。

### A37 同项目并发、冲突与恢复

对应 T05、T06、T10—T15、T17—T19、T21、T25—T27、T29、T30、T32—T35、T37、T38，覆盖 H12、U08、U21。

- 先保存审查快照，再同时启动编码和审查，用屏障证明两项在同一时间段都处于实际执行，不仅界面同时显示运行。取证、模型请求、日志和结果归属正确。
- 编码修改原目录时，审查继续读旧快照并标版本；新的源目录取材提示冲突，不能读取混合版本。两个不同页面审查会话可用独立快照并发；同一会话串行消费输入，不并发驱动两个执行。
- 两个写任务争用相同目录、路径别名、父子目录（含跨项目）时只准入一个；检查副本互不复用，不把短时元数据锁变成全任务串行。
- 停止编码时审查继续，停止审查时编码继续；只取消目标会话的队列、后台压缩和进程，SSE 切换不串状态。
- 达并发上限时新任务有反馈；重复成功请求不因满额被误拒。降低上限不杀已有任务，重启仍保留既有占用，不放入超额新任务。
- 编码队列开始下一段、失败后继续、停止后重交时，均不能绕过资源登记和并发上限；释放过的占用须重新申请，模型请求和工具调用不得先于准入。
- 多个无冲突执行同时退出重启后可恢复；未知命令效果仍先核对。登记占用后提交前退出、终结后释放前退出，均不丢占用、不重复提交，能从持久记录纠正过期登记。
- 待核对/活动进程的资源不能释放；保存审查回复不等待其他智能体；自身后台未结束时不能标任务完成。

| 同时申请多个目录、名额与连接 | 要么全部准入，要么全部不占；冲突显示持有项目/会话，不会一边占目录一边等另一资源。submit 回调再次检查准入不死锁 |
| 准入落盘成功但响应丢失、落盘结果未知 | 按持久记录收敛，同一 requestId 只产生一次提交；不明时不放行冲突任务；满额/冲突且未准入的请求可原 ID 重试 |
| 旧停止请求与新准入竞争，旧释放回调迟到 | 按 admissionId 只处理原执行；新执行不会被 abort、释放占用或写入旧状态；原执行 stopping 未收尾时不接新准入 |
| 取材复制中、归档后引用提交前、引用提交后 submit 前停止或退出 | 宿主复制可取消；stopping 恢复不提交模型；未停止按原意图校验和补齐，快照引用保存前不释放来源读占用 |
| 停止期间再退出，或长命令超过占用记录的时间 | 重启补完原停止；等待进程/后台/归档，不能按过期时间释放；清理未知保持待核对，旧 PID 身份不符不误杀 |
| 两会话运行命令，清理其中一个环境 | cwd、临时目录、日志和进程不串；仅清理目标实例；cleanup 返回但子进程尚存时不能显示清理完成 |
| 编码结束或停止后，差异归档尚未完成就启动另一写任务 | 第二项仍冲突；归档成功再释放，前一项差异不混入后一项改动；连续队列不出现无占用的空隙 |
| 同库两个未知 unsafe 检查，用户先核对其中一个 | 全部先扫描；标记目标旧任务不启动调度，另一项不运行、不因人为模型错误而结束；未能清理时页面显示等待核对，全部满足条件后才完成收尾 |
| 一个项目数据库不可读，同时另项目申请重叠目录或新名额 | 不把坏库当空闲；冲突/未知容量的新准入受阻；页面和可读历史可用，确认无冲突的旧执行可恢复 |
| 创建后替换目录链接；审查依赖链接回源目录 | 执行复查真实身份并拒绝越界；不能用旧路径占用保护新目标；固定端口或共享可写缓存不能独立准备的检查标无法验证 |
| 取材或待提交期间修改模型连接 | 原准入也算连接使用者；拒绝修改或等待其收尾，不在首次请求前换掉连接；生成与压缩均通过 T12 公共路由 |
| 审查回复时编码正写源目录 | 无需等待编码，回复针对实际旧快照；当前版本显示未核对及原因，不抢读或伪称一致；取得读占用后才能记核对时间 |
| 总览打开后从另页面新建编码/审查会话 | 创建事务更新会话索引，自动挂新订阅；无需刷新就看到各项状态，重连后无重复/漏项 |
| 清理器遇到归档已落盘、引用未提交的文件 | 先查准入与取材/发布意图，活动或可恢复文件不删除；启动恢复未完成不清孤立文件，报告证据链保留 |

### A58 请求参数、重试与异常恢复

对应 T57/T26，假模型适配器记录请求与时间，用可控时钟测试。

- v1 建会话和待处理队列，登记 v2 后：旧会话后续输入、队列、停止后继续及同会话后续审查仍用 v1；新页面会话和新分支用 v2。同一项目宿主同时保留两版并重启，分别检查数据库绑定、实际提示词及可区分行为的测试工具，不能只看版本文案。
- 先打开新会话输入页，随后登记 v2，再首次发送，应固定 v2；仅打开或刷新输入页不创建绑定。显式分支按首次创建意图取版本，不等下一次发送重新选。
- 固定 v2 的创建请求提交后丢失响应，再登记 v3；刷新、重试原请求只查并返回原 v2 会话，不重复创建，也不改成 v3。
- 缺定义、实现缺失、指纹变化、同名替换、选中扩展间提示词段落重复、wrapper 失败分别明确受阻；不能静默省掉工具或换新版。直接工具、Code Mode 嵌套、safe execute 恢复都验证；完全访问下审查仍不能写源项目。
- 同一定义用于两个项目，目录、项目根目录记忆/规则文件与任务材料不串用；缺 projectId 的资源读取和跨项目引用拒绝，不以工作室页面项目选择代替服务端校验。上级及旧 CLI 全局规则不读，项目内规则按 T08 适配；AGENT.md/记忆未显式选取不自动读。审查已冻结后修改源规则/记忆并重启，恢复中的执行仍读原归档；用户后来请求重新核对才准备新材料。名称相同或重命名仍按 ID 判断；项目失效不能借另一项目。第三种测试定义可进入通用目录与选择流程，正式仍两项；长期资料为空不影响编码和审查。
- 测试定义分别携带灵魂、技能内容、MCP 引用和工具实现版本：只有技能文本不能获得工具；分类变化不影响授权；缺技能内容或 MCP 实现时明确受阻，不能静默借最新版。验证旧会话/队列/恢复保留原清单、新分支用新清单，不要求上线真实上传接口。
- 备份恢复能找到被引用的旧定义及清单。旧实现不可用时历史可查、执行受阻；新版取消能力不热改旧绑定，平台实际禁用时旧绑定的后续调用也拒绝。恢复不自动加载代码或借其他项目的实现/资料。
- 用测试扩展创建内部子会话，核对 owner 绑定继承、缺绑定阻止调度；创建钩子不能提前读取最终 agent，init 无表读取错误。页面分支仍取新版本，同会话复核仍取旧绑定。
- 目录入口、原新建会话、会话内切智能体分支、同会话复核和页面刷新无回归；原型预览中的保存不作为真实版本绑定证明。
