本次同步：灵魂、Skills/MCP 拆分、技能分类卡片与上传；审查改为普通对话，保留独立分支、证据来源和恢复边界。1.0 共 60 项任务、61 组验收；完整工作室与真实技能上传仍为 2.0。产品实现待开发。

本次调整：工作室只管理智能体通用配置，去掉项目选择和项目资料分层。项目记忆/规则由各项目根目录文件维护，执行隔离仍保留。完整工作室属 2.0，1.0 仅做 T60/A61 预留。

## 1 已确定的方向

| 项目 | 1.0 决定 |
| --- | --- |
| 平台目标 | 面向各行各业，逐步增加不同专业的智能体 |
| 持久运行 | 固定采用 `pi-durable`，选型已确认，不再比较其他运行时 |
| 用户 | 单用户 |
| 权限 | 单用户工具审批纳入 1.0：手动审批、自动审批、完全访问；不做平台账号、角色和租户；厂商授权仍属于连接配置 |
| 部署 | 本地私有化部署，服务端直接调用云端模型 API |
| 模型配置 | 一个页面覆盖 packages/ai 全部内置接入项，同时配置多家连接和多个常用模型 |
| 界面 | 优先完成 Web；稳定后再开发桌面版和手机端 |
| 首个智能体 | `lg-codeing-agent`，名称按此拼写使用 |
| 第二个智能体 | `lg-examine`，独立做验收、对抗审查和整改复核 |
| 实现路线 | 两者都直接基于 Durable，独立包、指令、工具和会话，共用平台服务；编码参考现有 coding-agent |

1.0 交付两个内置智能体。跨行业是平台方向，审查不限定为代码检查；首批支持文本、代码、差异、任务和检查记录。其他专业智能体后续再加。

### 项目和智能体分开

项目保存目标、资料、任务和成果；专业智能体是平台统一提供的能力。新建项目不绑定智能体，也不复制智能体包。一个项目可以让多个智能体同时参与，同一个智能体也可以服务多个项目。

具体执行时，用户在项目中选择智能体创建独立会话和任务。每次执行有自己的模型、上下文、工具和结果；项目页汇总展示，智能体目录单独展示能力。1.0 内置两个，数据结构不把种类写死为两个；暂不增加自定义智能体编辑器或自动派单。

## 2 用户怎么用

1. 启动本地服务，在浏览器打开工作台。
2. 从左下设置配置模型，从左侧新建项目，填写名称、目标，关联已有目录或创建空工作目录；不必选择智能体，没有模型也能先建项目和浏览文件。
3. 点击项目加号、总览新会话或智能体入口，直接进入居中输入页，不弹窗。选项目、智能体、模型，首次发送才创建会话；编码进入执行，审查先带入要求并填写标准与材料。一个项目可有多个独立会话。
4. 编码时查看读文件、改代码和命令过程；审查时查看验收清单、证据、反例与问题核实过程。
5. 从右栏浏览、搜索文件和查看差异；打开文件时保留左侧会话，可同时查看多个文件。编码结束后可手动新建审查，也可直接审查已有文本材料。
6. 查看审查回复，用户或执行智能体另行整改，再向原审查会话发送复核要求；不自动派单或循环互审。
7. 关闭浏览器不会停止任务；服务重启后查看已保存进度，恢复前核对材料版本和执行状态。

项目文件和运行记录保存在本机。发给模型的提示词、代码片段和工具结果会通过 API 发送到云端。

## 3 首个智能体做什么

`lg-codeing-agent` 是平台内置的编码智能体，先完成开发工作的基本流程。

| 能力 | 1.0 实现 |
| --- | --- |
| 理解项目 | 读取目录、文件、README 和适用的 AGENTS.md |
| 查找代码 | 文件查找和文本搜索，统一封装系统工具调用 |
| 修改代码 | 新建文件、精确编辑，显示修改差异 |
| 执行命令 | 运行项目命令和指定检查，展示输出与退出码 |
| 持续对话 | 历史会话、追加任务、执行中补充说明、停止 |
| 上下文管理 | 复用 Durable 的上下文压缩 |
| 持久运行 | 保存消息、工具调用、执行状态；重启后恢复 |
| 结果说明 | 列出改了什么、检查是否通过、还有哪些问题 |
| 模型设置 | 从已配置厂商选择模型和适用的思考档，显示用量与可获得的费用估算 |

编码智能体遵守项目自身的开发规则。工具执行遵守用户选定的审批模式；审批通过也不能扩大智能体工具范围。

### 第二个智能体：lg-examine

它用普通对话独立核对交付物。用户直接发送审查要求，可附项目文件、文件夹、交付文本或本项目已结束任务。缺标准或材料就在对话里询问，不再要求填写准备表单、点击确认标准、走固定五步或创建审查轮次。

- 审查、补充和整改后复核都在原会话继续发送；同一个页面会话对应同一个 Durable 会话。切智能体或右键“新会话分支”才创建独立分支，保留原会话。
- 回复说明检查范围、实际材料版本、问题、证据和未验证项。可按需整理和下载 Markdown；不设单独的报告发布阶段。已证实违反明确要求才判断不通过；证据不足就说明无法判定，不能把“没发现问题”当通过。
- 运行中发送默认排队，可编辑、撤回或立即插入；插入在安全边界送达，不打断工具。新要求、新材料记录来源，不修改已保存的证据和旧结论。
- 审查只读选定材料，不装配 write/edit、任意 Shell 或 Code Mode。登记的可信检查在独立副本执行；缺环境说明无法验证，不自动安装或回源项目运行。完全访问也不放宽这些边界。
- 取材、检查、证据和结论按实际提交/执行关联。后台仍保留请求去重、有限执行预算、停止、审批、资源占用与恢复；不新增审查轮次、轮数限制或固定审批审查流程。
- 刷新恢复原消息位置、材料来源、草稿和服务端队列，不重发消息。命令效果未知先核对，不重跑；旧结果始终可追溯，后续复核重新核对变化部分。

首版支持本地文本、代码、差异和平台记录；PDF/Office/图片解析、联网事实核查及行业系统接入后续再做。

## 4 怎么实现 lg-codeing-agent

采用“Durable 执行内核 + 编码工具 + 编码指令 + Web 界面”。

- Durable 负责会话、模型调用过程、工具任务、存储和恢复。
- 直接复用 Durable 的 `read`、`write`、`edit` 和命令工具。
- Windows 接入已有的 PowerShell 工具，Bash 按本机环境配置。
- 编码包负责项目规则加载、代码搜索、开发指令和结果整理。
- Web 负责项目列表、聊天、执行过程、项目搜索、多文件查看、差异和设置。页面搜索由本地文件服务实现，不调用模型或启动智能体。
- 模型连接由平台统一管理，复用 pi-ai 的全部内置厂商及其认证；编码智能体使用其中支持聊天与工具调用的模型。
- lg-examine 独立装配审查指令、取证与指定检查工具。两个智能体可用不同模型，创建会话时固定身份；对话中切智能体会新建分支，原会话身份不变；编码接入 Durable Code Mode，审查不装配。

现有 coding-agent 作为功能参考，原包继续保留。新智能体不通过旧 SDK 或 PI CLI RPC 运行，也不复制旧的会话管理和 TUI。旧会话格式、旧扩展接口的兼容迁移不列入 1.0。

具体复用位置见 [技术实施说明](./TECHNICAL-REVIEW.md)。

## 5 系统结构

```text
浏览器 Web
    │ HTTP 发命令，SSE 接收进度
本地服务
    ├─ 项目与会话管理
    ├─ 智能体注册
    └─ 公共运行层
         ├─ pi-durable：持久运行
         ├─ pi-ai：全部内置厂商、认证与云端模型调用
         ├─ SQLite：保存运行记录
         ├─ lg-codeing-agent：编码指令与工具 → 本机项目
         └─ lg-examine：审查指令与工具 → 材料快照、检查副本、报告
```

本地服务默认只监听 `127.0.0.1`。API Key 和授权令牌由服务端保存，已有凭据不回传；浏览器可输入新凭据，但不写入浏览器持久存储。不建设平台登录和角色权限；单用户工具审批纳入本版。文件与命令使用启动服务的本机账户身份执行。

## 6 数据怎么保存

- 本地配置按 provider ID（接入项标识）分别保存连接、启停状态和常用模型，另存全局默认和项目目录；首版每个接入项一份生效连接，可共用多个模型。
- 浏览器本地保存五处尺寸、当前页面、项目/会话引用、文件标签、搜索条件、显示模式和未发送草稿；刷新或重新打开同一地址恢复。按服务数据实例、项目和会话区分，不存文件全文、搜索结果、连接密钥或执行状态。
- 项目、会话和已提交消息仍以服务端记录为准。新建成功后刷新能找到原记录；浏览器只恢复查看位置，不据此重新建项目、发任务或恢复执行。
- 新会话未发送草稿按项目保存，首次发送保留创建请求与首条提交关联；响应丢失只查原请求，不重建。明暗主题单独存为同源浏览器外观偏好，首屏就应用，不依赖服务数据实例。
- 项目/会话名称版本、删除标记与操作回执保存在服务端。删除移出日常列表并禁止执行，不删磁盘项目、数据库和历史证据；审查仍可只读追溯被引用的旧来源。本版不做恢复入口或物理清库。
- API Key、访问令牌和刷新令牌独立保存在服务端，配置与凭据重启后仍可用。模型目录缓存和测试记录保存更新时间与配置版本，连接变化后旧验证结果失效。
- 每个项目使用独立的 Durable SQLite 存储，保存会话、提交、消息和工具任务。
- 同一数据库只打开一个 Harness，由本地服务统一管理。
- 代码直接写入用户选择的项目目录，差异与命令结果在 Web 展示。
- 同项目允许多智能体并发。编码占用正在修改的工作目录；审查读取已保存快照、在独立副本检查，两者可以同时执行。仍在写入的目录先完成当前写任务再取材，不把半成品当稳定快照。
- 读写或写写争用同一目录时提示冲突，父子目录、跨项目重叠和路径别名也要识别；只读取材之间可并发。首版通用 Shell 按整个工作目录独占，不承诺按文件名推断其全部影响；外部编辑与脚本副作用仍如实标记。
- 编码、审查运行中发送均默认进入 Durable 队列，可编辑、撤回或改为立即插入。不同会话独立运行，受服务端并发上限限制；满额提示重试，不新增跨智能体自动任务队列。
- 审查和复核都在原页面与原 Durable 会话内继续，保留正常历史与压缩上下文。只有显式分支或切智能体才创建独立会话；新消息不改写旧要求、材料和结论。
- 标准、进度、预算、幂等回执与报告引用放在项目级/会话级自有文档，不能放在随任务结束退休的任务级文档中长期保存。材料与报告写在 dataRoot；引用的完整输出、生成证据独立归档后才可清理检查副本，备份保留全部引用链。

一次执行可含多条补充输入，各请求用固定请求 ID 防止重试重复提交。审查要求、材料、检查和回复按消息/执行关联；等待用户补充不算模型持续运行。进度以 Durable 与同库自有文档为准，不再建独立任务状态库。

执行开始前，统一检查名额、目录和模型连接，并保存本次准入标识。取材尚未调用模型也算执行中，可以停止；停止后不再自动提交。停止请求只作用于原执行，旧按钮或迟到响应不能停掉后来的任务。资源一直保留到进程、后台任务和必要归档收尾；不能靠超时自动释放。编码结束差异归档后，才允许下一项改同一目录。

检查副本分别持有环境与进程，不能共用一个可变 cwd。已知需要共享可写缓存、固定端口等环境而无法独立准备的审查检查，首版标无法验证；不把复制目录等同于完整环境隔离。

重启先检查全部会话与跨项目资源，重建身份、模型归属和资源占用，再开启调度；无冲突任务可一起恢复。结果未知的命令先待核对，必要时阻止该项目自动恢复，不盲目重跑。核对并结束旧执行后，用户可在原会话继续发送；这属于恢复处理，不是审批。

数据库损坏或占用记录读不到时，不能按空闲放行；先保留可能受影响的目录与名额。其他项目仍可查看，确认没有冲突的旧执行可恢复。重启先补完已保存的停止和归档，再恢复业务，不会因处理一个待核对任务而启动另一个。

审查结论只对实际使用的材料负责，记录固定快照、要求和回复的关联。当前材料另标“一致、已变化、未核对”；编码正在写入时不抢读，也不等待它结束才显示旧材料的结论。整改后在原会话发送并重新核对新材料，保留旧回复；修改要求要留痕，不能靠删要求伪装已修复。

设置页保留左导航，替换中间和右栏，只含模型连接、常用与默认模型、基础配置，所有项目共用。总览、目录、设置及未发送的新会话页不显示旧会话统计；切页不停止任务。

### 新建会话与右键管理

新会话直接在中间填写，输入框居中；项目选择在上方，智能体/模型/思考档靠右、位于发送按钮左侧，用无背景无边框的文字下拉。进入页面不建空会话，首次非空发送才保存；编码发送后输入回到底部，审查先填标准和材料，不直接取材检查。无模型可进设置再回来，草稿及选择刷新保留；打开的文件暂隐藏但标签保留。

不填写会话名称。默认取首任务规范空白后的前 28 个 Unicode 字符，不额外调用模型总结；后续可右键改名，回复不覆盖手工名称。重复发送、创建成功但提交失败均保持原会话；响应未知先查原请求。

项目和会话支持右键或 Shift+F10 重命名、删除。名称为去首尾空白后的 1—80 个 Unicode 字符，不能含控制字符；同名允许，ID 和目录不变。删除先确认项目/会话及范围；项目删除包含其下会话。执行、取材、待提交、停止/收尾、后台压缩、活动进程、待核对或队列未结束时禁删，服务端复查，删除不能代替停止。

删除只移出工作列表并禁止新执行，保留磁盘文件和报告证据。删除当前会话回总览，删除当前项目转其他有效项目，最后一个删除后显示新建入口；清理相关草稿、标签、搜索及设置返回引用。删除与新建/提交一起检查，刷新、重启和迟到响应不能复活；已有报告仍能只读追溯被删来源。本版无回收站、恢复或物理清库。

### 默认暗色与模型名称

暗色采用深蓝底、蓝灰面板、青绿强调；亮色沿用白底绿强调。左下设置旁单个太阳/月亮图标切换，首屏恢复上次选择。主题与工作位置分开保存，刷新或清工作位置不重置；存储不可用时本页仍能切换。所有表单、下拉、右键、弹窗、代码/差异和提示一起适配，切换不丢草稿、标签、尺寸或中断任务。

模型下拉、会话切换、默认模型只显示模型名称，不拼厂商；缺名称用完整 model ID，不截掉模型自身路径。内部仍用 provider ID + model ID，同名项不合并、不按名称找第一个。目录刷新和页面恢复不能切错连接；厂商设置页仍显示厂商与认证方式。

### 搜索当前项目

搜索放在文件和变更之间。支持字面内容匹配、大小写开关、路径包含筛选；输入后短暂防抖，结果按文件分组，可折叠，显示文件数、匹配处数、行号和高亮，点击定位文件。一行命中两次算两处。条件按项目分别保留，清空和快速切换不会被旧响应覆盖。

只检索当前项目可读取文本，不混历史差异、审查快照和其他项目。跳过忽略项、二进制、不支持编码或超限文件，明确显示限制；超时或达到数量/大小上限标“部分结果”。空关键词不扫描，无文件、无匹配、加载、取消、失败分别提示。不做替换、正则或跨项目搜索。

搜索与页面浏览可在编码写入时使用，只说明某次读到的内容，不保证整个目录一致；文件变化后提示重新搜索，不按旧行号误定位。它们不占智能体执行名额，也不取代审查快照；审查取材仍遵守源目录读写冲突规则。

### 多文件查看

打开文件后，中间为“窄会话 + 宽查看区”，右侧资源列表保留。会话和文件分别滚动，输入和停止始终可用；无会话时保留项目总览。多标签可切换、逐项关闭，过多横向滚动。

同项目同来源同文件复用标签；当前文件、指定执行差异、工作区差异和不同执行的材料快照分开。标签固定打开时的来源，切会话不能把旧快照换成新材料。按项目保留标签，切回恢复；设置返回不丢标签、草稿和阅读位置。

查看区右上可整体隐藏，保留标签并让会话恢复中间全宽；顶部“查看文件 · 数量”可恢复。关闭最后一项也恢复全宽。首版只读，不增加完整 IDE、编辑器、终端、Git 提交或回滚。

### 手动调整区域大小

五处分界线可拖：项目栏右边、会话/文件之间、资源栏左边、顶部栏下边、智能体区上边。每区有最小宽高，到限即停，也不能挤没相邻区域。双击恢复默认，支持键盘微调；五处尺寸存为浏览器本地布局偏好，切页和刷新后保留，双击只恢复该处默认。拖动不丢草稿、不停任务，隐藏查看区后会话仍恢复全宽。具体尺寸和用例见功能清单、A38/A41。

### 刷新回到原页面

保留当前项目、新会话页、会话或总览；停在设置/智能体目录时也恢复该页，设置返回原工作位置。文件标签保留顺序、选中项、固定来源和查看区显隐；右栏标签、差异筛选、各项目搜索条件、项目展开状态、智能体列表/方块模式和草稿也保留。新会话草稿按项目保存，不依赖尚未创建的会话 ID。

先读本地偏好，再向服务端核对项目、会话及文件来源。服务暂时断开时保留位置并显示重连，不当成记录已删除；确认会话不存在时回该项目总览，项目不存在时回项目列表。文件缺失或归档损坏显示原因，不换成同名文件或当前版本。搜索结果重新查询，旧行号须核对内容版本后才定位。

页面恢复只恢复查看和未发送文字，不重发任务、批准动作或启动检查。任务状态重新读取服务端；模型设置从服务端读取，连接和授权输入框不落浏览器存储。弹窗、下拉展开和像素滚动位置不恢复；主动选择的消息按稳定 entryId 恢复。

缓存损坏、版本不兼容或存储不可用时有提示并回退，不能白屏或覆盖服务端记录。同一地址换了服务数据实例也不能串项目；不承诺不同浏览器、端口或设备之间同步。

### 统一下拉

输入框、文本域和有边框下拉聚焦或展开时，只把原有 1px 边框改为淡蓝色，不叠加 outline 或外圈阴影，不改变尺寸。搜索框和任务输入框改容器原边框。发送旁的纯文字下拉继续无背景、无边框，用淡蓝文字/箭头和下划线提示焦点；普通按钮保留键盘焦点。明暗主题都要检查。

所有下拉使用跟随主题的圆角菜单：柔和阴影、充足间距、青绿选中项与勾选、清楚的悬停/焦点，长列表内部滚动。新会话用纯文字触发器，键盘焦点保留。按空间上下展开，弹窗内不裁切；方向键/Home/End、Enter、Esc、Tab 均可用，关闭后焦点正确，切页不残留浮层。

覆盖差异范围、新建项目/会话、模型与思考档、认证和设置中的选项。禁用原因、表单值、字段联动及忙时模型限制保持有效。原型样式是参考，产品共用一个下拉组件。

### 模型设置页

当前源码共有 **42 个内置接入项**，含厂商、网关、地区和产品版本，全部进入页面。完整名单统一维护在 [1.0 功能清单](../1.0/01-功能清单.md)，不只接入常见的几家。

- 搜索全部接入项，按已配置、未配置筛选；用户只填写自己需要的厂商。
- 多家连接分别保存，支持“保存当前”和“保存全部修改”。逐项显示结果，失败保留草稿，成功项不回滚。
- 按厂商显示 API Key、OAuth（浏览器授权）或专用配置。AWS、Vertex、Azure、Cloudflare 使用各自参数；需要外部云凭据时给出准备指引。
- 授权过程展示链接、设备码、输入问题和进度，支持取消、超时、重新授权；可替换/清除凭据或停用连接。
- 每家可搜索模型、勾选多个常用模型、设置全局默认；两个智能体会话可分别选其他已配置厂商，均要求支持聊天与工具调用，其他模型展示不可选原因。
- 保存不发生成请求；“测试所选模型”由用户点击，并提示调用费用。配置已保存、尚未验证、验证成功/失败分别显示。
- 目录刷新失败保留旧目录并标时间，切换账号或地址后旧动态目录失效。模型不可用时提示修复，不自动换模型；停用连接也不能退回环境凭据继续调用。

全局默认只影响新会话；会话切换模型须无活动任务、后台压缩和待处理队列。手动修改连接或授权须等待所有使用它的任务结束，保留队列先清空再修复连接。同一授权的自动令牌刷新正常进行，不算切换连接。

### 全局设置与高级参数

设置只保留三页：模型连接、常用与默认模型、基础配置。内容最大 1040px 居中；左边目录，右边表单，点击目录定位对应分组。常用与默认模型分“常用与默认”“已配置模型”；基础配置按命令、并发、环境、请求重试、压缩、网络、图片、编码工具、异常恢复分组。不按单个项目设置。

模型目录显示源码真实名称、支持的思考档、上下文容量和最大输出。每个模型可降低上下文使用上限，默认沿用目录；不把上下文容量当成实际已用 token。提示“修改上下文仅新建会话生效”。新分支算新会话；同会话新复核轮不算。已有会话刷新、重启后仍用原参数。

必要参数进入高级配置：连接的超时、内部重试、服务端等待上限、缓存与适用的传输方式；模型的输出上限、温度、思考预算与压缩覆盖；全局的异常重试、自动压缩、代理、图片处理、编码 Code Mode 和异常恢复。只显示底层实际支持项，详细字段和生效规则以功能清单为准。

连接表单不常驻展示占用会话。改上下文默认值可直接保存；改密钥、地址、授权或停用连接仍须等使用者空闲，失败时就地说明。保存与测试分开，保存成功不表示模型已验证。

移除“审查默认限额”目录和三个输入项。复核几轮由用户在对话里决定；后台仍有限制无限执行的预算，耗尽后留草稿，不自动开下一轮。它与网络重试、自动审批预算是三回事。

右栏不显示成果标签；旧审查结论及下载入口从原消息查看。文件标签隐藏滚动条，鼠标滚轮/触控板可横向滚动，键盘选中的标签自动露出。失效资源页签回到文件；不删除回复或文件标签。

本轮新增 T56—T59，验收 A57—A60；不改产品代码，也不把原型的内存保存当成产品持久化。

### 本轮补齐的交互

- 模型目录使用当前 pi-ai 的真实名称，不用 demo 型号。只展示模型名称，内部保留厂商与模型 ID；思考档随型号变化，不固定为两档。无思考能力禁用，未知能力说明原因，不猜档位。
- 左上图标收起为 60px 窄栏，保留项目简称、新建、智能体、设置和主题。悬停项目弹出会话列表，第一项是新建会话；支持键盘，移入菜单不关闭。展开恢复原宽度与智能体区高度，刷新保留。
- 已有对话输入区右侧也能选智能体、模型和思考档。切智能体创建同项目的新会话分支，复制可见历史背景与未发送草稿，原会话不变。会话右键顺序为重命名、新会话分支、删除；手动分支沿用原智能体。分支先准备，不自动执行。
- 分支显示来源及可折叠历史背景，保留原作者；新分支有独立身份、队列、预算和执行，不复制工具回执、批准决定或材料快照。审查分支进入普通对话，背景结论只作参考；在原会话继续复核则不创建分支。
- 输入区左下“＋”向上打开材料菜单，选择当前项目文件/文件夹；Skill 只做禁用占位。已选材料标签放在输入框外上方，左对齐、可换行、可移除；没有材料时不占位。各类会话及新会话统一，草稿、刷新和分支保留引用，换项目只恢复目标项目自己的草稿和材料，无草稿才为空；原项目草稿保留。
- 审查消息和输入区统一最大 1100px，居中；窄分栏随可用宽度收缩。智能体/模型/思考档在输入框右下；底部显示三组统计和执行状态。

### 普通审查对话、快速定位和统计

编码和审查共用消息列表、队列、输入区和快速定位。审查不显示轮次切换、准备表单、固定步骤条或“新一轮复核”按钮；需要复核直接发送。审查正文和输入区最大 1100px 居中，模型选择靠右，材料标签在框外上方。

两类会话都按已保存用户消息建立定位刻度，按稳定 entryId 恢复。统计汇总当前会话；“轮”只指已进入历史的用户消息数量，不是审查流程。查看旧消息不切换统计范围；分支背景不重复计数。未知显示“—”，上下文标估算。

T52 统一会话映射和历史服务，T53 接消息定位与恢复，T54/T55 接统计。T26/T27 汇总验收后由 T38/T28 收口；A53—A56 验连续对话、定位和统计。

### 默认排队与立即插入

- 普通队列按发送顺序处理；编辑只改这一条的文字，不改位置、不覆盖输入框草稿和已附材料。空内容不能保存，取消不修改；被消费或版本已变时提示并刷新。
- “立即插入”把该条改为等待工具轮结束后加入，不打断当前回答、工具或命令，不停止再重开任务。无工具而直接结束时进入下一段；最终边界可能同时带入一条普通排队消息，按 Durable 规则处理，不承诺独占下一轮。
- 插入后显示待送达；真正加入对话才显示已送达。收尾中可排队但不能立即插入；断线、停止中、恢复中或结果待核对时只保留草稿。停止清掉未消费队列和待插入项；失败保留普通队列，取消未送达的插入项，已加入对话的消息保留。
- 编辑、撤回、插入都带原条目 ID、版本和独立操作请求 ID。刷新只查服务端队列与操作结果，不自动重发；分支不继承来源队列。审查也使用这些操作；带新材料的输入必须先准备好对应快照，才交给模型，不能覆盖正在使用的证据。
- 统计居中范围是左项目栏右侧的整个工作台底栏，包含右资源栏宽度，不跟着窄会话区走。状态靠右；窄窗口放不下时分行，统计仍居中，状态独占另一行，不遮挡输入和停止。

### 对话与恢复约束

分支先固定来源会话和最后一条已保存消息，只复制用户/助手可见文字作为背景。来源的后续消息、工具结果、队列、批准决定和审查证据不自动继承。重试沿用原 requestId 和截止点。

审查证据按提交/执行保存不可变来源；新消息可提出新要求，旧记录不覆盖。查看、定位、刷新和下载均不提交任务。迟到回执只能更新所属会话及操作，不覆盖后来编辑的草稿或拉回旧页面。

原型只证明演示交互。真实审批、快照、模型回执、分页、版本装配与服务重启仍按产品任务验证。

### 工具审批进入 1.0

用户已确认本轮变更：从“不做工具审批”改为实现三种模式。仅涉及单用户操作审批，不扩展账号和角色。

| 模式 | 行为 |
| --- | --- |
| 手动审批 | 项目范围内普通只读直接运行；写入、删除、命令和有外部副作用的操作先展示具体操作，用户同意才执行 |
| 自动审批（默认） | 普通只读直接运行；其余交给单独的审批模型检查。明确允许才放行；无法判断、输出无效、连接失败或超限转人工，不自动放行 |
| 完全访问 | 跳过逐项审批，但仍遵守智能体身份、工具范围、停止、资源占用和恢复规则；不是系统沙箱或无限权限 |

审批入口在输入区左下“＋”旁。待批卡片展示目标、参数、原因与同意/拒绝；批准仅对当前这一次具体调用有效。停止、超时、参数变化或任务失效后，旧批准不能继续用。刷新/重启恢复待批，不重复执行已批准的操作。自动审批使用模型会产生用量，单独记录；它不是 lg-examine 的验收报告。

实现细节及默认限额见功能清单；真实审批是新增后台能力，不以原型选项保存冒充完成。

## 8 1.0 不做什么

- 多用户、平台账号登录、角色权限、组织租户。厂商模型授权在 1.0 内。
- 桌面安装包、手机应用和手机专用界面。
- 通用工作流设计器、自动派单、自动整改和循环互审。两个内置智能体及用户手动审查、复核属于本版。
- 插件市场、完整知识库、商业计费系统。

## 10 验收标准

共 61 组详细用例，以 [验收用例](../1.0/03-验收用例.md)为准。A38—A42 验布局、搜索、分栏和下拉；A43—A46 验页内首发、右键管理、主题和模型名称。原型记录只能证明样例交互，不能证明真实搜索或持久运行完成。

1. Web 覆盖全部 42 个接入项；可同时配置多家、选择多个常用模型和默认模型，重启后仍在，并能打开本机项目发起任务。
2. 智能体能读取项目规则、定位代码、修改文件并执行指定检查。
3. Web 能显示真实文件差异、命令输出和退出码，不能把失败显示成成功。
4. 刷新或关闭浏览器后，五处尺寸、当前项目/会话、文件标签及显隐、搜索条件和草稿保留；服务端任务继续，重新打开读取最新状态，不重复提交。设置页也能恢复并返回原位置。
5. 重启服务后，会话和已保存记录仍在，可恢复的任务能继续。
6. 写文件或命令中断后，不因恢复而盲目重复执行。
7. 停止任务能结束后续执行，已经发生的文件修改如实保留和展示。
8. 项目与智能体独立；同项目编码和快照审查可同时运行，停止一个不影响另一个。同一可写目录的冲突被阻止，等待用户补充不占执行名额。
9. API Key、厂商授权及专用配置都有用例；批量部分失败不丢其他配置，凭据不回显，保存不自动调用模型。
10. 自动化测试隔离模型与认证网络；42 项界面/配置覆盖和真实调用验证分开记录，未实连的厂商不能写成已验证。
11. lg-examine 可单独审查文本，也可引用已结束的编码任务；身份、模型、工具和历史与编码智能体分开。
12. 审查回复可追溯要求、材料和证据；缺标准、证据不足、关键疑点未核实不能判通过。停止与完成竞态不伪报成功，后台未结束不能显示任务已完成。
13. 整改后直接在原会话发送，底层会话不变，原问题及新增问题可追踪；刷新和备份恢复不丢证据，不重复提交或执行效果不明的检查，排队与插入不能重置执行预算。
14. 真实模型用有预期答案的代码、文本、干净交付、证据不足和整改回归样本验收，人工核对漏报与误报。
15. 新会话首次发送不重复创建；改名刷新保留，删除不影响磁盘文件或证据链；忙时和未知状态不能删。主题刷新保留，同名模型显示精简但实际调用连接准确。

逐项操作和通过条件见 [验收用例](../1.0/03-验收用例.md)。

**1.0 的交付物：本地部署、单用户、Web 优先的平台，内置能持久运行的 lg-codeing-agent 和 lg-examine。**

## 11 2.0 智能体工作室与 1.0 预留

每个内置、自建智能体都有自己的工作室，包括“智能体创造智能体”。全部继续使用 `pi-durable`；项目不复制智能体，多个项目可以使用同一定义。详细方案见 [创造智能体技术分析](./创造智能体技术分析.md)。

### 入口与八个区域

2.0 点击左下智能体卡片打开其工作室。采用已选 B 版：保留左侧导航，工作室内容最大 1200px 居中，顶部身份卡片，下方八区横向页签；基础信息页左侧编辑身份，右侧展示能力与改进，底部列最近运行。暂隐藏右侧项目资源栏；返回恢复原工作位置。窄处上下排列，明暗主题跟随工作台。顶部放头像、名称、简介、来源、版本，以及“开始会话”“保存修改”。会话中的智能体下拉仍按现有分支规则工作。

| 区域 | 内容 |
| --- | --- |
| 基础信息 | 名称、头像、简介、职责和适用任务 |
| 灵魂 | 智能体个性、语气、判断原则和工作习惯；不改变工具和审批边界 |
| Skills | 分类页签、技能卡片、选择与上传 Skill 包；工具卡明确标注“工具能力” |
| MCP | 单独管理已登记 MCP 能力引用和启用项；连接凭据全局管理 |
| 记忆 | 可追溯、可纠正的智能体通用经验 |
| 知识库 | 该智能体通用参考资料及来源版本 |
| 自进化 | 长期运行发现的问题、修改建议、验证与应用记录 |
| 运行轨迹 | 时间、项目、任务摘要、状态、打开原会话；展开看关键动作与结果 |

不设“模型配置与运行”区，模型连接、默认参数和运行参数统一用全局设置。会话仍可选全局已配置的模型。没有“保存草稿”或配置发布流程；保存校验通过就生成新版本，提示“修改已保存，仅对新会话生效”。未保存表单离开时可保存或放弃，不承诺刷新恢复。原有消息草稿、审查输入材料仍按 1.0 规则保留。

### 智能体配置与项目文件

- 智能体通用：人设、规则、技能、能力清单，以及明确可共享的记忆和知识。
- 项目专属：规则、记忆和资料留在项目文件中；执行服务仍核验当前项目工作目录和资源范围。
- 工作室不建立“智能体 + 项目”的配置、记忆、知识或改进分层，也不提供项目选择器。
- 会话与执行：上下文、队列、材料、审批、统计和执行记录继续独立。

项目专属记忆和规则由用户按需在项目根目录维护文件，不在工作室配置或自动汇入智能体通用资料。旧 coding-agent 能加载 AGENTS.md，但还会读取全局目录及项目上级目录；Durable 不会自动接入这套加载器。1.0 由 T08 适配，只自动读取当前项目根目录到目标目录之间的 AGENTS.md；说明和记忆文件须显式列入材料。AGENT.md 不作为自动加载文件名。MCP 连接和密钥全局管理，智能体只选择已登记能力；实际调用按当前任务核验资源范围，roots 或提示词不能代替执行校验。“开始会话”直接进入原新会话页，在那里选择项目，首次发送才创建。

### 只影响新会话

打开新会话输入页尚不绑定版本；首次发送、服务端受理创建意图时固定智能体配置、技能和实现版本，以及适用的长期记忆、知识版本。旧会话继续发送、排队、停止后继续、刷新或重启，都沿用原绑定。同一审查会话的后续复核也不升级配置；显式新会话或新分支才取得当时有效版本，创建重试保持首次固定的版本。

所有引用组成完整版本清单，依赖和索引就绪才切换新会话默认版本。修改或移除当前资料不破坏旧会话引用；旧实现必须保留并核对，不能只保存版本号却装配最新工具。

此规则不禁止用户提交新材料，也不冻结当前项目文件和目录规则；审查仍按实际提交/执行保存材料快照。全局设置继续遵守原有分类生效规则，不能借工作室绕过。工作室取消某项能力属于配置修改，只影响新会话；平台实际禁用的能力、凭据失效和停止控制仍在后续准入检查，不能由旧绑定绕过，也不宣称能撤回已发生的动作。缺旧版本时显示受阻，不悄悄用新版恢复。

### 自进化与简化记录

自进化从重复纠正、失败、审查遗漏、过时知识和缺失能力发现改进点，再归并证据、判断是否通用、提出修改、验证和应用。项目专属要求由用户维护项目文件，不建立项目改进配置；通用建议须去掉项目私有内容，经确认生成该智能体的新版本，仅新会话生效。完全自动应用另定，不自动改写项目文件。

自动发现只能处理有明确来源的任务记录，不能把全部项目对话汇入通用记忆。提案保留来源 ID 和必要摘要；证据失效时停止应用。普通规则、技能步骤和知识可形成新版本；新工具或代码须先实现、检查、登记，不直接加载模型生成的程序。新版本只供新会话使用，不改正在运行的智能体。创建、编码、审查可协助改进，但不无限自动互调。

运行轨迹使用原有执行记录，按执行时绑定的稳定 agentId 归集，不能按可改名称或后来选择的智能体归集；复杂内容回原会话查看；不另做调用链面板，不重复统计关联任务。底层恢复记录完整保留，缺数据标未知。

### 1.0 留什么

1.0 预留稳定 agentId、定义版本、显式能力清单、会话绑定、项目范围校验、通用目录入口和备份恢复检查。不提前做工作室编辑器、知识库或自进化服务，不新增第三个正式内置智能体。R01—R06 已落实为 T02 等基础任务及新增 T60 收口，A61 验证；T26/T27 等 T60，T28 最后交付。V01—V06 仍是 2.0 排期。


### B 版原型与交付范围

主原型左下列表、方块及收起后的智能体头像都打开该智能体的 B 版工作室，完整目录也使用同一入口。“开始会话”再进入现有页内新会话，不复用正在运行的会话。会话输入区的智能体选择仍创建分支。

主原型标注“2.0 预览”，只合并设计和演示交互，不代表把完整工作室提前加入 1.0。1.0 正式功能仍是两个内置智能体与通用预留；未开放工作室时卡片直达新会话。不要用预览验收代替 T60 的服务端版本绑定。

产品工作室位置按服务数据实例隔离；已保存配置由服务端重读，浏览器只保存 ID、页签和返回位置。保存结果未知时查原 requestId，不重新保存或生成版本。已保存的工作室页签、智能体和配置版本可刷新恢复，不保存项目范围；旧页面缓存的范围字段忽略并清除。运行轨迹汇总当前智能体的记录、标明项目来源，打开前再核对 ID 和归属；项目删除不改变工作室配置。损坏配置不能被内存旧值覆盖，保存失败保留输入。未保存配置切页签不丢，离开可取消或放弃；刷新不自动保存。返回原工作台仍保留项目、会话、文件和草稿。记忆、知识和 MCP 未接入时明确标注。原型仅保存演示定义，真实新旧会话装配按 T60/A61 验证。

### 灵魂、Skills、MCP 的交互与边界

- “灵魂”突出个性、语气、判断原则和工作习惯，保留原规则内容；改名称不重置已保存定义。项目规则仍由项目文件维护。
- Skills 独立显示“全部、开发、审查、通用、已上传”分类页签和数量；卡片展示名称、简介、类别、来源及选择状态，空分类显示空态。取消顶部技能指引占位行和长条工具列表。现有工具卡标“工具能力”，不把工具开关冒充已安装技能。
- 右上提供“上传 Skill 包”。原型选择 ZIP 后只加入待保存配置，记录文件名、大小和选择状态；可移除，重复文件名提示。它不读取、解压、安装或运行包，保存成功也不代表技能可执行。
- 正式上传是 2.0：服务端校验包、SKILL.md、内容版本和依赖，成功才可保存进定义；原型的文件名检查不能代替内容校验。上传不授予工具、MCP 或项目访问能力，脚本也不自动执行。
- MCP 单独一页，只引用已登记连接及能力；全局管理凭据。工具依赖缺失给出原因，不因勾选就显示已连接。审查仍不能获得源项目写入、任意 Shell 或编码 Code Mode。
- 页签按稳定 ID 保存，不按数组位置恢复；拆分后旧“人设与规则”位置回灵魂，旧能力页回 Skills，记忆/知识库/自进化/轨迹按原含义恢复，失效分类回全部。
- 分类、工作室智能体、页签和返回位置可恢复；已保存技能来自该智能体定义版本。未保存上传不自动落盘，刷新不重新上传、安装、应用或启动任务。定义保存后只影响新会话和显式新分支，旧会话、队列和同会话继续审查沿用原版本。

完整工作室和上传后端仍属 2.0；1.0 的 T60/A61 只预留分别可识别的技能内容版本、MCP 能力引用及工具实现清单，不交付上传安装服务。
