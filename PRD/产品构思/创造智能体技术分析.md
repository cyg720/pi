# 创造智能体技术分析

更新：2026-11-03。记录 2.0 的智能体工作室、在线创建和自进化，以及 1.0 的最小技术预留。完整产品功能尚未实现；主原型仅演示 B 版，1.0 的预留由 T60/A61 收口。

配套：[平台方案](./AGENT-EXTENSION-PLAN.md)、[技术实施说明](./TECHNICAL-REVIEW.md)、[1.0 开发任务](../1.0/02-开发任务.md)。本文替换此前“配置草稿 → 试用 → 发布”的方案。

## 1 已确定的方向

- 1.0 先交付 `lg-codeing-agent`、`lg-examine`，两者直接基于 `pi-durable`。
- 2.0 支持用户通过本地部署的 Web 创建各行业专业智能体，新增内置“智能体创造智能体”。技术 ID 暂建议 `lg-agent-creator`，未定名。
- 每个内置、自建、负责创建的智能体都有自己的工作室，运行都使用 `pi-durable`；不必为每个自建智能体新建代码包。
- 工作室不设模型配置与运行参数区，统一使用全局设置。会话中仍可从已配置模型中选择，不另建每智能体模型默认值或连接。
- 工作室只有“保存修改”，没有“保存草稿”。修改校验成功后生成配置版本，仅新会话生效。
- 自进化由长期运行中发现的问题驱动；运行轨迹只保留必要记录。

## 2 工作室入口与八个区域

2.0 点击左下智能体卡片或目录项，打开该智能体工作室。保留左侧全局导航，隐藏项目资源栏；离开后恢复原项目、会话和文件查看位置。会话里的智能体下拉仍负责选择或创建分支，不改成工作室入口。

顶部显示头像、名称、简介、内置/自建标记和配置版本，放“开始会话”“保存修改”。采用已选 B 版：身份卡片下方八区横向页签，内容最大 1200px 居中；基础页左侧身份编辑，右侧能力与改进，底部最近运行。窄处上下排列。“开始会话”直接进入现有新会话页，在该页选择项目，首次发送才创建运行会话。

编辑时可以有未保存内容，但不建立持久配置草稿。离开时提示保存或放弃；刷新未保存表单不承诺恢复。保存失败保留本页输入，成功提示“修改已保存，仅对新会话生效”。已保存配置及工作室位置可恢复，刷新不重复保存或启动任务。

| 区域 | 做什么 | 范围 |
| --- | --- | --- |
| 基础信息 | 头像、名称、简介、专业职责、适用任务；查看稳定 ID 和配置版本 | 智能体通用 |
| 灵魂 | 智能体个性、语气、判断原则和工作习惯；不改变工具和审批边界 | 智能体通用；项目规则留在项目文件 |
| Skills | 分类页签、技能卡片、选择与上传 Skill 包；工具卡明确标注“工具能力” | 智能体通用；执行检查当前项目范围 |
| MCP | 单独管理已登记 MCP 能力引用和启用项；连接凭据全局管理 | 智能体通用；执行检查当前项目范围 |
| 记忆 | 查看、纠正、移除长期偏好和经验，保留来源 | 仅管理智能体通用经验，项目记忆留在项目文件 |
| 知识库 | 管理长期参考资料及来源版本 | 仅管理智能体通用资料，项目专属资料留在项目 |
| 自进化 | 展示发现的问题、改进建议、验证结果与应用情况 | 确认通用性后生成智能体新版本，不配置项目范围 |
| 运行轨迹 | 时间、项目、任务摘要、状态和“打开会话” | 汇总该智能体参与的记录，保留项目来源 |

内置智能体也能修改开放的配置项，但其固定执行边界由程序保障。例如审查必须保留取材、证据和报告规则，不能通过改人设获得编码写入能力。工作室不提供在线修改平台源码的入口。

## 3 工作室不配置项目，执行仍按项目隔离

例如“采购审查助手”同时服务甲、乙两个项目：通用审查步骤可以共用；甲项目的报价、供应商空间和判断经验，不能自动带进乙项目。同一个智能体不必复制成两份，同项目也能使用多个智能体。

| 层级 | 保存内容 | 使用规则 |
| --- | --- | --- |
| 平台全局 | 模型连接、运行参数、已登记工具实现、MCP 连接及凭据 | 工作室只引用能力，不复制密钥或单独配置模型 |
| 智能体 | 人设、通用规则、技能、允许能力、明确共享的记忆和知识 | 跨项目复用，不能夹带某项目私有资料 |
| 项目文件 | 根目录记忆/规则、项目资料和工作目录 | 用户按需维护；只由当前项目任务按允许范围读取 |
| 会话与执行 | 消息、材料、队列、审批和运行状态 | 不因共用智能体而合并或互相继承 |

工作室完全移除项目范围选择及项目级配置，不建立“智能体 + 项目”的记忆、知识或改进库。项目专属记忆和规则由用户按需在项目根目录维护文件，不在工作室配置或自动汇入智能体通用资料。旧 coding-agent 能加载 AGENTS.md，但还会读取全局目录及项目上级目录；Durable 不会自动接入这套加载器。1.0 由 T08 适配，只自动读取当前项目根目录到目标目录之间的 AGENTS.md；说明和记忆文件须显式列入材料。AGENT.md 不作为自动加载文件名。运行轨迹仍标明项目来源；汇总简要记录不等于把全部项目资料传给智能体。新会话在原创建页选择项目，执行服务继续按 projectId 校验目录、材料和资源。

通用定义不写死本机项目绝对路径。MCP 连接全局管理，智能体选择可用工具；调用时根据当前任务校验目录或业务资源，不在工作室增加项目绑定表单。MCP 的 roots 或提示词不是访问隔离措施。

T08 以登记项目的真实根路径为边界，校验规则文件的真实目标，不读项目上级、旧 CLI 全局目录或越界链接。项目规则不是智能体人设；自定义记忆文件按普通材料显式读取，不自动写回。审查采用的规则/记忆先列入本次提交的取材清单再冻结，恢复不回源目录补读；内容不能改变用户标准和宿主固定边界。

## 4 保存后什么时候生效

保存生成不可变版本，并更新“新会话使用的版本”。规则、技能、实现和长期资料/索引组成完整版本清单；依赖全部准备好才切换当前指向，失败保留旧版，不能分别取各库最新值拼装。版本是后台记录，不增加发布按钮或发布审批流程。

| 场景 | 使用规则 |
| --- | --- |
| 打开新会话输入页，还未发送 | 尚未建立绑定；首次创建时取得并固定有效版本，创建前发现配置已变则提示更新 |
| 新建会话、显式新建分支 | 取得当时有效的智能体配置及适用的技能、记忆、知识版本；分支不复制原执行和审批决定 |
| 旧会话继续发送、执行排队消息 | 沿用原绑定，不自动读取工作室最新配置 |
| 旧会话停止后继续、刷新、服务重启 | 仍用原版本；缺版本或实现则受阻，不偷偷换新版 |
| 同一审查会话继续复核 | 继续使用原定义及原 Durable 会话；新要求和材料按消息/执行留痕，不新建审查轮次 |
| 自进化产生新规则、记忆或知识 | 应用后只进入新会话；旧会话需要使用新版时显式新建分支 |

绑定保存版本引用和内容指纹，不要求把整库资料塞进提示词。运行时只能检索已绑定的知识版本；更新索引不能让旧会话读到新内容。从当前记忆/知识列表移除，只影响新版本；历史会话引用的版本仍保留。历史版本确实不可用时说明受阻，不回退到最新版。

“仅新会话生效”针对工作室管理的配置与长期资料，不冻结用户主动提交的任务材料、当前项目文件或目录规则。编码仍可读当前文件，审查仍冻结已选材料；当前任务读取了什么，按原流程记录来源。

全局配置仍按 1.0 的分类生效规则处理：模型默认值在创建时固定，全局引擎及连接参数按既定空闲条件切换。会话显式换模型仍走原校验，不是工作室修改。工作室取消能力属于保存新配置，只影响新会话。平台实际禁用、凭据失效、停止执行仍参与后续准入，旧绑定不能绕过；已发出的动作走停止或待核对，不声称能撤回。1.0 不增加单独的能力撤销配置模块。

## 5 自进化怎么做

例如某智能体连续几次漏查日期，用户反复补充同一要求。系统将这些记录归为一个改进点，判断是某项目要求还是通用问题，提出“增加日期核验步骤”，验证后应用新版本。旧会话保持原样。

流程：**发现问题 → 归并证据 → 判断范围 → 提出修改 → 验证 → 确认应用 → 观察新会话效果**。

- 来源包括用户纠正、重复失败、审查发现的遗漏、过时知识和缺失能力；来源按项目、页面会话、执行或消息 ID 定位，只抽取必要证据，不能把全部项目对话汇入通用记忆；只有猜测时标为待验证，不能当事实写入记忆。
- 改进涉及规则、技能步骤、记忆纠错、知识更新或新工具需求。项目专属要求留在项目文件中，由用户维护；通用提案先确认适用性并去掉私有内容，不自动修改项目文件。
- 配置变更先校验并用针对性样例验证；新增可执行工具、MCP 适配或代码要先实现、检查、登记，不能把生成代码直接加载进运行服务。
- 创建助手整理建议；需要开发时可由用户安排编码智能体，审查智能体独立复核。它们使用独立执行记录，不无限互相调用。
- 首版方案为自动发现、整理和提出建议，用户确认后应用。完全自动应用的条件尚未确定，不默认开放；自动审批工具也不等于批准修改智能体。
- 每条只记录问题、来源引用、通用性说明、拟改内容、验证结果、状态及应用版本。应用前重查证据；来源不可核对则停止应用，不凭旧摘要批准。拒绝或应用失败不影响当前可用版本。

自进化不在每次对话后重写人设，也不常驻空转请求模型。触发频率和用量上限后续细化；执行复用全局调度与审批。验证任务是流程中的手段，不新增“试用与改进”区域。

## 6 运行轨迹保持简单

列表只显示时间、项目、任务摘要、状态和原会话入口；展开可看开始/结束时间、所用配置版本、关键动作、结果或失败原因。完整消息、工具输出、审批和报告回原会话查看，不复制成另一套日志。

项目执行记录归属至少包含执行时绑定的 agentId、projectId、页面会话和实际执行/消息，不按名称或当前下拉选择归集。后续平台创作/验证记录明确标为平台工作区，不伪造用户项目或混入项目统计。自进化验证与创建助手执行分别记账；关联显示不重复累计 token。缺统计显示未知，不能填 0。页面刷新重读记录，不触发重跑。

不增加复杂流程图或调用链面板。底层 Durable 的恢复日志和副作用核对记录仍保留，页面简化不能删掉恢复依据。

核对本地基线：`de21da3f8dc94578db1d7ce283a7c47e7abf61c5`。结论：**可以用现有底座扩展，但工作室、版本仓库、跨会话记忆、知识库和自进化需要平台实现。** 不能把上游示例当完整功能。

| [defineExtension](../../packages/durable/src/harness/define.ts)是类型辅助；[文档系统](../../packages/durable/src/documents.ts)提供持久状态基础 | 定义校验、保存去重、项目/智能体范围和版本仓库，不假设原生有 agent/project 文档范围 |

| [MCP 包](../../packages/mcp/README.md)提供连接与调用能力 | Durable 工具适配、凭据引用、项目资源检查；不是安装后自动获得隔离 |

同一项目继续只有一个 Harness；不为每个智能体重复打开项目库。内置与自建定义走统一解析入口。自建智能体先采用“配置 + 已登记能力”，不开放网页上传任意脚本直接运行。

## 8 创建助手与保存实现

2.0 拟新增 `packages/lg-agent-creator`。它自己也有工作室，使用 Durable；与编码、审查独立，不靠修改平台源码创建普通专业智能体。

用户说明职责、材料、步骤和输出要求，助手生成结构化建议，在工作室表单中供用户调整。宿主提供读取能力目录、校验、关联验证结果和提出修改等受限能力；这些是拟建能力，不是现成 API。用户“保存修改”后才成为有效配置，不接受模型自称已获确认。

不建立配置草稿业务流程。创建对话和自进化建议可持久保存供追溯，但它们不是可执行定义，也不自动覆盖有效版本。第一次保存生成稳定 agentId 和首个版本；保存本身不启动任务。

保存带请求 ID、预期版本和内容指纹；服务端校验全部引用就绪后，原子保存完整版本清单、当前指向和回执。旧页面冲突先提示，响应丢失保留原请求查询引用；刷新查回执，不自动保存或重复生成版本。工作室位置按服务数据实例隔离，已保存定义从服务端重读，读取失败不当成删除或空配置。内置的固定规则不可被编辑字段覆盖。

全局定义库和项目库不是同一事务。创建会话先固定目标版本和请求意图，再在项目库保存绑定与创建回执；失败重试仍用原版本。保留被会话引用的实现、技能和知识版本，恢复时缺失则受阻。

2.0 的 V04 需新增服务管理的创作/验证执行位置，建议使用 dataRoot 内独立工作区与持久库，单库单宿主；不借当前打开的项目，不要求先建一个用户项目。进入用户项目验证时，显式指定来源并走该项目准入，不能靠工作室选择器传递隐含权限。平台工作区是拟建业务概念，不是 Durable 新的文档 scope；1.0 仍只允许有 projectId 的业务执行。

验证会话与创建助手分开，使用各自的 ID、审批、资源占用和统计；停止一个不默默停止另一个。若提供一起停止，需逐项记录结果。自进化应用前再核对基准版本；用户已手改时重新比较，不覆盖新修改。

## 9 1.0 最小预留

完整工作室、用户创建、创建助手、长期记忆/知识管理和自进化在 2.0 实现。1.0 不新增工作室编辑排期；只落实两个内置智能体已经需要的通用机制。主原型先合并 B 版预览，卡片进入工作室再开始会话；1.0 正式版未开放工作室时保留直接新建。最小预留在 PRD/1.0 的 T60/A61 收口，不把预览当产品实现。

下列 R 编号是设计映射，已通过 T60/A61 汇入 1.0；不是产品已完成记录。

| R01 定义契约 | T02；contracts 的 agents | 稳定 ID、来源、定义版本、执行方式、能力与指纹；未知定义/版本拒绝，不按显示名路由 |
| R02 统一装配 | T07/T29；server 的 agent-registry、两个智能体 definition、runtime | 显式选择能力，内置与未来自建共用入口；第三个测试定义能装配，审查范围不扩大 |
| R03 会话绑定 | T11/T46/T52/T56；sessions、documents、分支与配置快照 | 原定义固定；新分支固定目标版本，复核沿用旧绑定；刷新、重试和恢复不取最新版 |
| R04 范围检查 | T12/T14/T29/T50/T59；准入、工具、环境与恢复 | projectId/agentId/会话归属由服务端检查；直接、嵌套、动态加载和恢复不越界，完全访问不绕过 |

必须补测：

- 保存 v2 后，旧会话、排队消息、停后继续和同会话复核均保持 v1；显式新会话/分支使用 v2。创建中途更新至 v3，原请求重试仍用已固定版本。
- 配置、技能实现、记忆、知识分别更新，旧会话仍按原绑定读取；主动提交新材料不被误拦，审查材料仍按实际提交/执行固定来源。
- 两个项目共用同一智能体及 MCP 连接，项目记忆、资料、资源、审批和记录不混用；仅改名称或客户端 projectId 不能越界。
- 保存前后退出、响应丢失、并发编辑、版本实现缺失、备份恢复分别验证；未保存表单不得变成有效配置，刷新不自动保存或发送。
- 自进化错误建议可拒绝；验证失败不应用。用户确认后重复响应只应用一次，基准版本变化不能覆盖，来源删除或证据不足要显示原因。
- 工作室取消能力后，旧会话沿用原清单；平台实际禁用该能力后，旧绑定的后续调用也被拒绝。完全访问、技能文本、MCP 返回和模型输出均不能放宽宿主边界。
- 记忆/知识索引准备失败不切当前版本；从新版移除条目不破坏旧引用。两个版本在同一宿主并存，重启后实际工具仍对应各自版本。
- 零项目下创建助手和验证使用独立工作区；失败、取消、重启不借用户项目或重复应用。平台与项目记录分别统计。
- 服务实例切换、保存结果未知、断网和记录删除分别恢复；不拿浏览器旧定义覆盖服务端，不重放保存。
- 工作室八区均无项目配置，保存反馈、开始会话和返回位置一致；轨迹保持简洁，统计未知如实显示，原会话及 Durable 恢复记录完整。

后续再定：创建助手正式 ID、首批能力与知识检索实现、自进化触发频率和自动应用范围。上述待定项不阻碍 1.0 的最小预留。

### 灵魂、Skills、MCP 的交互与边界

- “灵魂”突出个性、语气、判断原则和工作习惯，保留原规则内容；改名称不重置已保存定义。项目规则仍由项目文件维护。
- Skills 独立显示“全部、开发、审查、通用、已上传”分类页签和数量；卡片展示名称、简介、类别、来源及选择状态，空分类显示空态。取消顶部技能指引占位行和长条工具列表。现有工具卡标“工具能力”，不把工具开关冒充已安装技能。
- 右上提供“上传 Skill 包”。原型选择 ZIP 后只加入待保存配置，记录文件名、大小和选择状态；可移除，重复文件名提示。它不读取、解压、安装或运行包，保存成功也不代表技能可执行。
- 正式上传是 2.0：服务端校验包、SKILL.md、内容版本和依赖，成功才可保存进定义；原型的文件名检查不能代替内容校验。上传不授予工具、MCP 或项目访问能力，脚本也不自动执行。
- MCP 单独一页，只引用已登记连接及能力；全局管理凭据。工具依赖缺失给出原因，不因勾选就显示已连接。审查仍不能获得源项目写入、任意 Shell 或编码 Code Mode。
- 页签按稳定 ID 保存，不按数组位置恢复；拆分后旧“人设与规则”位置回灵魂，旧能力页回 Skills，记忆/知识库/自进化/轨迹按原含义恢复，失效分类回全部。
- 分类、工作室智能体、页签和返回位置可恢复；已保存技能来自该智能体定义版本。未保存上传不自动落盘，刷新不重新上传、安装、应用或启动任务。定义保存后只影响新会话和显式新分支，旧会话、队列和同会话继续审查沿用原版本。

完整工作室和上传后端仍属 2.0；1.0 的 T60/A61 只预留分别可识别的技能内容版本、MCP 能力引用及工具实现清单，不交付上传安装服务。
