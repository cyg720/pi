## 1 技术路线

固定使用 `pi-durable`。新建独立包 `packages/lg-codeing-agent` 与 `packages/lg-examine`。前者复用编码工具、参考现有 coding-agent；后者独立实现验收、对抗审查和整改复核。编码智能体通过 T59 接入 Durable Code Mode，审查智能体不装配。

现有 coding-agent 使用 `pi-agent-core`，其运行管理关联 `AgentSession`、`SessionManager`、扩展事件和会话切换。直接替换底层会牵动这些接口。1.0 只做 Web，新建基于 Durable 的实现更集中。

两包不互相依赖，由本地服务注册，复用模型、存储与通信；不为独立身份另开进程或同项目第二个 Harness。本次只更新文档，两个包尚未实现。

项目和智能体定义独立：项目保存名称、目标、资料位置；平台登记专业智能体定义，会话记录 projectId + agentId。一个项目可有多个智能体并发，同一智能体可跨项目使用。用户先建项目再派任务，或先选智能体再选项目，均使用同一关联模型，不把智能体复制进项目。

## 4 运行过程

1. 服务端读取各厂商配置与独立凭据，创建模型集合并注册全部内置 provider；未配置时仍可启动并进入设置页。
2. 打开项目的 SQLite 存储，创建唯一 Harness。
3. 按智能体身份为会话选择指令、工具、模型与执行环境；审查读取材料快照，指定检查使用单独工作副本。
4. 用户发起任务，调用会话 `submit()`，保存返回的提交标识。
5. 服务端订阅 Durable 的视图或事件，转换为 Web 需要的数据。
6. 编码显示文件变化与检查结果；审查按标准、证据和逐项状态生成报告，不能把执行成功直接当作验收通过。
7. 重启时核对身份版本、工具、审查快照与未完成检查，再按公共恢复规则继续；回复缺项并等待用户时不持续调用模型。

当前可复用的接口包括 `Harness.open()`、`createRegistry()`、`defineExtension()`、`createConversation()`、会话的 `submit/configure/watch` 和 `harness.resume()`。两个智能体的每个新页面会话/显式分支均新建 ownerless 会话；同会话后续复核复用原会话，不用 `root()` 复用根会话；已有 root 不会因传入新 agent 而自动切换身份。

凭据只由服务端保存和使用。会话通过 Durable 的 `configure` 切换模型，须先检查活动任务、后台压缩和待处理队列；全局默认只影响新会话。

### 全部厂商与模型配置

从公开 `builtinProviders()` 取得当前 **43 个接入项**，用 `createModels`、`setProvider` 注册。页面展示全部项，包括未配置项、支持动态刷新的 Radius（当前也有静态目录）、地区/产品版本和源码中的 legacy 提示。静态 `getBuiltinProviders()` 或 JSON 文件数量不能代替工厂清单。完整名单见 [功能清单](../1.0/01-功能清单.md)。

| 模块 | 要补的能力 |
| --- | --- |
| contracts | 接入项、认证方式、专用字段、配置版本、脱敏状态、批量保存结果、授权交互格式 |
| server | 按 provider ID 保存多家连接和独立凭据，提供 CredentialStore/ModelsStore 本地适配，协调配置变更与授权流程 |
| runtime | 全部厂商注册、认证交互转换、目录刷新、指定模型测试、模型能力校验 |
| web | 厂商搜索与筛选、专用表单、授权过程、常用/默认模型、测试结果、启停和批量保存 |

首版每个 provider ID 一份生效连接，可使用多个模型；模型引用始终包含 provider ID + model ID。常用模型只是选择偏好，取消勾选不改变旧会话。两个智能体均使用聊天且支持工具调用的模型，独立选择但不强制不同；思考档按能力显示，不扩展图片生成等产品范围。

T20 将显示名称与引用分离：新会话、会话切换、默认选择仅显示模型名称，缺名称用完整 model ID，不拼厂商。选项键/保存/调用均用 provider ID + model ID，同名不合并，目录重排也不按名称重新匹配。当前原型已离线读取源码模型名称及思考档快照；产品仍须通过公开 Models 目录和当前连接取值，不按斜杠截取模型命名空间；厂商连接页继续显示厂商。

### 认证与专用参数

- 普通 Key 与 OAuth 按 provider 的实际 auth 能力显示，不能统一做成 Key 输入框。表单描述由平台补充，pi-ai 没有现成 Web 表单。
- OAuth 复用 Models 的 `login`、`logout` 和 `AuthInteraction`。页面承接文本、密码、选择、手动验证码、授权链接、设备码和进度；支持取消、超时和重新授权。login 会保存并返回 Credential，服务端必须截留凭据，不原样回传。
- Bedrock 接 Bearer Token、AWS Profile/凭据链和区域；Vertex 接 Key 或 ADC/服务账号路径、项目和地区；Azure 接资源名/地址、版本和部署映射；Cloudflare 接 Token、Account ID，Gateway 另加 Gateway ID。外部认证文件路径指服务端本机。
- 自定义地址只给适用项，复用公开 Provider 接口或对应工厂参数；不能假设所有工厂接受 baseUrl，也不能覆盖 OAuth 返回的专用地址。
- 默认凭据和目录仓在内存中，必须接本地适配；凭据 modify 按 provider 串行，避免刷新令牌与人工保存互相覆盖。连接与凭据按同一配置版本生效，批量逐项返回结果，失败项保留原生效配置。
- 环境认证必须显式选择并按 provider 注入；停用或清除后不得自动读其他环境凭据继续调用。logout 只删除保存凭据，不自动关闭环境认证。厂商授权不引入平台账号或角色权限；工具审批是另一项功能。

### 目录、验证与生效时机

目录复用 Models 的读取与 `refresh` 接口，静态目录直接读取，动态目录按 provider 能力刷新。失败保留旧目录并显示更新时间；账号或地址变化后清理旧动态目录。模型下架或连接失效时保留原引用并提示修复，不自动换模型。

`checkAuth` 只判断认证条件，不证明远端调用成功。保存配置不发生成请求；用户点击“测试所选模型”才调用指定模型，记录配置版本、时间和结果，页面先说明调用费用。配置修改后旧成功结果失效。

手动修改连接、重新授权或停用前，等待使用该连接的活动任务与后台压缩结束；有保留队列时先清空。检查到配置发布期间阻止该连接的新执行，同一 provider 只保留一个手动修改/授权流程。同一授权的自动令牌刷新照常进行并串行落盘。

上述步骤对应 T02—T04、T11、T17、T20；各任务的拟改文件与验收编号见 [开发任务](../1.0/02-开发任务.md)。

### 本轮配置的源码边界

字段清单与默认值统一见 [功能清单](../1.0/01-功能清单.md)。`packages/ai/src/types.ts` 有请求参数，目录模型有 contextWindow/maxTokens；`packages/coding-agent/src/core/settings-manager.ts` 及 `settings-defaults.ts` 说明 CLI 已有设置，但不会自动应用到新工作台。

`ConversationStreamOptions` 已提供 transport、timeoutMs、maxRetries、maxRetryDelayMs、cacheRetention、thinkingBudgets、websocketConnectTimeoutMs 等；temperature、maxTokens 仍不在该类型中。T57 只对缺失字段补公开 Models/Provider 请求包装，同时隔离连接和会话参数，连同压缩请求逐适配器验证；不能向 configure 塞未知字段或深层导入 CLI 设置管理器。

上下文覆盖必须真正进入 Durable 读取的模型容量及压缩计算，不能只改进度圆环。T57 先验证版本化 Models 包装：内部模型引用映射到“原 provider/model + 参数版本”，getModel 返回该版本有效容量，streamSimple 转回原模型路由并注入参数；持久保存映射，目录/UI/统计仍展示原引用。使用公开接口，不改 models.generated.ts。先用两个不同上限会话并发验证容量、路由、压缩、重启；做不到不能宣称配置生效，也不能改为每会话一个 Harness。

HarnessSettings 是全局动态读取，回调不接收 conversationId；models 工厂也不提供会话参数。全局重试/恢复/代理等按功能清单的空闲发布规则处理。连接请求参数也按该连接使用者空闲发布，再由模型包装按连接注入；不能把 Harness.stream 误当会话参数。按模型的压缩覆盖使用 AgentChange.compaction.modelOverrides，键映射到实际内部版本引用；会话模型覆盖优先于 Harness 模型覆盖，再到会话通用字段、Harness 通用策略，会话 enabled=false 可压过 Harness 模型覆盖。显式覆盖保留会话快照，未覆盖字段按全局空闲发布规则继承；不能写入原模型的共享条目影响旧会话。compaction 在 configure 中整体替换，null 清除、undefined 保持，平台先合成完整目标并校验。T56/T57 是新增适配工作，公开类型存在不等于完整接线已完成。

Code Mode 使用 Durable 公开 codemode 子路径；on/only 和 inlineBudget 是编码装配设置。T59 验证嵌套工具仍经 T50 审批，模型不能通过 Code Mode 取得审查未注册工具。图片处理只接编码环境的公开图片能力，不把 coding-agent 的设置对象当 Durable 配置。

移除审查默认限额表单，不移除 T33 的内部有限预算。模型重试按实际尝试记账；审查关闭 SDK 内部重试，避免漏计。自动审批的调用/等待预算保持独立。maxRetryDelayMs 超过服务端建议等待上限则报错，maxAgentDelayMs 用 min 截住外层指数等待，restartLimit 限制无进展重启，三者不能混成“重连间隔”。

设置三页及目录整体最大 1040px 居中；取消项目运行覆盖和单项目并发。连接页取消常驻占用提示，受阻保存给就地错误；上下文提示仅新建会话生效。旧设置路由和成果页签做定向回退，报告历史不删。产品配置服务端落盘，原型内存保存与重置不作为产品验收依据。

### 合并后的运行与订阅边界

`restart_limit` 会结束旧任务：生成记录 runFailure，工具记录错误结果，压缩记录 compactionFailure，其他任务 faulted；不再使用 retryTask。未知副作用的核对标记独立保留，全部收尾后用户用新 requestId 继续，不能把缺定义/版本的 blocked 与重启上限混为一类。

`Submission.wait()` 先于可能存在的 afterRun 收尾完成；waitForIdle 包含普通所属任务，后台压缩及外部进程/归档仍由平台另查。T12/T13/T44 在最终收尾前保持占用和忙时限制，只读查询不触发 resume。

`conversation.watch()` 是有界历史窗口和内置文档，默认最新 50 条、超过 100 条裁回 50 条。复用 ConversationTranscript 的 merge/loadEarlier/fillGap/resume，按 entryId 合并且用 before 识别早期历史，不把窗口裁剪当删除。Chord 的 WatchCall 使用 kind=value/failed，终止使用 WatchEnd.kind，文档退休看 retired。自有文档仍显式订阅；SSE 连接序号不是永久恢复游标。详见功能清单对应契约和 T18/T52—T54 的验收。

## 5 编码能力的补充工作

### 项目规则

编码会话读取当前项目根目录的 AGENTS.md，处理子目录前读取项目内适用的局部规则；说明和记忆文件显式选取。扫描不越过登记项目根，不带入旧 CLI 全局规则。保存实际来源、内容指纹与摘要；编码恢复识别规则变化，审查则只使用本次执行已冻结的规则材料。

这是智能体工作上下文；工具审批另由 T50 实现，不增加平台账号或角色服务。

### 搜索与命令

搜索封装成稳定工具，限制输出长度，明确报告命令缺失和执行错误。Windows 启动时检查 PowerShell 与所配置的 Bash，不能假定环境一定安装。

执行命令保留退出码、输出和超时信息；输出截断时给出完整日志位置。命令以本机服务账户运行，项目工作目录不是操作系统沙箱。

### 文件差异

edit 已能返回单次修改的 diff 和 patch。会话汇总还要处理 write 新建文件、命令修改文件和用户自行改动。

Git 项目同时展示工作区状态；任务开始记录已有改动，不能把用户原有修改都算到智能体名下。非 Git 项目以本次记录的文件前后内容生成差异，不自动创建 Git 仓库。

## 6 lg-examine 的实现

### 普通会话与独立身份

与编码一样，一个 workbenchSessionId 绑定一个 ownerless Durable conversationId，按 projectId 联合校验。首次发送复用 T11/T12 创建与提交；后续审查、补充和复核复用同一会话，不创建 reviewId/roundId 映射或新的底层会话。切智能体和右键分支仍走 T46，创建独立身份与背景。

服务端将固定 agentId、定义版本和显式 extensions/tools 清单解析为 AgentChange 对象，再用 createConversation/init 保存绑定。init 写表后不能再读表；conversationCreated 早于显式 agent 设置。缺实现、同名意外覆盖必须拒绝，不能默认全选扩展或仅靠 modelTools 隐藏工具。[类型](../../packages/durable/src/harness/types.ts)、[解析](../../packages/durable/src/harness/agent.ts)、[注册器](../../packages/durable/src/harness/registry.ts)是复用依据。

env 按会话、实际执行与检查选择实例，不共享可变 cwd。直接、嵌套、动态加载及恢复 execute 都核对固定能力与材料；审查不装配写工具、通用 Shell 或 Code Mode，不接受返回 addTools/handoff 放宽范围。这是受信代码的应用隔离，不是系统沙箱。

### 输入、材料与证据

用户直接发送要求和材料。明确标准直接采用，缺项在聊天中询问；建议不自动升级为用户要求。不做准备表单、确认标准接口或固定五阶段状态机。缺材料可以答复缺项，不无限请求模型。

T30 保存提交的要求、材料引用及版本；实际取材前取得来源读占用，复制前后核对清单、真实路径和内容，有限重试后仍变化则受阻。先原子归档文件再提交证据引用；保存来源、哈希、缺失原因与所属 submissionId/执行引用。没有快照的材料不得被工具当成已取证内容。

普通发送走 followUp，立即插入走 steer，复用 T13 的去重、编辑、撤回和停止。新材料先完成独立取材，未就绪时不送入模型；插入在 Durable 安全边界送达。每次模型请求、工具调用和结论记录实际采用的要求/材料版本，新输入不就地覆盖旧材料集合；无新材料时显式沿用原引用。模型或工具仍在使用旧证据时，不能用共享“当前材料”变量替换它。

本地规则和项目记忆一旦用于审查也记入证据来源；恢复读取原归档，不回源补读。新的复核要求可重新取材。旧助手回复、分支背景和执行方自称完成只是参考，不能代替本次核验。

### 指定检查、持久记录与停止

用户通过对话附属配置登记可信检查命令、参数、预期结果、材料和超时，模型只传 checkId。每个检查意图固定命令版本、材料指纹及 executionId；同一意图重试返回原回执，未知效果先核对。用户明确要求重跑时才建立新的检查意图，不清除旧记录，也不要求新建审查轮次。

各检查使用独立副本和环境，宿主串行执行；不使用指回源项目的可写链接。缺依赖或固定端口、共享可写缓存等无法独立准备时说明无法验证。副本不是 OS 沙箱，不承诺隔离任意脚本的网络或绝对路径副作用。

输入、证据、问题、执行政策及幂等回执存同库会话级/项目级自有文档，不依赖任务结束会退休的文档。记录工具以 conversationId/taskId/callId 与参数指纹去重，先查回执再查版本，用工具 api.commit 或宿主提交；不假设 HookApi 有 commit。受信只读取证可 safe，run-check 保持 unsafe，恢复 execute 再次核对身份与哈希。

有限预算按一次准入执行保存政策、已用次数和截止时间，连续排队/插入不自行清零；失败重试、生成和压缩均计入，重启不延长时间。预算耗尽停止当前执行，用户后续发送重新准入；不在界面设置审查轮数。模型归属复用 T12 的 ProviderDoc.sessionId 映射，Harness.models 工厂没有会话参数；审查请求 maxRetries=0，deferred 关闭，未知归属拒绝。streamSimple 保持同步流接口，预算异步保存后转发，失败和取消必须终结流。

停止先禁止后续派发，再取消对应执行、取材和进程；等后台、检查、队列处置与归档收尾才释放。命令效果未知先核对，不能用新消息绕过。待批审批与验收建议是两回事，三种工具审批仍有效。

### 回复、复核与恢复

结论是普通助手消息，可附问题清单、材料引用和证据。存在已证实违背明确要求的问题才能断言不通过；通过须有足够覆盖要求的证据；其余说明无法判定或未验证。平台校验引用与结构，不声称能证明模型语义正确。

不再设置“待报告/已发布”业务阶段；输出可流式展示，任务是否结束仍看真实运行与收尾。停止或失败保留已有回复并标未完成，不能把候选文字当成功。需要下载时从指定已保存回复及证据生成 Markdown，按消息/版本去重归档，不另调用模型、不覆盖旧件；所需日志和生成文件先归档再清副本。

用户整改后在原会话发送新要求，保存新的材料/结论关联，重新核对原问题和受影响项。旧标准变更保留消息来源；旧通过结论不沿用到新材料。同会话保留正常对话上下文及压缩历史；只有新分支隔离上下文。无用户发起不自动整改或循环互审。

重启先恢复全部会话身份、模型、材料版本和资源占用，再开放调度；缺证据或实现受阻，未知命令不重跑。已结束会话不因刷新执行；有效未结束任务按 Durable 恢复。消息、审批和停止回调始终核对原执行标识，不能影响后来任务。T29—T38 实现，T52—T55 回接公共历史、统计和页面。

## 7 持久化规则

- 同一项目的数据库由一个进程、一个 Harness 管理，避免重复打开。
- 一个 Harness 可以并发执行多个会话。源码一次预约多个符合条件的任务，再分别启动处理；串行的是提交事务，不是所有智能体执行。应用不再加项目独占锁。依据：[任务调度器](D:/code/CYG/pi/packages/durable/src/harness/scheduler.ts)。
- 按真实资源管理占用：编码 run 独占可写工作目录；审查取材短时占来源目录的读取权，快照发布后即释放；读取快照和独立副本检查可与编码并发。跨项目目录别名/父子重叠也判断冲突；任意 Shell 不能用细粒度文件锁保证安全，首版保守占整个工作目录，不承诺阻止脚本越界副作用。
- 服务端短锁一次检查全部资源、名额及连接，再持久保存 admissionId 和待提交意图；失败不保留半套占用。短锁释放后才 submit、扫描文件或等模型，避免回调死锁。设置有限并发上限，默认至少容纳两个会话；满额或目录冲突提示重试，不新增跨会话任务队列。
- submit/wait/abort 会开启整个 Harness 调度，启动前扫描全部会话及跨项目资源，重建身份和模型映射；无冲突会话可一起恢复。未知命令影响仍可保守阻止该项目自动恢复，属于异常处理。停止某项只取消对应会话及所属进程，不能整体取消项目。
- 同一请求重复发送时使用相同 requestId，避免生成两次提交。
- 编码和审查运行中均默认按 followUp 排队，立即插入改为 steer。恢复先核对执行与未消费队列，禁止刷新自动补发；新材料准备成功才可消费，不能偷换旧证据。
- 前端进度可能来自尚未落盘的 deferred commit（默认 persistWithinMs=1000）；watch 不等于持久确认。断线重连刷新暂态进度，累计统计与分支截止点从已落盘记录生成，用 Session.observeCommits 观察持久提交；回调只记录通知，不嵌套 Session API 或等待网络。
- 消息恢复和文件现场恢复分开：数据库记录恢复，不代表项目文件自动回滚。
- 审查恢复额外检查材料快照、标准、预算与证据；报告引用的证据纳入备份和保留范围，不能被普通日志清理删除。检查工作副本在无活动或待核对任务后才清理。

读写文件与命令工具保留各自的重放策略，不统一改为“重启自动重跑”。例如安装依赖的命令可能已经完成，但结果尚未保存；此时先展示中断结果，让用户核对后继续。

这项处理用于核对未知执行结果，与 T50 的执行前工具审批分开。

审查记录与回复归档使用短事务，不等待同项目其他智能体空闲；任务完成仍须核对自身后台收尾和资源占用。

准入、停止与释放补充约束：

- admissionId 由应用在 submit 前生成，覆盖取材、连续编码队列和收尾；run 仍独立记录。停止先保存 stopping 并禁止后续模型/工具调用，再取消对应会话；后续准入须等收尾。旧请求、异步回调及释放操作核对 admissionId，不能作用于后来执行。
- 等任务、后台压缩、进程、队列处置和必要归档完成才释放；结束差异也在原写占用内采集。无回执或进程未知保留占用，不凭超时自动过期。只保留失败队列且执行已收尾时可释放，继续队列重新准入。
- 重启先扫描全部项目。坏库不能当成空占用；保留其工作目录，无法计算的全局名额阻止新准入，无冲突的已准入旧执行仍可恢复。占用写入结果不明须重读，不能乐观释放。
- conversation.abort 会先 resume 整个 Harness；核对阶段先用不主动 resume 的公开 Harness.abortTask 标记用户要结束的旧任务，所有未知效果达到可调度条件后才启动清理。未满足则显示等待核对，不让另一个会话提前运行或因人为模型错误而结束。依据：[停止入口](D:/code/CYG/pi/packages/durable/src/harness/harness.ts)、[调度开关与 abort](D:/code/CYG/pi/packages/durable/src/harness/scheduler.ts)。
- 关联或创建目录均拒绝 dataRoot 内外嵌套；准入与执行复查真实路径身份，链接被替换后受阻。不能只在创建项目时查一次路径。

长期记录与恢复依据：[任务结束退休文档](D:/code/CYG/pi/packages/durable/src/session/transaction.ts)、[Harness 调度入口](D:/code/CYG/pi/packages/durable/src/harness/harness.ts)。文档缓存保留时间不是证据保存期限。

### 队列控制：公开能力与平台补充

普通发送复用 `Conversation.submit({ type: "input", whenBusy: "followUp", requestId, content })`；空闲也走此入口。固定 steeringMode/followUpMode 为 one-at-a-time，afterFailedRun 为 keep。忙时由服务端确认是否还有有效准入；刚结束且占用已释放时走 T12 新准入，不沿用旧 admissionId。

源码没有 editQueue/promoteQueue 便捷接口，但公开导出 InboxDoc，`Harness.commit` 的 Tx 支持读取提交、修改文档及结算。T13 先用真实 SQLite 和假模型验证，再做平台封装：同一事务先查操作回执，再校验归属、执行、条目版本和 queued 状态。编辑仅改普通 followUp 条目的文字；插入仅把 mode 改为 steer，保留 submissionId、数组位置和材料元数据。二者均不采用“撤回再提交”，不直接 placeSubmission，也不改已有历史。底层最终边界与这些事务竞争，谁先提交谁生效；已消费则返回真实状态。

普通单条撤回复用公开 `abortSubmission`，仅 queued 可撤；平台保存操作意图和回执，结果未知按原 submissionId 查询后补完，不能换 ID 重发。清空只针对受理时捕获的未消费条目，逐条记录成功或已消费，不误删随后发送的消息。编辑/插入的版本和回执在与 InboxDoc 修改的同一事务保存；相同操作 ID 换参数拒绝。原发送指纹不改写，编辑有独立请求 ID 和预期版本；同请求重试先返回原回执，不因新版本而重复修改。事务内先完成读表，不嵌套调用 Harness API。

postTools 是整轮工具结束后的边界，不是每条命令结束；此处最多消费一条 steer。final 可同时选择第一条 steer 和第一条 followUp，再按原队列顺序加入下一段 run；不能写成插入项一定单独、优先执行。待插入状态仍属 queued，未形成历史前不计轮数/定位刻度。原型的步骤按钮和一次推进多项只演示交互，产品以真实边界为准。

停止沿 T13 关闭入口、取消执行并清理未消费输入。keep 会保留失败队列，包括 steer；平台须在失败收尾中取消未消费的 steer，普通 followUp 留待明确继续/清空，T14 重启先补完清理再放行。取消不能删除已 placed 的历史。断线/停止/恢复/结果待核对时队列控制禁用；待插入不再提供普通队列编辑入口，待消费期间模型和审批模式仍锁定。审查使用同一队列机制，材料准备由 T30/T48 接入消费前校验。

T17/T18 返回队列、条目版本、待插入和操作回执；T21 重连整份替换，旧请求不得覆盖新版本或另一会话。浏览器只保留未发送草稿和待确认操作引用，不持久复制执行队列。依据：[公开导出](../../packages/durable/src/index.ts)、[事务类型](../../packages/durable/src/types.ts)、[提交与撤回](../../packages/durable/src/harness/submissions.ts)、[边界选择](../../packages/durable/src/harness/inbox.ts)。

## 8 Web 通信

Web 左侧放项目和其下会话，底部智能体区位于设置上方；点击标题打开完整目录。1.0 点击智能体预选项目创建会话，2.0 上线工作室后改为打开各自工作室，再由“开始会话”进入。项目创建不要求 agentId，支持名称/目标及已有目录或新空目录；智能体定义独立读取。总览汇总参与智能体、任务状态和成果，实时流按项目+会话+执行分开，不能只保留一个 currentTask。

项目级会话索引在 T11 的创建 init 同事务更新，T18 订阅索引后再挂各会话文档，避免漏掉后台新建的任务。T19 依赖 T18 后实现实时总览；不能依赖审查专用索引替代通用会话发现。

HTTP 处理创建会话、提交输入、补充说明、取消和设置；模型接口包含全部接入项/目录、单项与批量保存、常用/默认模型、刷新、测试和授权操作。SSE 将服务端执行进度推送到浏览器。

智能体目录、证据读取和回复下载由平台补充；审查创建、发送与队列复用公共接口，校验项目、会话、消息/执行、版本与 requestId，下载按登记 ID。自有文档须显式 watchDoc；未创建文档返回 undefined，创建会话时初始化必要文档，再订阅后续记录。重连先取快照，等待、收尾和执行中分开显示。依据：[文档订阅](../../packages/durable/src/session/session.ts)。

授权流程由服务端持有，Web 通过授权会话 ID 查询状态、回答问题或取消；短时断线可接回，过期回答拒绝，服务重启提示重新发起。只返回必要的交互信息和脱敏状态，Key 与令牌不进入浏览器持久存储或普通日志。

前后端只共用平台数据格式，不把 Harness、存储路径和凭据对象发送给浏览器。模型文本、工具调用和输出通过稳定 ID 关联。

浏览器断线仅停止订阅，不取消任务。重新连接使用当前快照恢复；1.0 不建设完整事件历史重放服务。

默认绑定本机回环地址。保持本地请求来源检查和输入校验，避免其他网页直接操作本机服务；这不需要平台账号或角色权限。

### 重命名与删除的服务端边界

T44 新增平台记录管理，不假设 Durable 有项目改名/删除接口。名称保存在现有项目登记与同库自有文档，校验 1—80 个 Unicode 字符、非空无控制字符；版本和 requestId 防旧页覆盖与重复操作。只改显示名，不改目录、ID、身份或已发布报告。

删除采用持久标记，普通列表不展示且执行入口拒绝；不物理删库、工作目录或证据。复用准入协调顺序，取材、待提交、任务、后台压缩、进程、收尾、待核对、队列或未知状态任一存在即拒绝，项目检查所有会话。删除与新建/提交/继续队列竞争时只有一个生效，不能用 abort 替代检查。

### 页面恢复流程

原型对照补充：草稿缓存按项目分别保存任务、配置和材料；切项目先存原草稿，再读目标草稿，不能把项目选择控件的新值与旧任务一起写入。审查可选检查字段保持类型，超时为正整数；原关联任务不可用时保留提示，提交前重新校验。T19/T21/T37 接线，A27/A43/A50 验证。

- T02 定义非敏感的服务数据实例标识；T03 在 dataRoot 的配置中生成并持久保存，T17 在工作台初始化读取响应中提供。这是拟新增平台字段，不是 Durable 接口，不暴露磁盘路径。浏览器按同源地址、实例标识和格式版本保存，防止同端口换库后相同数字 ID 串数据；服务重启标识不变，独立新 dataRoot 使用新标识。
- T19 的 workspace-view/workspace-storage 只保存白名单字段。尺寸、页面位置和项目/会话引用在操作完成后保存；草稿/搜索输入短暂防抖保存，离页补存，不只依赖离页事件。布局和页面状态分开存，恢复完成前不把默认值写回。后台旧页面离开不能覆盖另一页面更新的位置；打开的页面不因其他页面保存而强制跳转。
- 启动先取得实例标识、读本地偏好，再核对项目和会话。引用有效才恢复对应总览、会话、目录或设置分类；设置同时保存返回位置。历史会话即使不在列表第一页，也按项目+会话 ID 查询；不能因未加载分页就判不存在。新建项目/会话先取得服务端成功结果，再保存选中引用；刷新不重发创建。
- T18/T24 重新取执行快照并订阅；页面偏好不得保存或覆盖运行状态、队列、报告结论和资源占用。发送结果未知时 T21 只用原 requestId 查询，不自动补交；未发送草稿按会话恢复。审查草稿不能因刷新自动成为已发送消息或覆盖证据。
- T42 先恢复标签顺序、活动项、固定来源和显隐，再读取活动文件；其他标签按需加载，隐藏查看区不主动显示。文件全文不缓存；当前文件读取新版本，归档按原执行/快照读取，缺失或损坏显示原因，不换源。定位摘要不匹配则取消旧高亮并提示重新搜索。
- T43 只保存条件，不保存结果、片段和计数。恢复后只有当前可见的搜索页签、非空条件且服务可用时发一轮新查询；其他项目/页签待打开再查，沿用取消和迟到响应隔离。
- 确认会话不存在或不属于该项目时回项目总览；项目不存在时回项目列表。断网、服务恢复中或查询失败不等于不存在，不清引用和偏好。坏字段单项回退，未知格式版本给提示；存储禁用/满额时保留本页内存并提示不能保证下次恢复，不阻止工作台启动。

连接密钥、OAuth 回答/令牌、未保存的连接表单、文件全文和搜索结果不写入此存储。OAuth 有效流程仍按 T20 向服务端接回，不从页面缓存还原授权结果。弹窗、下拉展开状态和像素滚动位置暂不恢复；主动消息定位引用由 T53 恢复；页面内设置返回的阅读位置仍保留。原型的演示记录本地保存仅作交互参考，产品的项目/会话/消息必须回读服务端，不能整份照搬原型 state。

### 文件来源和多标签

移除右栏成果入口；历史审查结论在原消息中查看和下载，新消息不隐藏旧结论。打开材料读取指定证据版本，不能只跳当前文件。来源丢失的标签保留错误页，越项目引用拒绝。T37/T42/T52 接线，A41/A53 验证。

T39 在 contracts/server 新增统一文件来源与读取规则，T23 提供内容/差异渲染，T42 提供分栏和标签容器。来源键包含项目、相对路径、来源类型及执行/快照标识；当前文件、指定执行差异、工作区差异、不同快照分别识别。T39 先定义快照格式，T36/T42 再接实际登记快照读取，不假设已有通用文件接口。

打开文件时中间分为窄会话与宽查看区，资源列表仍保留；两区分别滚动。标签可逐项关闭、横向滚动；整体隐藏保留标签并让会话恢复全宽，顶部入口可恢复，末项关闭同样恢复。无会话保留项目总览。切项目分别恢复标签，切同项目会话不改变旧标签来源；设置返回不丢草稿与阅读位置。

内容读取结果带来源、版本摘要、读取时间和完整性。摘要与实际返回字节绑定，不能只比较 mtime。当前文件可刷新，归档版本固定；缺失/损坏不能回退到当前文件。关闭标签、换项目后的迟到响应不能重开旧标签或写入新项目。文本与高亮均安全渲染，不执行文件内容，不增加编辑器或终端。

### 页面搜索是新的本地服务

当前 [Durable 工具导出](../../packages/durable/src/tools/index.ts) 只有基本读写、编辑和命令工具；tool-search 是发现工具定义。旧 [grep 工具](../../packages/coding-agent/src/core/tools/grep.ts) 可参考 `--json`、`--fixed-strings`、argv 与取消处理，但它的输入含正则/glob，输出面向模型，不是 Web 搜索 API。不能让浏览器调用编码会话来搜索，也不从旧包深层导入实现。

T39 定义平台契约，T40 实现 server 文件服务，T43 接界面。只检索当前项目 UTF-8 文本，支持字面关键词、大小写、相对路径包含筛选；不搜历史差异、审查快照或其他项目，不做替换与正则。与文件读取共用真实路径校验、排除和大小规则；二进制、不支持编码、忽略项和不可读文件说明原因。

请求携带项目、查询序号和条件，响应携带相同归属、文件分组、行号、片段、高亮范围、内容摘要、已返回计数及完整性。同一行多次命中分别计数；排序固定。摘要与匹配来自同一有界缓冲区；如参考 rg，须将 UTF-8 字节位置转为约定的 UTF-16 下标，不能直接用于中文高亮。

限制单文件大小、扫描文件数、命中数、响应字节、时间及搜索并发，默认值见 T40；任一到限显示部分结果，不冒充全项目总数。页面防抖、取消旧请求，并丢弃不属于当前项目/查询的响应；HTTP 断开仅取消搜索读取，不调用 Durable abort。空词不扫描，无匹配、无文件、部分、取消和失败分别显示。

页面查看与搜索是观察性读取，可与编码写入并行，不申请智能体名额或目录读占用，不承诺跨文件一致。读取中发现变化有反馈；点击命中时复查摘要，变化/删除则提示重新搜索，不能把旧行号标到新内容。此入口不向审查工具开放，审查取材和版本核对仍使用原有读占用与快照校验。

### 分界线复用一个拖拽组件

T19 提供 pane-resizer，接项目栏、资源栏、顶部栏与智能体区，T42 复用它调整会话/文件比例。最小宽度：项目栏 220px、会话 280px、文件 320px、资源栏 240px；最小高度：顶部 44px、智能体区 100px，项目列表至少留 120px。最大值受相邻区和窗口限制；窗口不足先改浮层或横向滚动，不挤破下限。拖动不重新挂载会话、取消订阅或丢草稿。

五处尺寸用独立版本键存有限数值，拖动完成或键盘调整后保存；Esc/指针取消回到拖前值，不保存半途尺寸。双击/Enter 只复位该处并保存；刷新先恢复再按当前窗口限制显示。窗口变小不覆盖原偏好，变大后恢复；隐藏文件区保留其宽度。A38/A41 一起验证五处刷新、重开、上下限和状态不变。

方向键、Home/End、Enter、Esc、Tab、外部点击和焦点返回规则统一；禁用项不可选，切页清理浮层。保留表单值、校验、重置、动态选项与认证字段联动；忙时模型规则仍由业务层检查。原型的 selects.js/CSS 仅作交互参考，不假设 pi-ai 提供 Web 表单组件，也不要求照搬原型 DOM 装饰实现。

### 本轮新增能力与真实接口边界

**型号与思考档。** `packages/ai/src/models.ts` 公开导出 `getSupportedThinkingLevels` 和 `clampThinkingLevel`，通过 index.ts 可用。T04 从聊天模型元数据生成允许值，T20 展示中文档名；`reasoning=false` 只有 off；xhigh/max 必须有映射，null 档位不可选。切型号按源码函数归一并提示，服务端再验证；模型下架/未知不能用默认第一项蒙混。静态原型快照不证明厂商可连接，也不是固定的未来型号数量。

**分支。** T46 新建 ownerless 会话，复用 T11 创建和 T30 审查初始化；不直接拿原生 fork 复制另一智能体的配置。来源项目/会话、稳定历史截止点、作者及背景摘要保存在平台自有文档；按已持久保存的历史取材，未落盘流片段不复制。超长历史按有界、可追溯方式取最近完整消息并提示截断，不调用模型自动总结。背景作为引用资料提供，不注入原生工具调用或未配对 tool result。

原会话即使运行也可分支，创建不占执行名额、不继承资源锁、不触发提交；真正执行仍走 T12。requestId、来源截止点与目标智能体绑定；重试、崩溃和删除并发均由平台去重。子分支再次分支保留最初作者与引用，不递归复制相同祖先段。来源删除后已保存背景仍可看，但不能恢复原会话。T35 同会话继续复核保留原上下文，并关联新要求和材料；分支背景不能作为审查证据。

**材料。** T48 复用 T39 的真实路径、排除和读取规则；只允许当前项目文件/文件夹引用，不是任意磁盘上传。目录选择不在浏览器递归读取全文。发送时保存有界清单与选择版本，编码按实际读取说明内容变化；审查必须再经 T30 占用、取材和冻结，不能拿页面搜索结果或路径当快照。草稿只存引用，提交指纹包含这些引用及清单摘要；响应未知先查原请求，不能重扫后偷换同一个请求的材料。

**真实审批。** 原型的 approvalMode 只是演示值。T50 必须新增平台审批文档与执行入口，T51 才能显示有效模式。现有 beforeTool 的 block 会结束调用，不是可恢复等待；execute 恢复会跳过 beforeTool。不能只加一个 hook 或虚构 Harness.approve/pause。

可复用公开 ToolExecutionApi 的 commit、createTask、waitForTask、executeTool，以及任务检查点/等待能力。先做离线验证：审批包装记录稳定调用键，等待持久决定，通过后只派发一次对应底层动作；嵌套动作保持自己的 replay 策略。重启时包装可重入不等于命令可重跑；底层效果未知仍走 T14 待核对。底层工具不能通过模型列表、嵌套或恢复路径绕过入口，应用副作用回调也要检查。具体等待实现须在 T50 首步验证公开 API 与取消行为后确定；测试不通过不得宣称审批可恢复。

审批只针对智能体动作与指定检查，平台固定的记录/归档写入仍按目标边界执行，不递归审批自身。自动审批使用独立的无工具模型请求，只读冻结操作摘要和必要背景，输出结构化允许/转人工及理由；文件里的指令不能改变审批规则。固定边界优先于模型决定。输出失败转人工，不调用 lg-examine 充当审批器。模型、参数、策略版本、理由及用量落盘；批准不沿分支、队列或后续调用扩散。

**布局。** T19 做收起栏和项目浮层，60px 为收起态专用宽度，不覆盖展开态最小 220px 及五处偏好；收起后禁用左栏宽度/智能体区高度拖拽。T37 做 1100px 审查容器和底部横排配置；T47/T49/T51 接所有对话输入，文件分栏、缩放及主题一起验。

T46—T51 保留；T52/T54 补后台，T53/T55 补页面和历史定位。前置链汇总到 T26/T27，再由 T38/T28 收口；A47—A56 是必测项。

### 普通会话映射与分支

编码和审查都以 workbenchSessionId 对应一个 Durable conversationId；ProviderDoc.sessionId 仅用于模型归属，不能混用。T02/T11/T30 建立绑定，T35/T36 接连续审查，T52 回接历史、记录管理与恢复。后续复核不新建底层会话，不引入轮次指针或封存流程。

T46 的显式分支先持久保存来源会话、固定 tail entryId、目标智能体及请求指纹，按 entries 的 maxEntryId 分页读取。只复制用户/助手可见文字作为背景，不带系统提示、思考、原生工具记录、执行、队列、批准或证据。草稿只复制对应来源的浏览器可见草稿，旧回执不覆盖新编辑。

创建与提交结果未知只查原请求。刷新恢复实例/项目/会话、消息锚点和固定文件来源；网络失败不当删除。查看旧消息不改变执行配置，也不启动任务。删除检查整会话所有未结束活动，不能只看当前页面。

### 快速定位与统计来源

T52 提供两类会话的用户消息分页定位数据，T53 负责页面；复用 entries、UserEntry，不用活动 context/watch 代替完整历史。摘要取已保存文字片段，无需模型。位置用 projectId + workbenchSessionId + entryId，不用数组下标；定位不执行任务，历史材料始终按固定来源读取。

T54/T55 新增平台统计契约和只读查询/推送，不假设 Durable 有 workbenchStats API。已核对的来源：

| 指标 | 当前源码来源与限制 |
| --- | --- |
| 轮数/步数 | 两类会话均取已保存 UserEntry / 业务 AssistantEntry；不把 run、工具调用或审查次数当用户消息数 |

补核对：[OpenAI 兼容适配](../../packages/ai/src/api/openai-completions.ts) 会将缺失缓存字段补 0，[Anthropic 适配](../../packages/ai/src/api/anthropic-messages.ts) 也有缺省零；因此读 UsageDoc 无法区分真实未命中与缺报。缓存比例只能说明已记录值，不按厂商名称臆造支持能力。[工具记账](../../packages/durable/src/harness/tool.ts) 对嵌套调用和外层结果分别记账，包装器再次转报子调用 usage 会重复；审批账必须与它们互斥。

历史索引按固定尾 entryId 分页，游标绑定项目/会话/上界，不能跨范围复用。[context 实现](../../packages/durable/src/harness/context.ts) 只给活动上下文，并滤掉部分错误/中断记录，不适合历史计数。公开 [entries 查询](../../packages/durable/src/types.ts) 支持 ID 上下界；统计从稳定范围读计数，在同一次只读提交读取 UsageDoc、审批账和配置版本，再用该截止点读取上下文。不能在提交回调内嵌套 Harness API，也不能拼接不同时间的多次 watch 值冒充同一快照；有界索引尚未追齐时显示部分。

统计以服务端快照为准，增量带版本；刷新重取，不能把每次推送累加到本地数字。历史缺耗时、未上报缓存、不可读记录都返回未知/部分及原因。流片段不入累计，压缩只影响上下文估算、不减少历史轮数和用量；分支不复制来源用量。精确口径见功能清单，T52/T54 进入 T26，T53/T55 进入 T27，A53—A56 必测。

## 10 智能体工作室：2.0 扩展与 1.0 预留

详细产品流程和未来实施用例见 [创造智能体技术分析](./创造智能体技术分析.md)。每个内置、自建和创建助手都有自己的工作室，全部使用 Durable。工作室是管理界面，不是新的运行内核；同项目继续一个 Harness，不为每个智能体重开项目数据库。

### 源码支持与新增边界

[AgentChange / createConversation / init](../../packages/durable/src/harness/types.ts)支持装配指令、扩展、工具和保存应用绑定；[文档系统](../../packages/durable/src/documents.ts)支持持久状态。这些可作为基础，但没有现成的智能体工作室、在线创建管理、智能体通用知识库或自进化服务。

[Registry](../../packages/durable/src/harness/registry.ts)同名安装会替换扩展；[Agent 解析](../../packages/durable/src/harness/agent.ts)保存和解析名称，缺失项可能被忽略。RegistrySnapshot 只是当次内存快照，不是持久版本仓库。AgentChange 接收实际扩展/工具对象，不接收定义中的字符串 ID；平台先解析受信清单，再显式装配。

注册器只检查单扩展内部的工具名/段落键重复；多个扩展同名工具或提示词段落会由后选项覆盖。T29/T60 要校验同一会话选中集合，拒绝意外覆盖；有意的 wrapper 单独登记顺序和实现版本，失败后不能静默丢掉能力。扩展版本名须可区分，自定义任务名在整个注册器内唯一；不同会话可以分别选 v1/v2，不同时把两版混入一个会话。代码指纹来自受信部署产物清单，不对函数对象做 JSON 哈希。模型工具列表不等于安全边界，直接、嵌套、动态加载与恢复路径仍按 T29/T50 检查。

[Skills 加载](../../packages/coding-agent/src/core/skills.ts)、[项目规则加载](../../packages/coding-agent/src/core/resource-loader.ts)和 [MCP 客户端](../../packages/mcp/README.md)可参考或适配；不能假设它们已经接入 Durable 工作室。AGENTS.md 仍是项目规则，不把 AGENT.md 当现成的智能体定义协议。

### 工作室与保存

Web 按稳定 agentId 定位工作室。八区固定为：基础信息、灵魂、Skills、MCP、记忆、知识库、自进化、运行轨迹。采用 B 版统一外壳：身份总览、八区横向页签、最大 1200px 居中内容；开始会话复用既有项目选择与首次发送，返回恢复原页面。不同智能体不各写一套管理页面。

不设置智能体自己的模型连接或运行参数。模型、重试、压缩、并发等继续使用全局配置及已有生效规则；工作室只管理身份、专业规则、能力和长期资料。

不建立持久配置草稿，不增加发布按钮。保存修改携带 requestId、预期版本和内容指纹；校验通过，在定义仓库的一次事务中保存不可变版本、当前版本指向和回执。请求重试查原结果，并发旧版本写入拒绝。未保存表单只留当前页面，离开提示保存或放弃；保存失败不清输入，刷新不自动保存。

目录项保存稳定 ID、来源、名称、简介和当前版本；版本保存规则、技能与能力引用、执行方式及内容指纹。2.0 将这些引用连同记忆/知识及索引版本组成一份完整清单；依赖和索引准备完成、校验通过后才原子切换当前指向。中途失败不露出半套新配置；会话固定整份清单，不分别读取各库的“最新”。内置实现的固定约束不属于可编辑字段。创建助手的建议、自进化提案可持久记录，但不是生效配置，不能被运行入口直接读取。

### 智能体配置与项目执行隔离

| 范围 | 服务端归属与读取要求 |
| --- | --- |
| 平台全局 | 模型/运行设置、工具实现、MCP 连接和密钥；定义只引用连接与能力，不复制凭据 |
| 智能体 | agentId 对应通用规则、技能及明确共享的记忆/知识版本 |
| 项目文件 | projectId 对应工作目录、根目录规则/记忆及任务资料；读取时核对当前任务范围与智能体能力 |
| 会话与执行 | 保存 projectId、workbenchSessionId、实际 conversationId/executionId；队列、审批、统计和材料不跨记录复用 |

Durable 的 session/conversation/task 范围不等于平台的智能体/项目范围。按现有一个 Session 对应一个项目的方案，项目数据可用自有文档承载；跨项目的定义与通用资料放平台仓库。不得将当前项目变量放进所有智能体共用的全局对象。

工作室无项目选择、项目专属配置或项目资料管理分层。项目专属记忆和规则由用户按需在项目根目录维护文件，不在工作室配置或自动汇入智能体通用资料。旧 coding-agent 能加载 AGENTS.md，但还会读取全局目录及项目上级目录；Durable 不会自动接入这套加载器。1.0 由 T08 适配，只自动读取当前项目根目录到目标目录之间的 AGENTS.md；说明和记忆文件须显式列入材料。AGENT.md 不作为自动加载文件名。运行轨迹可以按当前 agentId 汇总各项目的简要记录，打开时重查 projectId 与会话归属；这不授权模型检索其他项目材料。MCP 使用全局连接和智能体能力清单，调用时校验当前任务资源；知识检索只读取该智能体已绑定的通用资料版本。

### 仅新会话生效与恢复

创建会话固定 agentId、definitionVersion、技能内容/依赖版本、工具实现清单和适用的记忆/知识版本引用。资料版本和索引都需可复现，不要求把全量知识复制到提示词。运行记录保存实际命中的来源。

进入新会话页或刷新草稿不固定定义；首次发送受理创建意图时才取有效版本，显式分支按其创建意图固定。定义库与项目库不共用事务：先保存创建意图及固定版本，再由 T11/T46 的项目创建流程保存绑定和回执。响应丢失或中断重试查原意图，不重选最新版。init 在创建写入和 agent 配置后执行，可访问自有文档，但不能再读表；定义查找及文件读取提前完成。conversationCreated 钩子早于显式 agent 配置，不能在该钩子里假定已拿到最终身份。任务创建的子会话虽会复制 AgentDoc，却不会自动补齐平台绑定；宿主须从已验证的 owner 继承绑定，缺绑定禁止调度，不创建新的页面会话。原有事务限制继续有效。

旧会话继续发送、执行队列、停止后继续、同会话复核、刷新或重启都用原定义绑定及原 Durable 会话。只有新会话或显式分支取得当前有效版本；分支不继承原审批、队列和执行资源。

这一规则只约束工作室配置和长期资料，不改变用户补充材料、当前项目文件/AGENTS.md 的读取规则；审查若使用项目规则或记忆，也须列入本次提交的取材清单并冻结；恢复不回源目录补读，文件内容不能改变用户标准和宿主边界。全局参数的分类生效与显式换模型保持 1.0 规则，不通过工作室热改 Harness 设置。

保留被历史会话引用的定义、技能、资料和实现版本；恢复前验证，不满足则只读可查、执行受阻。代码扩展使用可区分的版本名称，任务名称也需避免冲突，不以同名 install 实现热升级。工作室取消能力只形成新配置，不立即撤销旧会话能力。平台实际禁用、凭据失效和停止按现有运行准入检查；已发出的动作按停止/待核对流程收尾，不承诺撤回。1.0 不因此新增能力撤销管理界面。

### 自进化和最小运行轨迹

从已保存的用户纠正、执行失败和审查发现提取问题，按来源记录去重。只有去除项目私有内容并验证为通用问题后，才形成智能体改进提案；项目专属要求留给用户维护项目文件。提案保存来源的项目/页面会话/执行或消息 ID、必要摘要、基准版本、拟改内容、验证结果和状态，不设置项目生效范围。缺证据标待验证，不自动写入通用记忆。

首版采用自动发现和建议、用户确认应用；完全自动应用策略另定。应用前校验基准版本与提案指纹，已有人工修改则重新比较；保存新版本后只作用于新会话。普通工具自动审批不能代替此确认，模型不能自己扩大能力范围。

规则/资料改进走校验与针对性验证；新增工具、代码或连接适配先开发检查再登记。验证与创建助手是独立 Durable 执行，复用全局调度、资源占用、审批、停止和待核对机制，不无限循环调用。重启只恢复原工作，不重复应用修改或重跑结果未知的动作。

归并程序只从来源执行取证，不把所有项目历史交给创建助手；进入通用提案前先去除私有内容，应用前重查证据。轨迹按执行时绑定的 agentId 从现有记录生成：时间、项目、任务摘要、状态、原会话入口；展开只补开始/结束、配置版本、关键动作和结果。完整过程回原会话；保留底层恢复记录，不建设第二套复杂追踪系统。独立验证/助手用量各计一次，缺字段显示未知，刷新重读不累加。

### 实施顺序与检查

1.0 仅预留已有两个智能体需要的通用契约与检查：T02 定义身份/版本/范围；T07/T29 统一装配；T11/T46/T52/T56 固定会话绑定；T12/T14/T50/T59 覆盖执行边界；T17/T19/T37/T47 保持目录和入口通用；T18/T25/T26/T27/T28 接记录、备份与整链。新增 T60 将这些预留统一收口，依赖基础任务完成，不要求 1.0 建好知识库或创建助手。

2.0 顺序为定义保存与版本仓库 → 工作室及装配 → 智能体通用记忆/知识 → 创建助手 → 自进化 → 整链验收。创建助手和验证的执行位置须在 V04 明确：建议使用服务管理的独立创作/验证工作区，不借当前打开的项目；指定用户项目的验证才按该项目准入。该机制属于 2.0 平台新增设计，不是 Durable 原生作用域，也不放宽 1.0 业务执行必须有 projectId 的规则。简单轨迹可先接已有记录。完整八区编辑留到 2.0；主原型先通过卡片进入 B 版预览，再开始会话。1.0 正式界面未开放工作室时，卡片仍直达新会话；目录按稳定 ID 生成，不写死为两种类型。

重点检查：v2 保存后 v1 旧会话/队列/复核/恢复不变，新分支取 v2；创建重试不漂移版本；项目文件和 MCP 资源不跨任务越界；知识索引更新不改变旧绑定；缺实现明确受阻；并发保存与自进化确认不覆盖人工修改；平台实际禁用后旧绑定也不能继续调用；刷新恢复位置但不自动保存、应用或执行。详细 R01—R06、V01—V06 见技术分析。1.0 共 60 项任务、61 组验收；T60/A61 验预留，B 版页面检查单单列为原型验收，不混入产品完成率。


### B 版接线与核对边界

- 卡片、方块、窄栏头像与完整目录统一指向 agentId；工作室不持有项目范围。返回位置独立保存，不覆盖原项目、会话、草稿和文件来源。“开始会话”直接进入现有新会话页，由该页选择项目。
- 配置保存与开始会话分开。新会话创建意图固定 definitionVersion、实现指纹及资料引用；创建成功但响应丢失后只查原意图，不能取新版本重建。已有会话继续审查沿用原定义和原 conversationId；只有显式新分支创建新绑定。
- 1.0 不实现在线定义编辑 API；两个内置定义可由受信包清单提供。T60 保存被引用版本及指纹，装配时精确匹配；测试 v2 用测试定义，不引入真实第三个内置智能体。记忆/知识引用在 1.0 可为空，不提前搭检索系统。
- B 版能力区按智能体显示。lg-examine 不出现源目录写入和编码 Code Mode；取消或启用能力的演示开关不代表真实授权。凭据仍只在全局连接配置管理。
- 运行轨迹复用会话索引，不复制运行日志或重新累加统计；历史会话缺失时明确提示，不能跳到同名会话。浏览、筛选和刷新不调用模型。
- 产品工作室位置按服务数据实例保存 agentId 和页签，与工作台返回位置分开；实例切换不带入旧引用。定义内容从服务端读取，浏览器不另存权威副本。保存结果未知只保留 requestId/指纹等查询引用，刷新查回执，不重放保存；已确认成功才切到新版本。主原型独立浏览器键只验证演示交互。恢复先校验智能体和定义；旧 scope 字段忽略并移除，不重置原会话或已保存版本。项目删除仅影响其轨迹入口与原工作台回退，不清空工作室表单。刷新不保存、应用或执行；网络失败不当作记录已删除。
- 保存前区分“尚无演示配置”“已存配置被移除”“格式损坏”和“读取失败”；后三类不以旧内存覆盖。旧版本冲突/写入失败保留输入。原型只演示顺序冲突检查，localStorage 的读后写不保证多页面并发原子性；产品保存仍需定义仓库事务及幂等回执。
- 当前主原型版本只保存在浏览器独立键，未接服务端版本仓库、运行装配和真实资料。自进化为当前智能体的通用模拟提案，按提案 ID 去重；旧项目应用标记只留历史，不视为通用批准，新应用不再携带项目标记。正式保存事务、并发和恢复仍按 2.0 实现。

### 灵魂、Skills、MCP 的交互与边界

- “灵魂”突出个性、语气、判断原则和工作习惯，保留原规则内容；改名称不重置已保存定义。项目规则仍由项目文件维护。
- Skills 独立显示“全部、开发、审查、通用、已上传”分类页签和数量；卡片展示名称、简介、类别、来源及选择状态，空分类显示空态。取消顶部技能指引占位行和长条工具列表。现有工具卡标“工具能力”，不把工具开关冒充已安装技能。
- 右上提供“上传 Skill 包”。原型选择 ZIP 后只加入待保存配置，记录文件名、大小和选择状态；可移除，重复文件名提示。它不读取、解压、安装或运行包，保存成功也不代表技能可执行。
- 正式上传是 2.0：服务端校验包、SKILL.md、内容版本和依赖，成功才可保存进定义；原型的文件名检查不能代替内容校验。上传不授予工具、MCP 或项目访问能力，脚本也不自动执行。
- MCP 单独一页，只引用已登记连接及能力；全局管理凭据。工具依赖缺失给出原因，不因勾选就显示已连接。审查仍不能获得源项目写入、任意 Shell 或编码 Code Mode。
- 页签按稳定 ID 保存，不按数组位置恢复；拆分后旧“人设与规则”位置回灵魂，旧能力页回 Skills，记忆/知识库/自进化/轨迹按原含义恢复，失效分类回全部。
- 分类、工作室智能体、页签和返回位置可恢复；已保存技能来自该智能体定义版本。未保存上传不自动落盘，刷新不重新上传、安装、应用或启动任务。定义保存后只影响新会话和显式新分支，旧会话、队列和同会话继续审查沿用原版本。

完整工作室和上传后端仍属 2.0；1.0 的 T60/A61 只预留分别可识别的技能内容版本、MCP 能力引用及工具实现清单，不交付上传安装服务。
