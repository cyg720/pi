## 中文提交解说的范围

当前历史有 6,891 条提交。48 条提交提供基于提交说明、统计及相关实现的中文解说（本轮同步新增 43 条）；其他记录提供**自动元数据中文概述**：变更类型、主题线索、受影响包、文件与增删行数。它们不是逐条补丁审查，也不是所有英文提交说明的完整人工翻译。界面明确区分两者，避免把概述当作源码审查结论。

## 更新

在仓库根目录运行：

```powershell
node docs/doc-html/build.mjs
node --test docs/doc-html/catalog.test.mjs docs/doc-html/capabilities.test.mjs docs/doc-html/package-tutorials.test.mjs docs/doc-html/mastery.test.mjs docs/doc-html/versions.test.mjs docs/doc-html/development.test.mjs docs/doc-html/directory.test.mjs docs/doc-html/verify.test.mjs
```

生成时需要本地仓库、Git、Node 和仓库已有的 TypeScript 依赖；阅读时都不需要。生成器不会调用在线翻译、模型 API 或外部 CDN，不修改 package.json 和锁文件。正文是人工维护内容，源码与 Git 元数据自动刷新；接口改变导致定位文本失效时，生成器会报错，要求同步修订正文。

提交导览本身会产生新的 Git SHA，不必因此重写整份历史快照。验证以 HTML 记录的生成基线核对提交历史和版本范围，允许该基线之后只有 `docs/doc-html/` 与配套功能清单的文档提交；仍逐文件核对内嵌业务源码及外部参考资料与当前磁盘的 SHA-256。出现其他仓库改动或来源内容变化时，必须重新核对并生成，不能仅替换基线编号。

`src/edition-baseline.json` 保留 2026-09-29 旧导览的固定基准，普通重新生成不会覆盖它。差异始终相对该基准，“本次补充”统计的是导览条目新增，不等同于 Git 新增业务功能。后续如需改用另一版导览作为基准，应先保存那一版的提交、功能和源码指纹。

## 源码目录说明的更新

目录树的范围比功能清单广：使用 `git ls-files --cached --others --exclude-standard -z` 收录源码、测试、文档、配置、脚本和资源，并还原全部祖先文件夹。目录从文件路径还原，不包括空目录、node_modules、.git、忽略的模型数据与其他本地产物。未跟踪但未被忽略的新文件也会出现；文件列表对应生成时的工作区，不自动实时读取磁盘。

说明保存在 `src/directory-notes.json`，以仓库相对路径为键，根目录键为空字符串。普通生成保留所有已有说明，新节点登记为 `{ "description": "" }`。未经初始化的节点在树里显示“待补充”，作用描述区域保持空白；不会继承父目录说明，也不会把覆盖索引当作已解读说明。

初版已从现有中文包 / 模块 / 功能讲解初始化有依据的节点。文件说明明确区分“参与某能力”“静态关联的测试资料”“参考文档”；关联功能的整体作用不表示每个文件独自实现全部行为。原始注释与声明是语法树提取的源码证据，文件级更细的职责可以继续人工补充。

后续更新时，先修订中文功能讲解或逐文件说明，再运行：

```powershell
node docs/doc-html/build.mjs --initialize-directory
node --test docs/doc-html/catalog.test.mjs docs/doc-html/capabilities.test.mjs docs/doc-html/package-tutorials.test.mjs docs/doc-html/mastery.test.mjs docs/doc-html/versions.test.mjs docs/doc-html/development.test.mjs docs/doc-html/directory.test.mjs docs/doc-html/verify.test.mjs
```

显式初始化只填充描述为空且已有中文依据的节点，不覆盖非空说明；无依据的节点继续为空。更精细的说明可直接编辑对应项的 `description`、`details` 和 `evidence`。`details` 的项包含 `title`、`entry`、`behavior` 和关联 `feature` ID；`evidence` 是仓库相对路径数组。

已初始化源码文件保存初始化 commit 和源码 SHA-256；后续快照内容变化会标记“待复核”，仍保留原说明。人工对照当前源码复核后，可更新该项 `sourceHash` 为当前 `data/manifest.json` 中的指纹，并更新 `initializedCommit`。没有收录全文的文件没有快照指纹，不据此宣称内容已经复核。旧路径说明仍留在登记表，当前树只显示当前路径。已移除功能的详情链接不再渲染，并标记关联说明待复核。本轮仅对可与旧生成说明逐项匹配的 142 项自动说明更新语义，previousExplanation 保存其上一版；历史实验应用遗留目录另加明确说明，未知项仍为空。

## 功能索引边界

清单覆盖 Git 已跟踪的包 src、coding-agent/examples、agent/examples、durable/test/examples、tui/native、根/包 scripts 与根 shell 入口。新增文件需纳入 Git 跟踪后才进入下次生成。根工作区中新包自动加入“待解读”索引，避免静默漏扫；自动发现不替代中文语义解读。测试通过可解析的 import、再导出和字面量动态导入关联，计算路径动态加载无法据此解析。文档与二进制不作为独立业务功能。原始注释保留原语言，缺失注释不自动编造。

中文能力说明在 `src/features.mjs`、`src/feature-additions.mjs` 和 `src/example-notes.mjs` 维护；提供商和示例自动分组，未单独解释的实现按目录进入明确标记的“支撑实现”。**全部文件有归属，不表示全部业务语义已经人工逐项讲解。** 静态引用不是精确调用链，文件导出也不等于 npm 公共 API。功能关联提交按当前路径匹配，不追溯重命名。

界面用“Markdown 功能说明、中文能力解说、源码规则归类、源码覆盖索引”区分说明依据。可以先从编号功能建立整体认识，再按源码专题、文件和符号深入。单文件内嵌 1,850 份源码/文档快照，当前约 53.8 MiB，首次打开与全文搜索可能比原版稍慢。

## 版本介绍的维护与范围

入口为 `#versions`，例如 `#versions/1.1.0/overview`、`#versions/Unreleased/upgrade`。列表按语义版本从新到旧，未发布置顶；列表内部切换只重绘详情，不重建左侧菜单。版本与栏目可直接定位，离开后返回保留搜索条件、选择和列表位置。六个栏目提供版本定位、重点读者、变化前后、影响解释、建议检查、全部包日志、兼容性原文、两版记录统计、当前源码线索、提交范围和证据来源。

`src/versions.mjs` 收集全部已跟踪 `packages/*/CHANGELOG.md` 与 `CHANGELOG.zh.md`，聚合同一数字版本。现有中文日志最高到 1.0.2，可能滞后于英文原文，独立展示；中文“未发布”不自动配对较新的英文 Unreleased。空版本章节保留并标明“未单列变更”，不推断为没有源码改动。只有中文资料的旧包明确标为历史资料。条目数以规范日志的顶层列表项统计，产品重点与详细分类可能重复，不能当成功能总数。
