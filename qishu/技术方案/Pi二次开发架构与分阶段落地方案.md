# Pi 二次开发架构与分阶段落地方案

日期：2026-10-10。状态：架构方案，未实施。目标：企业内网中的多端智能体工作台与智能中枢平台。

## 架构决策

采用 **统一平台入口、durable 优先执行、coding-agent 兼容执行、多端共享权威数据** 的架构。

- `packages/apps/web` 负责 Web 界面，`packages/apps/desktop` 负责桌面外壳，复用 Web 界面和平台接口。
- 智能中枢负责账户、权限、Agent 与团队定义、任务调度、应用和资源管理。
- 新建平台 Agent 优先采用 `pi-durable`；现有 Pi 功能由 `coding-agent` SDK 兼容执行器承接。
- 执行进程内直接复用 Pi；跨进程、跨节点通过平台任务与事件接口协作。RPC 作为可选执行适配，不作为整个平台的数据协议。
- 首期采用模块化后端与独立执行进程。达到容量或隔离需求后再拆分服务，不先铺设大量微服务。
- durable 能力验证是正式开发前置门槛；未通过的能力保留明确限制，不以模拟数据替代。

Web 采用 **React + TypeScript + Vite**，使用 SPA（浏览器内运行的单页应用）。开发约束直接读取根目录 [开发规范](../../开发规范.md)，架构边界与阶段目标以本文为准；原型文件迁移和验收批次见 [原型正式接入 Pi 源码技术方案](./原型正式接入Pi源码技术方案.md)。以上为方案约定，不代表工程已接入。

## 需求与职责

| 需求 | 承担模块 | 交付边界 |
| --- | --- | --- |
| 专业工程师与普通员工使用 | Web 与桌面客户端 | 同一能力体系；普通视图提供表单与模板，高级视图提供配置、诊断和开发入口 |
| 创建独立 Agent | Agent 管理 | 模型策略、指令、工具、资源、执行位置和版本；普通员工也可在权限内创建 |
| Agent 互相调用与组队 | 团队编排 | 委派、消息、等待、汇总、取消、失败处理和共享产物 |
| Web 与桌面端数据一致 | 平台数据与订阅 | 同账户、同工作空间、同一权威状态；权限变化同步生效 |
| 用户创建独立应用 | 应用管理 | 应用定义、版本、表单或页面、服务入口、权限、执行器绑定及发布状态 |
| 知识库、MCP、Skill、工具、插件 | 能力资源管理 | 注册、授权、版本、运行适配及可观测性；不同资源保留各自语义 |
| 算法检测与其他独立程序 | 服务执行器 | 可直接执行确定性程序，也可被 Agent 调用；不要求经过大模型 |
| 本机文件或工厂设备访问 | 本地执行节点 | 绑定设备身份与授权目录；显示执行位置和在线状态 |

普通视图和高级视图只改变交互复杂度，不替代权限控制。内网部署仍执行身份认证和资源授权。

## 总体结构

```text
apps/web                      apps/desktop
       └──────────────┬──────────────┘
                      ↓ 统一 API 与事件订阅
                  智能中枢
       ┌──────────────┼────────────────┐
       账户与权限      Agent 与团队       应用与能力资源
       数据与审计      任务调度与路由       知识库与文件
       └──────────────┬────────────────┘
                      ↓ 持久任务投递与执行授权
                   执行节点
       ┌──────────────┼────────────────┐
       durable 执行器  coding-agent 执行器 算法与服务执行器
       └──────────────┬────────────────┘
                      ↓ 受控调用
            模型 / MCP / 工具 / 文件 / 外部服务
```

中枢是确定性的管理与调度服务。可增加总控 Agent 帮助用户分配任务，但模型不能自行授予权限、决定租户归属或绕过预算。

### Web 与桌面客户端

源码分别位于 `packages/apps/web` 和 `packages/apps/desktop`。`apps` 仅作为客户端应用分组目录；两端分别建立包定义与构建入口，桌面端复用 Web 界面，不复制维护另一套业务页面。

负责登录、工作空间、应用入口、Agent 创建、团队配置、会话、任务进度、产物、资源和设置。

浏览器仅持有界面状态与必要缓存，不保存服务端模型密钥，不直接连接运行时存储，不导入 Pi 内部实现。关闭客户端不等于取消任务；取消必须提交明确操作。

保留现有原型的布局、交互及深浅色。将演示数据限制在显式演示入口和测试夹具，生产连接失败不得自动显示模拟成功结果。

### 智能中枢

负责身份与组织、工作空间、访问控制、版本化定义、任务接收、执行节点选择、资源目录、数据查询、审计与配额。平台管理库保存这些业务事实。

任务进入执行前校验身份、资源权限、定义版本、执行节点能力和预算；恢复、重试及跨 Agent 委派时重新校验必要权限。

### 执行节点

负责启动执行器、隔离运行目录、装载已批准资源、注入短期凭据、回传状态和维护运行时存储。可部署于内网服务器，也可部署于经授权的用户电脑或工厂节点。

开发环境允许本机进程；多用户插件或代码执行需要受控容器或等效隔离。独立进程和独立目录本身不构成安全沙箱。

## durable 基础与 Pi 复用边界

### durable 作为新增 Agent 的基础

现有 durable 已提供：持久提交、会话与分叉、任务检查点、输入去重、子任务、任务图、状态订阅、工具调用及执行环境接口，并有前后台子智能体的可运行示例。[S1]

平台优先在其外层扩展以下能力：

| durable 已有基础 | 平台扩展职责 |
| --- | --- |
| Conversation 与 Agent 配置 | 版本化 Agent 定义、所有者、可见范围和发布状态 |
| Harness、Task、Submission | 业务任务 ID、配额、跨节点调度及历史任务索引 |
| 子任务与子对话所有权 | 团队角色、允许的调用关系、共享范围及生命周期策略 |
| viewState、watch、任务图 | 用户可见的数据投影、跨端订阅与权限过滤 |
| ExecutionEnv | 容器或本地节点环境、目录与网络策略、凭据注入 |
| Storage 与一致性测试 | 独占所有者、备份、恢复、存储迁移和生产可靠性 |

同一 durable Session 内的任务执行和子任务调度由 Harness 负责。中枢只调度 Session 所属执行节点及跨 Session 的业务委派，避免两套调度器同时推进同一任务。

**Session 粒度：**一个独立工作会话或一项紧密协作的团队任务对应一个 durable Session，其中可以有多个 Conversation。不建立全租户共享的单一 Session；Agent 定义也不绑定永久运行进程。

### 必须保留的限制

- durable 当前标注为实验性，接口可能变化。固定已验证的仓库提交与依赖版本，升级前执行兼容、恢复与存储测试。[S1]
- durable 原生存储要求单进程所有者，不提供跨进程锁。首期使用执行节点独占存储与宿主所有者锁；未经确认旧所有者停止，不自动启动第二个写入者。[S1]
- 多节点接管必须验证存储与工具执行边界上的所有者代次校验，使旧执行者无法继续写入；仅有心跳或租约不足以保证这一点。
- 任务恢复不保证外部操作只执行一次。非安全重放工具中断后可能返回 interrupted；支付、发单、设备动作等必须使用业务幂等键、执行凭据或人工核对，不自动盲重试。[S1]
- SQLite 的当前默认设置可恢复进程崩溃，但断电可能丢失最近提交；JSONL 可配置 fsync。上线前明确可接受的数据丢失范围和恢复时间，并验证相应存储策略。[S1]

### 两类 Pi 执行器

| 项目 | durable 执行器 | coding-agent 兼容执行器 |
| --- | --- | --- |
| 用途 | 新建平台 Agent、团队及长任务 | 现有 Pi 工作台和尚未适配的原生能力 |
| 内部调用 | durable Harness 与扩展接口 | coding-agent SDK；必要内部引用集中适配 |
| 恢复承诺 | 以检查点及工具重放策略为准 | 沿用原生会话能力，不自动承诺 durable 级恢复 |
| 扩展体系 | durable Registry 与 Extension | coding-agent 扩展、资源加载器及原生交互适配 |
| 平台呈现 | 统一任务与产物接口 | 同一平台接口，按能力声明显示差异 |

两类执行器共享平台身份与资源授权，不共同写入同一运行时存储。统一接口属于拟建平台契约，不是宣称 Pi 已存在的新 API。

coding-agent 的扩展、MCP、Skill、提示模板、图片、认证交互和自定义 TUI 组件不能直接视为 durable 原生兼容。逐项标记“直接复用、需要适配、保留兼容执行器”。仓库已有 durable 编码代理示例可作为参考，但其文档明确列出尚未包含的能力。[S2][S3]

### 其他 Pi 包

| 组件 | 采用策略 |
| --- | --- |
| pi-ai | 复用模型访问与提供商能力；用户凭据及配额归平台管理 |
| pi-tui | 用于兼容原生扩展界面；普通 Web 页面仍使用网页控件 |
| pi-client、pi-server、pi-protocol | 评估内部服务路由与订阅复用，不直接作为账户平台；当前协议实验性，认证由应用负责 [S4] |
| 传统 RPC | 保留跨语言或子进程执行适配；33 个命令不承担平台应用、团队和同步协议 [S5] |

## Agent 团队与通信

| 平台对象 | 内容 |
| --- | --- |
| AgentDefinition 与版本 | 指令、模型策略、工具、资源、执行器、执行位置及授权上限 |
| TeamDefinition 与版本 | 成员角色、协作流程、调用白名单、并发、预算、失败与取消策略 |
| Run | 一次业务任务，关联定义版本、执行器、所有者及最终结果 |
| Conversation | 用户或 Agent 的交流范围；映射到具体运行时对象 |
| Delegation | 父子任务关系、目标 Agent、输入、结果关联、截止时间及去重键 |
| Artifact | 报告、文件、检测结果；保存版本、来源任务与访问权限 |

这些是拟建领域对象。平台 ID 与 Pi 内部 ID 建立映射，客户端不直接使用内部路径或运行时路由标识作为授权依据。

首批支持串行、并行、汇总和审核流程。动态分派在调用关系、预算和终止条件受控后再开放。

**调用流程：**父 Agent 提交委派意图 → 中枢授权并持久记录 → 相同 Session 交由 durable 子任务，跨 Session 投递到目标执行器 → 提交结果与产物 → 父任务接收结果并继续。

- 消息携带租户、工作空间、源任务、目标、关联 ID、去重键和截止时间。权限使用服务端身份上下文，不信任模型生成的身份字段。
- 跨 Session 投递采用至少一次传输与接收端去重；不承诺跨系统 exactly-once。
- 前台子任务随所属任务取消；独立后台工作必须显式声明，显示单独停止入口。停止父任务不等于撤销已经发生的外部操作。
- 限制调用深度、循环次数、并发、上下文和费用。共享摘要与授权产物，不默认共享完整历史、全部知识库和凭据。
- 同一文件或设备的并发修改由资源锁或独立工作副本协调；不能只靠 Agent 自行协商。

## 数据归属与跨端同步

| 数据 | 权威位置 | 同步规则 |
| --- | --- | --- |
| 账户、组织、工作空间、权限 | 平台管理库 | 所有客户端统一读取 |
| Agent、团队、应用、资源定义 | 平台管理库 | 版本化保存，运行任务固定所用版本 |
| 会话内容、检查点、运行中状态 | 所属执行器存储 | 单一写入者；平台提供可重建查询投影 |
| Run 受理、归属与调度记录 | 平台管理库 | 中枢负责受理，执行终态以执行器已提交结果为准 |
| 报告、附件、知识库原文 | 文件或对象存储 | 保存校验值、版本、权限与保留期限 |
| 知识索引 | 检索服务 | 从授权原文生成，可重建；同步删除和权限变更 |
| 凭据 | 受控凭据存储 | 仅向获准执行节点提供，客户端不接收明文 |
| 输入草稿与界面偏好 | 客户端或平台偏好存储 | 草稿单独定义同步规则，不混入运行时事实 |

平台与执行器存储之间不存在默认的跨库事务。任务先记录待投递状态，与待发记录在同一平台事务提交；执行器按 requestId 去重受理，再回报受理标识。丢失回执时查询同一标识，不能重新生成新任务。运行事件在执行器提交后发布，投影可通过快照重建。

客户端采用“授权快照 + 后续订阅”。平台事件携带对象、版本或序号；断线、缺口或订阅过期时重新读取快照。WebSocket 或 SSE 只承担传输，不代替持久存储。

同一账户多端同时操作时：设置更新校验版本，会话输入由执行器排序，重复请求去重；权限收回后关闭相关订阅并清理缓存。服务端查询、下载和订阅均校验对象权限，不能只在界面隐藏入口。

本机路径必须关联节点 ID，不作为跨设备可直接访问的文件地址。仅同步获准上传的文件与产物。首版不承诺断网编辑自动合并，也不承诺运行任务从服务器无缝迁移到桌面。

## 智能中枢的应用与能力资源

采用统一资源目录，保留类型专属配置。每项资源包含类型、版本、所有者、输入输出约束、权限、执行位置、依赖和状态。

| 类型 | 运行与管理方式 |
| --- | --- |
| 应用 | 页面或表单绑定 Agent、团队或服务；支持草稿、发布、停用和版本回退 |
| 知识库 | 导入、解析、索引、权限过滤、检索与引用溯源；检索前和文件读取时均校验权限 |
| MCP | 管理连接、凭据和工具授权；连接属于租户或工作空间，不默认全平台共享 |
| Skill | 版本化指令及资源；按运行时适配加载，不把文本本身当作权限 |
| 工具 | 明确参数与结果、超时、取消、幂等及副作用；可被 Agent 或应用调用 |
| 算法检测 | 独立服务或批处理任务；按需使用 GPU、文件输入和结构化结果 |
| 插件 | 包含代码与依赖；安装审查、版本固定、隔离运行、权限清单及卸载影响分析 |

员工创建应用优先使用表单、模板和能力组合；工程师可配置高级参数及接入代码。可视化编排生成相同的版本化定义，不建立另一套运行规则。

运行任务固定资源版本，恢复时装载兼容版本；升级不得把旧任务静默切换到新插件。MCP、Skill、插件和应用不共用一套任意 JSON 配置来掩盖类型差异。

## 源码组织与迁移

客户端目录确定为 `packages/apps/web` 和 `packages/apps/desktop`，其余包名为建议，在实施时创建。目录名不直接决定 npm 包名；逻辑模块不等于独立部署服务。

| 位置 | 职责 |
| --- | --- |
| packages/apps/web | Web 视图、交互、客户端缓存与平台通信 |
| packages/apps/desktop | 桌面外壳、登录及本地节点交互，复用 Web 界面 |
| packages/cyg-platform | 账户、授权、定义管理、调度、同步及资源目录 |
| packages/cyg-runtime | durable、coding-agent、服务执行器及 Pi 适配 |
| packages/cyg-contracts | 平台通信类型、版本与校验，不包含 Node 专用实现 |
| qishu/prototype | 原型与历史验收基线，迁移验收前保留 |

前端只依赖平台契约；平台通过执行适配调用运行时；Pi 内部源码引用限制在适配层。可公开复用的能力优先使用现有导出，确需增加导出时只导出既有必要实现。

原型迁移按“页面与交互、宿主执行能力、演示与历史材料”分流，不能把整个原型目录直接作为 Web 应用的生产后端。原型的本机令牌认证不直接升级成多用户账户系统，服务器任务也不得默认继承开发者的全局 Pi 凭据。

开发模式与构建产物模式分别验证。接入 workspace、构建顺序、类型检查、格式检查及 CI；清除 qishu 和个人工具路径依赖；模型与主题等资源按 Pi 原有定位规则打包。先冻结原型行为与视觉基线，再按页面逐步迁移为 React 组件；不把前端迁移、平台账户改造和 durable 执行器替换合成一次切换。原型复制到正式目录仅是输入材料，不代表完成生产接入。

嵌套应用目录的工程接入要求如下，仅列为实施事项：

| 位置 | 后续调整 |
| --- | --- |
| 根 package.json | workspace 增加 `packages/apps/*`；根构建脚本按依赖顺序显式接入应用；`apps` 分组目录不设占位 package.json |
| 类型检查入口 | Web 单独设置 JSX、DOM 与浏览器模块解析；桌面宿主单独设置 Node 环境。根检查显式调用应用检查，不直接把浏览器源码塞入当前 Node 配置 |
| biome.json 与检查脚本 | 增加嵌套应用的 TS、TSX 及测试范围；复核相对导入检查等脚本对 TSX 的覆盖；遗留 JS、MJS 按迁移范围纳入 |
| 应用包与启动脚本 | 调整配置继承、资源与仓库根路径解析；不要继续假定应用根目录向上两级就是仓库根 |
| CI 与版本发布 | 检查应用安装、构建、测试与打包入口；应用包首期保持 private，核对递归包发现与版本脚本的处理 |

当前 `packages/*` workspace 和 `packages/*/src` 检查规则不会自动覆盖下一层应用包。平台、运行时和共享契约仍位于 `packages` 下，不因客户端分组一并迁入 `apps`。

## 分阶段落地

| 阶段 | 主要交付 | 验收门槛 |
| --- | --- | --- |
| P0 边界冻结 | 对象关系、数据归属、执行器能力矩阵、平台契约草案、原型迁移表、前端框架决策 | 每项需求有归属；旧功能无未解释的删除；确定并发规模、数据保留与恢复目标；冻结视觉与交互基线 |
| P1 durable 基础验证 | 单节点执行器、存储独占、版本固定、恢复、子任务及配置适配 | 进程中断可按策略恢复；重复输入不重复受理；旧写入者无法并行打开存储；非幂等工具不盲重放 |
| P2 单 Agent 平台闭环 | packages/apps/web 的 React 界面、登录与工作空间、Agent 创建、任务、文件产物、订阅、coding-agent 兼容入口 | 嵌套应用包纳入 workspace 与检查；两个浏览器看到同一任务；断线可恢复视图；未授权跨账户访问拒绝；原有核心交互回归通过 |
| P3 Agent 团队 | 版本化团队、串并行、委派与回报、任务图、预算及取消策略 | 父子取消语义正确；重启不重复投递；超时与循环可终止；权限不能通过委派扩大 |
| P4 应用与能力服务 | 应用模板及发布、知识库、MCP、Skill、工具、插件和算法执行 | 普通员工可创建并使用一个报告应用；工程师可接入检测服务；版本、权限和资源撤销均有效 |
| P5 桌面与本地节点 | packages/apps/desktop、复用 Web 界面、统一登录、节点注册、本地资源授权 | 桌面包独立构建；Web 与桌面同数据；本地任务执行位置明确；节点离线有反馈；文件不擅自上传 |
| P6 生产强化 | 多节点调度、接管、备份恢复、升级回退、限流、监控及容量验证 | 故障接管不双写；旧执行者被隔离；达到 P0 确定的容量与恢复目标；升级恢复旧任务通过 |

P0 → P1 → P2 为主线。P3、P4、P5 在 P2 契约稳定后可按团队资源推进，P6 的隔离与备份要求从前期建设，最终统一验收。没有人员和容量依据前不承诺日历工期。

前端迁移是 P0 至 P2 的工程分支：契约草案和原型基线冻结后，可与 P1 的执行器验证并行推进；durable 验证未通过时不开放对应生产功能。实施批次统一采用 [原型正式接入 Pi 源码技术方案](./原型正式接入Pi源码技术方案.md)中的 A0–A4、B1–B2：A0 对应 P0 的迁移基线；A1–A4 交付正式本机 Web，可与 P1 并行；B1–B2 承担 P2 的平台化 Web 接入。A 阶段通过不代表 P2 完成，P2 还须满足 Agent 创建及执行器等整体验收要求。

P1 若出现关键恢复或兼容问题，阻止相关 durable 功能上线；可交付明确标识的 coding-agent 兼容能力，但不能用普通会话恢复冒充持久任务恢复。

## 验收与上线规则

| 验收范围 | 必测场景 |
| --- | --- |
| Pi 兼容 | 33 个原生 RPC 对应行为、会话树、流式、工具、取消、压缩、配置、资源及扩展界面 |
| durable | 提交前后崩溃、工具执行中断、重复 requestId、前后台子任务、恢复时资源版本变化 |
| 团队 | 成员失败、部分成功、超时、重复回报、循环调用、预算耗尽及共享文件冲突 |
| 同步 | 两端同时操作、断线重连、迟到事件、权限收回、配置冲突及已受理请求回执丢失 |
| 隔离 | 跨工作空间读取、越权调用工具、凭据泄露、未授权插件及节点失联 |
| 交付 | 从构建产物启动、中文与空格路径、退出与重启、升级、备份恢复及回退 |

每阶段先列用例，再批量验证、批量修复、批量回归。自动测试优先使用 faux provider 和隔离资源；实际模型、企业 MCP、设备及算法服务另列受控联调验收。

原型 108 项通过是历史基线，迁移后重新运行；531 条功能清单用于标记“保留、适配、条件支持、明确不适用”，不能当作 531 项业务验收通过。33 个 RPC 的行为验证与原生 stdin/stdout 传输验证分别记录。

上线采用小范围试用、保留旧版本、停止接收新任务后排空或检查点停机的流程。存储格式升级先备份并验证恢复；存在不兼容写入后，不以直接降级程序代替数据回退。审计串联用户操作、任务、委派、工具和产物，日志不记录密钥。

## 首期需确认的业务参数

以下影响容量与排期，在 P0 确定，不阻碍本方案的模块划分：

- 首批用户数、同时运行任务数、最大团队规模及典型任务时长。
- 企业登录方式、组织与工作空间共享规则、数据保留期限。
- 第一批必须接入的知识库来源、MCP、算法服务与本地设备。
- 可接受的数据丢失范围、恢复时间及是否要求离线使用。

首版默认在线使用、服务器执行为主、单企业内多账户和工作空间；本地执行与多节点接管按阶段增加。
