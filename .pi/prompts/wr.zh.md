附加说明：$ARGUMENTS

首先根据对话历史确定上下文。

上下文检测规则：
- 如果对话中已经提及了GitHub问题或拉取请求，请使用已有的上下文。
- 如果这项工作来源于`/is`或`/pr`，请假设对话中已知该问题或拉取请求的上下文，并且已完成相关分析工作。
- 如果对话历史中没有提及GitHub问题或拉取请求，请将此视为非GitHub工作。

除非我在此请求中明确覆盖，否则请按以下顺序执行操作：

1. 根据repo changelog规则，在`## [Unreleased]`下添加或更新相关的包发布日志条目。
2. 如果此任务与GitHub问题或拉取请求相关，并且本会话中尚未发布最终的问题或拉取请求评论，请以我的语气起草评论，预览后发布。评论必须以以下确切的独立免责声明结尾，不得有任何变体：

   ```text
   This comment is AI-generated by `/wr`
   ```
3. 只提交本会话中你修改的文件。
4. 如果此任务仅与一个GitHub问题相关，请在提交信息中包含`closes #<issue>`。如果与多个问题相关，请停止并询问使用哪个问题。如果没有关联任何问题，请勿在提交信息中包含`closes #`或`fixes #`。
5. 检查当前的git分支。如果不是`main`，请停止并询问应如何处理。除非我明确要求，否则不要从其他分支推送。
6. 推送当前分支。
7. 如果此任务仅与一个GitHub问题相关，请在推送后显式关闭该问题，关闭原因使用`completed`，以便`.github/`中的问题关闭工作流能够运行。此规则仅适用于问题，不适用于拉取请求。
   - 检查`gh issue view <issue> --json state,stateReason,labels`。
   - 如果问题处于打开状态，请运行`gh issue close <issue> --reason completed`。
   - 如果问题已关闭且关闭原因不是`COMPLETED`，请先重新打开问题，然后再以`gh issue close <issue> --reason completed`关闭，以便GitHub发出新的关闭事件。
   - 如果问题已关闭且关闭原因为`COMPLETED`，请保持关闭状态，除非`inprogress`标签仍然存在；如果标签仍然存在，请重新打开问题并再次以`completed`关闭。

约束条件：
- 绝不要暂存无关文件。
- 绝不要使用`git add .`或`git add -A`。
- 在提交前，如果代码有变动，请运行必要的检查。
- 除非我明确要求，否则不要打开拉取请求。
- 如果是非GitHub问题或拉取请求工作，请勿发布GitHub评论。
- 如果本会话中已经发布了最终的问题或拉取请求评论，请不要再次发布评论，除非我明确要求。
- 如果在非`main`分支上工作，请跳过发布日志。
