## Fixed / 已修复

1. JSON validation previously depended on English display labels containing `JSON`. Planned hooks, tool declaration, tool input examples and telemetry event draft were therefore not consistently checked. Validation now uses stable field keys, independent of either UI language.
2. Parseable JSON of the wrong basic shape could pass (for example `samplingParams: "[]"`, `stdio.args: "[1]"`, or roots as an object). Added explicit object/array/string-array contracts, source-backed durable selection unions, deferred windows, thinking-budget keys and integer values, and flat telemetry attribute types. Nested SDK semantics remain host work, not a claimed full schema validator.
3. Export previously downloaded a state that could fail the app's own import validator. Export now validates the complete bundle before creating the Blob; the UI catches and shows failure instead of reporting a successful download.
4. Provider and class-specific options could look effective when ignored. Added subscribed visible warnings for ignored sampling parameters, provider-dependent transport/deferred/reasoning/cache/etc., TuiMainScreen versus alternate-screen options, native versus polling settings, conflicting MCP reconnect delays, executable hooks, and eval dependency exclusion.
5. Made local effectiveness and independent form/document state explicit in both languages. Chord, telemetry and TUI illustration helpers are explicitly separate from form drafts. No helper output is evidence that Pi ran.

## Important semantics / 重要边界

- Field change events write `drafts[package].fields[key]`. A structured editor's Apply button writes only `drafts[package].document`. Full-bundle import replaces all ten package drafts after validation and clears editor scratch. Scoped reset changes only its own package. No cross-package draft leakage was observed in the exhaustive tests.
- All 153 defaults are workbench choices and are retained in exports. Some agree with SDK defaults, but there is no universal-provider-default claim. Example documents are separate fixtures; changing a field does not rewrite those fixtures.
- `model.provider` and `model.id` are catalog selectors, not a full Pi `Model`. The actual picker handlers are tested together; changing providers chooses a catalog model, caps output tokens and clears unsupported reasoning. Arbitrary model text isn't accepted by bundle import.
- `reasoning = "unspecified"` is a workbench sentinel: a future adapter must omit that option. Image and classifier contexts are different API inputs, not additions to a chat request. Their model capability must be selected and validated separately on the host.
- Source `StreamOptions` explicitly says only OpenAI-compatible completions/responses/Azure responses apply `samplingParams`; other APIs ignore it. Supported adapters merge these keys after named request fields, so they can override named settings. `transport`, `sessionId`, cache mapping, metadata and timeouts are provider-dependent. Reasoning support is not equivalent to support for every reasoning level. [Pinned source](https://github.com/earendil-works/pi/blob/7d75a0e3eb273dff753d49c066ea29fbe7b3b6f6/packages/ai/src/types.ts).
- `workbench.*` values are explicitly annotations or grouped method arguments. Hook names are not functions. Tool schemas are not executable tool callbacks. Runtime/adapter/link/renderer choices are constructor plans, not SDK string options.
- Durable extensions belong to durable's own registry; names require host resolution. The durable tools do not imply enabling coding-agent. Harness compaction and retries need resolved models, context windows, storage and actual scheduling.
- TUI numbers use terminal cells. Browser illustrations are not Pi terminal output. Alternate-screen fields do not configure a main-screen renderer.
- Eval observation score maps to `score` only for a `scored` outcome; otherwise a host must omit it. No eval result, latency, score improvement or token cost is measured here.

## Remaining gate / 后续运行时验证条件

To claim SDK effectiveness requires a separately authorized trusted host adapter. It must select one canonical argument group per operation, parse JSON fields, omit sentinels and irrelevant options, resolve full model/registry/runtime objects, enforce complete nested schemas and cross-field/provider constraints, and supply authenticated transports/callbacks/storage/terminals. Start with offline or faux-provider tests that assert the exact canonical options received by the SDK. Only then run explicitly authorized live integration tests per package/provider and record observed outcomes. Evals must remain excluded unless the dependency constraint changes. This audit neither creates that backend nor makes secret-dependent calls.
