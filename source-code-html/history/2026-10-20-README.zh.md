## 中文提交解说的范围

提交数量与人工中文解说数由生成数据统计；工作台整合提交补充人工解说。其他记录仍是自动元数据中文概述，不代表逐条 diff 审查或完整翻译。

为任意提交增加更详细中文解说：在 `src/history-notes.json` 中以完整 commit SHA 为键填写说明，再生成。Git 历史只覆盖本地 HEAD 可达提交；不包含其他未合并分支。时间采用作者日期与原始时区，排列采用 Git `--date-order`，合并提交可能没有常规 numstat 文件列表。旧提交中的“当前快照”按钮指向文档生成版本，不代表该旧提交的文件版本。

## 更新

在仓库根目录运行：

```powershell
node docs/doc-html/build.mjs
node --test --test-isolation=none docs/doc-html/catalog.test.mjs docs/doc-html/capabilities.test.mjs docs/doc-html/package-tutorials.test.mjs docs/doc-html/mastery.test.mjs docs/doc-html/versions.test.mjs docs/doc-html/development.test.mjs docs/doc-html/directory.test.mjs docs/doc-html/verify.test.mjs docs/doc-html/workbench.test.mjs
```

生成时需要本地仓库、Git、Node 和仓库已有的 TypeScript 依赖；阅读时都不需要。生成器不会调用在线翻译、模型 API 或外部 CDN，不修改 package.json 和锁文件。正文是人工维护内容，源码与 Git 元数据自动刷新；接口改变导致定位文本失效时，生成器会报错，要求同步修订正文。

提交导览本身会产生新的 Git SHA，不必因此重写整份历史快照。验证以 HTML 记录的生成基线核对提交历史和版本范围，允许该基线之后只有 `docs/doc-html/` 与配套功能清单的文档提交；仍逐文件核对内嵌业务源码及外部参考资料与当前磁盘的 SHA-256。出现其他仓库改动或来源内容变化时，必须重新核对并生成，不能仅替换基线编号。

`src/edition-baseline.json` 保留 2026-09-29 旧导览的固定基准，普通重新生成不会覆盖它。差异始终相对该基准，“本次补充”统计的是导览条目新增，不等同于 Git 新增业务功能。后续如需改用另一版导览作为基准，应先保存那一版的提交、功能和源码指纹。

## 源码目录说明的更新

目录树的范围比功能清单广：使用 `git ls-files --cached --others --exclude-standard -z` 收录源码、测试、文档、配置、脚本和资源，并还原全部祖先文件夹。目录从文件路径还原，不包括空目录、node_modules、.git、忽略的模型数据与其他本地产物。未跟踪但未被忽略的新文件也会出现；文件列表对应生成时的工作区，不自动实时读取磁盘。

说明保存在 `src/directory-notes.json`，以仓库相对路径为键，根目录键为空字符串。普通生成保留所有已有说明，新节点登记为 `{ "description": "" }`。未经初始化的节点在树里显示“待补充”，作用描述区域保持空白；不会继承父目录说明，也不会把覆盖索引当作已解读说明。

初版已从现有中文包 / 模块 / 功能讲解初始化有依据的节点。文件说明明确区分“参与某能力”“静态关联的测试资料”“参考文档”；关联功能的整体作用不表示每个文件独自实现全部行为。原始注释与声明是语法树提取的源码证据，文件级更细的职责可以继续人工补充。

后续更新时，先修订中文功能讲解或逐文件说明，再运行：

```powershell
node docs/doc-html/build.mjs --initialize-directory
node --test --test-isolation=none docs/doc-html/catalog.test.mjs docs/doc-html/capabilities.test.mjs docs/doc-html/package-tutorials.test.mjs docs/doc-html/mastery.test.mjs docs/doc-html/versions.test.mjs docs/doc-html/development.test.mjs docs/doc-html/directory.test.mjs docs/doc-html/verify.test.mjs docs/doc-html/workbench.test.mjs
```

显式初始化只填充描述为空且已有中文依据的节点，不覆盖非空说明；无依据的节点继续为空。更精细的说明可直接编辑对应项的 `description`、`details` 和 `evidence`。`details` 的项包含 `title`、`entry`、`behavior` 和关联 `feature` ID；`evidence` 是仓库相对路径数组。

已初始化源码文件保存初始化 commit 和源码 SHA-256；后续快照内容变化会标记“待复核”，仍保留原说明。人工对照当前源码复核后，可更新该项 `sourceHash` 为当前 `data/manifest.json` 中的指纹，并更新 `initializedCommit`。没有收录全文的文件没有快照指纹，不据此宣称内容已经复核。旧路径说明仍留在登记表，当前树只显示当前路径。已移除功能的详情链接不再渲染，并标记关联说明待复核。早期迁移曾对可与旧生成说明逐项匹配的 142 项自动说明更新语义，previousExplanation 保存其上一版；历史实验应用遗留目录另加明确说明，未知项仍为空。

## 功能索引边界

清单覆盖 Git 已跟踪的 packages 与 apps 的 src、coding-agent/examples、agent/examples、durable/test/examples、tui/native、根/包 scripts 与根 shell 入口。新增文件需纳入 Git 跟踪后才进入下次生成。根工作区中新包和应用自动加入“待解读”索引，避免静默漏扫；自动发现不替代中文语义解读。测试通过可解析的 import、再导出和字面量动态导入关联，计算路径动态加载无法据此解析。工作台 NativeSettings 的 esbuild 字符串入口另以人工核对的确切路径、原文与行号关联，明确标为打包测试入口；其他无可解析依据的测试不猜关联。文档与二进制不作为独立业务功能。原始注释保留原语言，缺失注释不自动编造。

中文能力说明在 `src/features.mjs`、`src/feature-additions.mjs`、`src/current-features.mjs`、`src/workbench.mjs` 和 `src/example-notes.mjs` 维护；提供商和示例自动分组，未单独解释的实现按目录进入明确标记的“支撑实现”。**全部文件有归属，不表示全部业务语义已经人工逐项讲解。** 静态引用不是精确调用链，文件导出也不等于 npm 公共 API。功能关联提交按当前路径匹配，不追溯重命名。

界面用“Markdown 功能说明、中文能力解说、源码规则归类、源码覆盖索引”区分说明依据。可以先从编号功能建立整体认识，再按源码专题、文件和符号深入。单文件内嵌全部已收录快照；大小与数量见生成结果，首次加载和全文搜索可能需要数秒。

## 版本介绍的维护与范围

入口为 `#versions`，例如 `#versions/1.1.0/overview`、`#versions/Unreleased/upgrade`。列表按语义版本从新到旧，未发布置顶；列表内部切换只重绘详情，不重建左侧菜单。版本与栏目可直接定位，离开后返回保留搜索条件、选择和列表位置。六个栏目提供版本定位、重点读者、变化前后、影响解释、建议检查、全部包日志、兼容性原文、两版记录统计、当前源码线索、提交范围和证据来源。

`src/versions.mjs` 收集全部已跟踪 `packages/*/CHANGELOG.md` 与 `CHANGELOG.zh.md`，聚合同一数字版本。现有中文日志最高到 1.0.2，可能滞后于英文原文，独立展示；中文“未发布”不自动配对较新的英文 Unreleased。空版本章节保留并标明“未单列变更”，不推断为没有源码改动。只有中文资料的旧包明确标为历史资料。条目数以规范日志的顶层列表项统计，产品重点与详细分类可能重复，不能当成功能总数。

本地标签仅采用 HEAD 可达的语义版本标签。当前最高可达标签由 data/versions.json 的 latestTag 记录；以实际 HEAD 可达关系为准。每个有标签的版本使用前一较低版本标签到本标签的 Git 可达差集；未发布使用最高可达标签到 HEAD，首个标签使用其可达历史。无标签时不猜提交归属，非祖先标签明确提示，浅克隆注明截断。包版本、日志日期、标签时间和远端实际发布状态是不同维度，本页不据此证明 npm 或在线 release 已发布。

`src/version-notes.mjs` 维护 10 个版本的重点中文解说：未发布、1.3.0、1.2.0、1.1.0、1.0.4、1.0.3、1.0.2、1.0.1、1.0.0、0.87.0。每项绑定版本、包及英文原文定位文本，生成时失效会报错。其他版本提供自动记录概述、完整原文及已有中文日志，不冒充逐条中文翻译。两版对照仅比较各自的记录分类与包，不是累计升级报告；跨版升级仍需逐一检查中间版本。

版本页的源码链接使用当前快照，不是历史源码；提交文件名用于阅读线索，合并提交常规 numstat 可能为空。关联测试没有自动运行，历史源码可在本地仓库按标签或提交查阅。原有功能编号、静态引用图、测试关联和学习路线保留。所有日志和版本数据内嵌离线 HTML，不调用在线翻译或远端 API；日志中的外部资料链接需要联网。

## 源码精通路线的维护与范围

入口为 `#mastery`；例如 `#mastery/model-connect/step-1` 直接定位模型接入步骤，`#mastery/conversation-round/slides` 打开六视角讲解。`#mastery/coverage` 查看全部稳定编号的学习位置，`#mastery/plan` 查看制作待办。学习进度仅保存到当前浏览器的 `pi-doc-mastery-v1`；存储不可用时仍可阅读和在当前页面勾选。

课程正文维护在 `src/mastery-curriculum.mjs`。每条路线显式声明阶段、先修、场景、连续步骤、失败边界、练习及参考答案；每步关联已登记源码专题并继承真实文件、入口与契约。`src/mastery.mjs` 将现有稳定编号与专题关系接入路线，示例和文档方案额外显式登记。新增编号未覆盖、先修循环、缺少专题或步骤没有源码依据时会停止生成。覆盖表示全部已登记功能有学习位置，不等于穷尽所有执行分支或逐条测试通过。

源码按钮打开完整文件，当前步骤引用从第 1 行进入，可在弹窗查找函数，或跳转功能详情查看符号行号和引用图。教学顺序不宣称是精确运行时调用轨迹。练习由读者结合本地开发说明执行，页面本身不运行代码、模型或部署操作。

HTML 每条路线有场景、职责、时序、数据、失败和验证六个视角。阶段 PPTX 每条路线用三页组合呈现这些视角，完整解释、源码路径、参考判断和测试线索保存在讲者备注。普通 HTML 生成不会自动重新创作 PPTX。课程或 HEAD 变化后，旧课件下载自动隐藏并提示“课件待同步”；需对照新课程重制并验证课件后，更新 `learning-slides/manifest.json` 的基线、`courseHash`（`JSON.stringify(mastery.routes)` 的 SHA-256）、文件指纹和页数，再生成 HTML。不能只更新指纹来冒充内容已同步。

## package 教程的维护与范围

入口为 `#packages`，单包和栏目可定位到如 `#packages/agent/config`、`#packages/durable/flow`。中文教学内容保存在 `src/package-lessons.mjs`；`src/package-tutorials.mjs` 从当前包清单、已跟踪路径和已有 AST 索引生成参考内容。发现没有教学内容的新包，或流程引用失效时，生成器会报错，要求先补充有依据的说明。历史目录不从 dist 或 node_modules 推断当前接口。

参数区引用全部已收录的包与应用 src 声明，保留签名、函数入参、类型、原始注释和源码行号；接口及类型别名可展开完整原文。配置类型筛选只是快捷入口，可以切换全部声明。JSON schema 保留嵌套属性、required、default、enum 和引用；CLI、环境与配置文档也完整内嵌。直接导出不等于公共 API，类型允许省略不等于已经确定默认值；内部声明和依赖库类型不伪装成独立用户设置。

中文重点解释按参数作用域组织，原始注释和参考文档保留原语言；并非每个参数都已有逐字段中文翻译。环境变量列表仅列出显式读取线索，不宣称覆盖计算键或间接读取的全部语义。示例与测试按路径分类并可阅读全文；已有示例中文解说可继续跳入原专题，未单独解说的文件明确说明。教学流程是有来源的阅读路线，不是自动执行轨迹。页面不运行示例、命令或模型请求。
